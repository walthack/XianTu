# 六朝系列角色正典库生成方案

## 1. 最终目标

产物必须能导入仙途。玩家在关系面板观察角色、查看技能装备、与角色互动时，应读取小说事实和当前剧情阶段快照，不由运行时 LLM 临时编造基础设定。

三本书分别生成角色库，最后建立跨书统一 ID：

1. 《六朝清羽记》
2. 《六朝云龙吟》
3. 《六朝燕歌行》

## 2. 模型分工

### MiniMax：正文事实抽取

通过本机 OpenClaw 调用：

```bash
openclaw infer model run \
  --local \
  --model minimax/MiniMax-M2.7-highspeed \
  --thinking off \
  --json \
  --prompt "$PROMPT"
```

MiniMax 负责阅读正文批次，输出人物事实，不负责最终 ID、游戏数值或跨书合并。

适合抽取：

- 首次登场和外貌描写；
- 身份、称号、年龄线索、种族；
- 性格表现和明确人格底线；
- 所属势力、职位与变更时间；
- 人物关系及变化事件；
- 技能、功法、装备的获得、失去、使用和专属关系；
- 所在地点、离场、死亡、失踪和被囚状态；
- 各剧情切点的人物状态。

### DeepSeek V4 Flash：合并与归一化

通过现有 OpenRouter 适配器调用 `deepseek/deepseek-v4-flash`。

DeepSeek 负责：

- 合并同一人物的多批事实；
- 识别称号、别名、旧名和同名歧义；
- 生成单书角色档案；
- 从证据账本生成阶段快照；
- 建议跨书人物、技能、功法、装备的统一 ID；
- 列出冲突和不确定项，不擅自裁决。

### Codex：契约、校验和导入

Codex 负责：

- Schema 与稳定 ID；
- 引用完整性和阶段时间检查；
- 与地图、势力和 Mod 实体对齐；
- 映射为仙途 `NpcProfile`、技能、功法和物品；
- Canon guard 与观察界面验收；
- 失败用例、边界用例和存档重载测试。

## 3. 节省 Token 的读取策略

不为每个人重复通读全书。每本书执行以下流水线：

1. 复用已有 `source-index.json`、全文批次抽取和阶段计划。
2. 从现有 Mod、事件抽取和人物状态中建立候选人物表。
3. 按人物名称、别名和称号定位正文段落。
4. 核心人物读取全部相关段；次要人物读取首次登场、状态变化和高潮相关段；功能性人物只读取首次登场和结局段。
5. 一个正文批次同时抽取其中所有人物，禁止按人物重复发送同一正文。
6. 每批结果按“正文哈希 + 模型 + Prompt 版本”缓存；成功文件永不重复调用。
7. 合并阶段只传结构化事实，不再次发送大段正文。

角色分层：

- `core`：主角、主要同伴、主要对手；完整档案和每个 Mod 阶段快照。
- `recurring`：反复参与剧情的人物；完整基础档案，只在状态变化阶段生成快照。
- `supporting`：有姓名且影响事件的人物；最小档案和必要关系。
- `functional`：原作未给出稳定姓名或设定的功能性角色；不得伪装成正典人物。

## 4. 中间证据账本

模型不得直接生成最终 `NpcProfile`。先输出事实账本：

```json
{
  "characterKey": "程宗扬",
  "factType": "appearance|identity|personality|affiliation|relationship|location|ability|item|status",
  "value": {},
  "validFromSourceIndex": 1,
  "validToSourceIndex": null,
  "sourceRefs": [
    {
      "book": "qingyu",
      "sourceIndex": 1,
      "heading": "章节标题",
      "summary": "不超过两句的证据摘要"
    }
  ],
  "confidence": 0.9,
  "inference": false
}
```

硬性要求：

- 不保存长篇原文摘录；只保存事实摘要和精确来源索引。
- 外貌必须区分稳定特征与当时衣着、伤势、年龄状态。
- 没有证据的灵根、修仙境界、六司和天赋不得补写。
- 同一事实冲突时保留多个候选并进入人工复核队列。

## 5. 最终角色库结构

每本书输出：

```text
character-canon/<book>/
  character-index.json
  characters/<character-id>.json
  stage-snapshots/<mod-id>.json
  evidence/<batch-id>.json
  review/conflicts.json
  review/unresolved.json
```

固定档案包含：

- 稳定 ID、姓名、别名、称号和角色等级；
- 性别、种族、年龄或出生线索；
- 基础外貌：体态、面容、发型、显著特征、气质；
- 稳定性格、价值观、人格底线；
- 身份和势力经历；
- 专属技能、功法、装备引用；
- 来源证据和不确定项。

阶段快照包含：

- 当前地点和地图 ID；
- 当前势力、职位与阵营；
- 当前境界或小说能力层级；
- 当时已获得的技能、功法和装备；
- 当前衣着、伤势、身体状态；
- 生死、失踪、被囚或离场状态；
- 与玩家及其他人物的关系和好感度。

## 6. 技能、功法和装备

人物与内容必须分离建库并通过 ID 引用：

```text
shared-canon/
  characters.json
  skills.json
  techniques.json
  items.json
  aliases.json
```

每项内容记录：

- 稳定 ID、名称、别名和类型；
- 小说效果与限制，不强行转换成仙途通用法术；
- 首次出现和获得时间；
- 已确认持有者；
- 是否专属、是否可传授、是否唯一物品；
- 各阶段持有、遗失、转移或损毁状态；
- 来源证据。

例如“只有主角会”的能力必须同时满足：

- 内容标记为 `exclusive`；
- `allowedCharacterIds` 只包含对应人物；
- Canon guard 拒绝其他 NPC 学习或生成同名替代能力。

## 7. 游戏导入规则

导入时把固定档案和阶段快照合并为原生 `NpcProfile`：

- `外貌描述`：稳定外貌加当前阶段衣着，不使用角色简介代替。
- `当前外貌状态`：阶段伤势和状态；进入游戏后允许按事件变化。
- `性格特征`、`人格底线`：来自正典档案并受保护。
- `当前位置`：引用共享地图坐标。
- `势力归属`、`宗门`：取当前阶段快照。
- `技能`、`功法`、`背包`：只导入该阶段已经获得且仍持有的内容。
- 小说未明确字段使用“原作未明确”或留空；禁止使用“凡人、五维全 5”等伪正典默认值。

运行时字段分级：

- `immutable`：姓名、基础外貌、稳定身份、专属内容。
- `stageLocked`：阶段开始时的势力、地点、技能、装备和关系，可由正式剧情事件改变。
- `dynamic`：当前衣着、伤势、情绪、内心想法和临时状态。

## 8. 质量门槛

每本书必须通过：

1. 所有角色 ID 唯一，别名无歧义。
2. 技能、功法、装备和势力引用全部存在。
3. 早期阶段不得拥有后期才获得的能力或装备。
4. 已死亡或未登场人物不得出现在错误阶段。
5. 专属能力不能分配给无权角色。
6. 人物地点必须存在于共享地图或明确列入未解析地点。
7. 观察面板展示外貌、性格、技能、装备与当前阶段一致。
8. 保存并重载后正典资料和阶段状态不丢失。
9. AI 互动上下文包含正典资料，且不能用随机生成内容覆盖。
10. 每类规则至少包含一个失败用例或边界用例。

## 9. 执行顺序

1. 完成并接入共享地图。
2. 新增角色正典、阶段快照、技能和装备 Schema。
3. 先以《六朝清羽记》试跑完整流水线并完成游戏验收。
4. 固化抽取 Prompt 和校验器。
5. 运行《六朝云龙吟》和《六朝燕歌行》。
6. 最后做跨书统一 ID 与冲突复核。
