## 实施建议与边界

1. **存储/来源/在场先落地。** 在actorMemory[id]补recent（最近3条），复用episodes上限12；每条含receiptId、事件类型、subjectId/objectId、目击id、heardFromId、统一时间序号、可渲染的事实引用。原著固定动作与战斗结算用同一个事件适配器；入离场在代码提交事件前完成。读正文、点名、LLM维护的位置都不产生目击者。
2. **好感与记忆一次提交。** 一个settledReceipt一次写两边，去重/更正也一次处理两边；跨关保留同一id的recent/episodes和去重信息。状态本身不存记忆，只有「为谁受伤」的已结算起因可以记；角色伤情仍读状态载体。
3. **模型事件小票只作提议。** 白名单动词+对象id+确定/不确定+原话依据；代码验过在场、动作来源及对应回执后才收。小事可通过本地白名单形成回执；救命/背叛/揭身份等大事必须另有代码结算，模型不能升格。不确定丢弃；更正只撤被引用的可更正小事回执，不能撤原著承重事件或秘密事实。
4. **面板/演出统一消费。** 代码选当前对话1–2人；每人recent3+相关episodes2，上限由代码截断。相关性按角色/事件/议题标签，不做全书检索；每次渲染查询称呼账本，不存显示名。正式剧情、自由回合、新战斗宿主都接同一消费函数；私有知情继续走原门。
5. **核验与新档。** 每20回合或切关异步核验，只输出报告；不让核验模型执行存档命令。可自动修的仅是明确回执/在场错配，其余留报告。新记忆协议标记仅新档启用，旧档明确提示开新档，不做兼容迁移；状态扰动记忆按32号§8留到后做。
