# 星月湖原游戏内体验校准（2026-09-20）

范围只覆盖现有星月湖隔离试玩的呈现层。这不是完整游戏交付，也不关闭 P0 / B1 / G2。

## 改了什么

把原先“五个承重事件测试串”的入口和游戏内提示，改成玩家能亲自评价目标、选择、节奏和结尾的连续校准段。原游戏界面、自然输入、真实判定、存读档、既有分支合同都保留。

- 入口改为玩家视角：当前在海神殿、谢艺有事只说这一次、先听清再回话。默认不列出五个承重事件，不剧透生死结果、骨灰或后续资源。测试清单放进默认收起的说明。重置已有试玩前必须确认；正式档不动。
- `/game` 内新增仅此试玩可见的轻量 HUD。当前目标、阶段名、继续旅程提示和结尾回顾都从本地 runtime flags / pathReceipts / activeEventIds / pending judgement 推导，不是固定全剧情列表。
- 鬼王峒在玩家真正面对抉择时，说明眼前两种行动的可知代价：陪说完 vs 施针护持。救治需正式判定，不保证成功，不提前宣称死亡。
- 试玩结束后才显示回顾。命运只写死亡或存活长养；接应、认领、资源处理权分别有回执才出现。听清可用资源不会写成背包到账。谢艺口径无“失踪”。
- HUD 内可收起的本机反馈：不知道做什么 / 不知道为什么 / 选择没区别 / 节奏拖沓 / 其他，加自填。导出 JSON 只含阶段、当前 event IDs、玩家主动文字和时间；明确仅本地、不发送外部。

未改：canon、builtin、核心 prompt、runtime 结算、strictInitializer、存档 schema、服务、API 配置、晋宋提案、国家线、原有生成机制。

## 用户怎么从主页进入

1. 打开游戏主页。
2. 点「星月湖任务线试玩」。
3. 读当前困境和近期目标后，点「建立试玩角色并开始」。若已有试玩档，可「继续上次试玩」；点「重置并重新开始」会先确认，避免误删试玩进度。
4. 进入正常 `/game`。上方 HUD 只显示当前已发生的目标或阶段；旧战/命运完成后，用原有的「继续旅程」启程。
5. 走完星月开库这一拍后，HUD 给出基于回执的回顾。反馈可写可不写，不挡游戏。

## 体验校准要问的问题

这段用于校准“好不好玩”的标准，技术测试不能替用户作出体验结论。请用户亲自看：

- 是否知道此刻该做什么、为什么要做。
- 鬼王峒两个选择的可知代价是否清楚，会不会感觉没区别。
- 旧战/命运结束后，“继续旅程”是否及时出现，会不会误以为已经到了下一幕。
- 结尾回顾是否只反映自己走过的分支，会不会把听说的资源当成已经进口袋。
- 节奏是否拖沓，卡在哪一拍。

## 2026-09-20 窄修（呈现层）

只改体验纯函数、HUD、体验测试和本文件。未改 runtime、存档 schema、canon、核心 prompt，也未 commit。

1. HUD 作为 `MainGamePanel` 的 flex 子项，限制 `max-height: min(42vh, 22rem)`，自身 `overflow-y: auto`、`min-height: 0`、`flex: 0 1 auto`。默认收起时仍只占几行；展开反馈或鬼王峒选择时在小屏也不再挤掉正文输入。
2. `settledXieyiFate` 在 `status=dead` 且 longrest 分支旗标同时成立时返回 null，不选一边。接应、认领、事务权若两侧回执同时存在，对应回顾字段为 null，不输出矛盾句。未结束仍无回顾。
3. HUD 可见句去掉“落账 / 这不是判定 / 启程尚未发生 / 不是物品到账”等技术口吻；保留「继续旅程」、确认判定、神识消耗、不保证留下、可用支持需另行领取。
4. 反馈首次改字或改标签时锁定最小上下文（stageId / activeEventIds / capturedAt），导出该快照；提供「清除／新建本条反馈」。不自动导出、不外发。导出不重置已写文字。
