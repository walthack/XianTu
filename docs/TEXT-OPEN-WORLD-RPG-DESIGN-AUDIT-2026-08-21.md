# 六朝文字开放世界 RPG 定位体检（2026-08-21）

## 文档定位

本文记录“六朝若定位为文字类开放世界 RPG，下一阶段应补齐什么”的产品判断与优先级。

它是设计方向与排期依据，不是已经批准的运行时 schema，也不授权直接改 canon、核心 prompt、事件 ID 或存档合同。具体实施仍应先做窄纵切，再按真机结果决定是否扩量。

## 实施状态（2026-08-21）

五原窄纵切的 P0/P1 本地合同已经实现，范围仅覆盖战后进入五原至白湖商馆这一小段，不代表全项目开放世界改造完成：

- 通用空间／行动／后果账已经落地；
- 五原市集到点心铺有显式路线、到达回执与一条需现场消息解锁的替代路线；
- 点心铺既定落奴拍有两种过程合同，失败会产生新状态而非原样重试；
- 固定消息先于动态生成，来源与可信度对玩家可见；
- 凝羽、苏妲己以已有角色 ID 提供白湖阶段的稳定 presence，早期选择有 4 轮与 12 轮回响；
- canon_companion 与 world_sim 共用局部能力，但 world_sim 不获得 Canon Rail 完成权；
- 未修改 canon、核心 prompt、事件 ID、条件或王哲锦囊用途。

完整自动化与生产构建已通过；尚未完成“从草原开场连续人工玩到五原”的真机叙事验收，因此本文后续的 30–40 回合玩家视角指标仍是放量前门槛。

## 总判断

六朝已经具备一套较强的正典互动叙事与世界因果底座：三级任务、确定性事件链、A／B 两类推进、场外结算、分歧账本、知识边界、NPC 记忆、关系姿态、本地判定和物品交易均已有可运行部分。

当前缺口不是内容量，而是这些系统尚未完全汇成玩家能够反复感知的开放世界 RPG 循环：

> 获取局势与人物欲望 → 自己决定去哪里 → 用角色能力解决问题 → 承担成本与失败 → 世界和人物可见变化 → 产生新机会或新麻烦 → 留下玩家自己的历史。

因此，下一阶段不应优先继续扩写大量 event、征兆或人物卡，而应先证明上述循环在一个 30–40 回合纵切内稳定成立。

## 已有地基：保留并继续复用

以下方向已经正确，不应另起平行系统：

- 三级任务仍只有主轴、二级任务线、人物任务；动态委托不是第四级正典任务线。
- A 类事件等待玩家；B 类事件在世界时限到达后场外结算，玩家只能通过可信渠道获知。
- 本地合同、NPC 决策与场外结算写世界真值；LLM 只负责人物化与场景化表达。
- 重大分歧继续走本地判定 → 待确认分歧 → 玩家确认 → 原子写入分歧账本／既有 IF。
- 未确认知识、私有知识、流言和世界真值继续分账；不得用全知事件描述喂给模型。
- 物品继续走 catalog、transferId 与幂等交易回执，不回退到“正文说获得就补背包”。
- objective 只写当前可执行方向，不提前写成功结果；制作侧 reviewSummary 不进入玩家 UI 或叙事 prompt。

## P0：先补开放世界的承重地基

### P0-1 显式移动与空间规则

现状中的位置主要是一个可被 LLM 改写的三层字符串，不具备可靠的出发、途中、到达、耗时与可达性。国家线地点入口、人物在场、世界时限、跑商和动态委托因此都缺少硬地基。

最小能力：

- 地点连接图与稳定地点 ID；
- 显式移动动作：出发地、目的地、路线、耗时；
- 三层位置的结构化解析与到达回执；
- 已发现／未发现路线和相邻可达性；
- 安全慢路与危险快路等至少一种真实取舍；
- 途中事件只能消费当前路线、当前时间和玩家已知事实；
- 禁止模型用正文直接把玩家瞬移到不可达地点。

这不是先做完整大地图。首版只需覆盖纵切内 3–5 个地点及其连接。

### P0-2 收拢核心玩法动词

战斗、修炼、技能、装备、货币和本地判定已有地基，但玩家还需要一组稳定、可理解、可重复使用的解决问题方式：

- 交涉；
- 调查；
- 战斗；
- 潜行／脱身；
- 修炼／疗伤；
- 交易／跑商。

首版不要求六类全部铺开。纵切至少选择三类，让同一问题可因角色能力、装备、关系、知识或资源不同而形成不同路径。

统一闭环应为：玩家自然输入或结构化选择 → 当前场景合法动词匹配 → 本地 preflight／判定 → 成本与结果落账 → LLM 渲染已结算事实。自由输入不应失去合同身份，按钮也不应成为剧情遥控器。

### P0-3 深拍的延迟后果

不是每个 event 都需要分叉。只把“换一个合理玩家，下一拍会不会不同”为真的节点升为深拍。

每个深拍至少声明并验收：

1. 当轮可见反馈；
2. 3–5 轮内的一次 NPC 或局势反应；
3. 10–20 轮内的一次任务、地点、势力、价格、关系或人物行动回响；
4. 失败／部分成功形成的新局面，而不是原样重试；
5. 编年史能说明“因为玩家做了什么，所以世界怎样改变”。

优先增加高质量后果包，不按数量批量制造 IF。

## P1：让开放世界持续有事可做

### P1-1 动态委托／机缘接入运行时

复用 `DYNAMIC-LLM-QUEST-DESIGN-2026-08-21.md` 的既有边界：任务必须先有世界内触发物，LLM 只提交受候选集合约束的草稿，本地合同冻结来源、目标、生命周期、验收、奖励和幂等回执。

完整的送货、赴约、护送和追查需要可靠到达回执，因此动态委托与显式移动应在同一纵切中串联，但实施顺序仍是先建立最小移动合同，再注册任务。

### P1-2 成长、经济与声望互相消费

物品、技能、装备、货币、地区立足度不能只存在于面板；它们需要改变玩家可选择的解决方式。

建议关系：

- 地区声望解锁人脉、价格、情报和进入权限；
- 功法与装备提供新的行动能力或判定因子，而非只加抽象数值；
- 伤势、时间、金钱与人情形成选择成本；
- 跑商影响少量可感知的地区供给、人物处境或委托类型；
- 六阳成长由师承、材料、风险和选择共同推动，不只是一条自动增长的进度条。

首版不做复杂供需模拟，只做有限、可解释、玩家能感知的差异。

### P1-3 承重 NPC 的生活逻辑

不模拟全库角色。每条二级线先选 2–3 名承重人物，保证他们具备：

- 当前欲望、困境和不可变底色；
- 可解释的所在地与移动原因；
- 对玩家承诺、帮助、伤害和缺席的长期记忆；
- 玩家不在场时也可能采取的本地行动；
- 随关系姿态改变投入程度与表达方式，但不改人格、知识权限和世界事实。

“世界活着”的主要证据应是人物主动做事并留下痕迹，而不只是更多环境征兆。

## P2：玩家可读的信息与节奏

- 新事件激活时用世界内的人话告诉玩家发生了什么、现在可往哪里追，不显示内部 ID。
- 流言显示来源与可信度层级，不把 rumor 表现成 confirmed。
- 地图只显示玩家已知地点和路线，不做全知地图。
- 编年史强调因果，不堆状态流水账。
- 枢纽事件使用半预制文本、BGM 与演出节奏；日常段落保留 LLM 的质感发挥。
- 保持“模型可以发明质感，不可以发明去处”：闲聊可以自由，新的可执行方向必须有本地合法来源。

## 推荐下一里程碑：五原商馆 30–40 回合纵切

范围建议落在清羽开局、五原商馆及相邻可达地点，复用现有清羽 Demo、王哲锦囊交易和动态委托设计，不新开大范围内容线。

纵切至少包含：

1. 3–5 个可靠连接的地点；
2. 两条代价不同的移动路线；
3. 一条当前二级任务入口；
4. 一条 `npc_request + player_dependent` 动态交付委托；
5. 一个可用交涉／调查／战斗中至少两类方法解决的问题；
6. 一个错过后由世界自行结算、玩家只能事后得知的 B 类事件；
7. 一件稳定获得且在后续行动中真正有用的物品；
8. 一名 NPC 在十轮后根据玩家行为主动回应；
9. 一次失败或部分成功继续生成可玩局面；
10. 保存、刷新、重试不重复发奖励，不遗失路线、任务或后果。

### 玩家视角验收

- 前 15 分钟能说清身处何地、能去哪、为什么值得去；
- 玩家可以连续偏离固定任务 20 轮而不死锁、不被文字催回、也不失去目标；
- 三次游玩至少出现两条结构性不同的解决路线；
- 早期选择在 10–20 轮内重新产生可见后果；
- NPC 不只复述变化，而是采取不同动作；
- 失败至少一半情况下形成新局面；
- 无瞬移、无提前泄密、无正文越权落账；
- 测试者最后讲得出“这是我造成的故事”，而不只是复述原著。

## 明确不做

- 不先为 37 个 stage 继续批量增加 event、征兆或机会卡；
- 不模拟全库 NPC 日程；
- 不新增饥饿、天气耐性等大批生存数值；
- 不让 LLM 自由创造地点、神器、功法、任务完成和世界真值；
- 不把开放世界做成满地图感叹号；
- 不以自动化全绿代替真机文本、知识边界和长期乐趣验收。

## 推荐实施顺序

> 显式移动与地点回执 → 纵切所需核心玩法动词 → 深拍延迟后果 → 动态委托 → 成长／经济消费 → 承重 NPC 生活化 → 表现层扩量。

在纵切通过以前，新增内容应优先服务这条循环，而不是扩大总量。
