## 三、样板真机问题与修复

燕歌长存档真机首次触发班超段时，暴露出四项运行时问题：

1. 长存档状态与完整剧本 prompt 重复发送，使 149k 输入再叠 16k 输出预算，超过兼容端点 163,840 上下文；
2. 普通拍点的 120 字摘要上限截断了半预制高光后半段；
3. `critical:false` 事件虽然不抢主轴，但玩家点名时也没有进入当前叙事 prompt；
4. 模型把布尔完成值输出成字符串 `"true"`，并把纯文本临时角色田荣创建为永久关系 NPC。

对应收口：

- 主叙事状态去掉重复的 runtime canon/chapter/event 正文，并把默认输出预算封顶为 8192；
- `半预制高光：` 合同保留至 600 字，逐拍注入“全部演完才可完成”的硬约束；
- 玩家点名事件或相关正典角色时，只额外召回一个已激活的非阻塞高光，不改变主轴锚点；
- 精确声明的完成键允许把 `"true"` 规范化为 `true`，其他 flag 不放宽；
- 非阻塞高光增加 `completionEvidence`。本轮正文同时命中全部证据时由本地确定性落账，不依赖模型二次判断；
- 未列入“相关正典”的纯文本临时角色只作场景演员，不创建持久身份或关系状态。

真机复验中，班超段完整出现羊腿、刀尖、吉策、九门出入记录、田荣与差事六项证据；随后
`flags.event.highlight_banchao_lamb_leg.done` 从 `undefined` 落为 `true`，当前主任务仍是
`s01_08`，证明可选高光完成但没有抢走 Canon Rail。董卓生还 IF 的替代文案链未改。

## 五、小圈子内测卡

第一轮建议仍使用燕歌行第一关新档观察两段；第二轮从清羽、云龙各抽一条观察跨书复现，
不要求测试者知道原著。

每位测试者记录：

1. 董卓段结束后，能否复述出他的三层人物感受：枭雄气、黑色幽默、边将警觉。
2. 贾文和是否像克制送别，而不是模板化嚎哭或突然殉死。
3. 班超出场后，测试者是否明确认为“这一场属于班超”。
4. 羊腿动作是否有画面感，九门记录是否把“莽”翻成“有备而来”。
5. 替田荣谋职是否形成恩威反差，而不是削弱镇场力度。
6. 两段 BGM 是否分别形成挽歌／权谋节奏，切换是否突兀。
7. 新班超事件未触发或被玩家绕开时，`s01_08` 及后续主线是否仍能推进。
8. 董卓生还 IF 下是否完全避开默认死亡文本，同时仍保留凉州旧部收束和边地军情。
9. 王哲、易虎、林冲三段能否各自保留表中列出的因果链，而不是被压成一句结果摘要。

通过建议：至少 3 名外部测试者中，2 名以上能在不看提示的情况下说出上述人物反差；不存在主线阻塞、旧 IF 串线或 BGM 错位。
