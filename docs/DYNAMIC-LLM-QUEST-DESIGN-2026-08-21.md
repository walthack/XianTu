# 动态 LLM 委托／机缘设计（2026-08-21）

## 结论

随机 LLM 任务可以放，但它不属于第四级正典任务线。

现有层级仍然只有三层：

1. 主轴：决定终局能否成立的承重条件。
2. 二级任务线：宗派、国家、商道与太泉远征等可选长线。
3. 人物任务：挂在上级 event 下面、因某人是否在场而改变的插入段。

随机内容另设为“动态委托／机缘”。它只能消费当前已经成立的世界事实，不能反向改写三级线、正典事件或人物真相。

## 为什么不能继续复用“即兴目标”

`系统.扩展.任务追踪.即兴目标` 现在只是玩家侧跨轮备忘：记录玩家已经明确表达或接受的临时打算。它没有正式来源、完成合同、奖励预算、期限或幂等回执。

因此本轮把玩家称谓统一为“个人目标”。它不负责：

- 随机生成任务；
- 发物品、金钱或关系奖励；
- 推进或完成三级任务线；
- 代替 worldActor 的机会卡；
- 因模型一句“完成了”就落账。

## 与 worldActor opportunity 的边界

worldActor opportunity 是人工精选、与确定性 NPC 决策绑定的过程机会。它可以改变参与方式、NPC 记忆和一次性权限，但不改变 Canon Rail。

动态委托更轻：它来自当前地点的普通需求和机缘，不要求预先为每张卡写死内容，但必须经过本地合同注册后才成为任务。

两者关系如下：

| 系统 | 来源 | 是否可由 LLM 起草 | 谁验收 | 能否改正典 |
|---|---|---:|---|---:|
| 三级任务线 | 人工正典任务数据 | 否 | 本地 event 合同 | 否，除显式 IF |
| worldActor opportunity | 已裁定 NPC 行动 | 只演出 | 本地机会合同 | 否 |
| 个人目标 | 玩家明确意图 | 只做低温整理 | 后台目标审计 | 否 |
| 动态委托／机缘 | 世界内触发物＋LLM 候选 | 是 | 本地动态任务合同 | 否 |

## 世界内触发

动态任务不能靠右栏“刷新任务”按钮出现。必须先有玩家可见的世界内触发物：

- 已登场 NPC 当面请求；
- 当前地点的告示、悬赏或商队委托；
- 玩家实际捡到的物品、信笺或现场痕迹；
- 玩家已听见且来源明确的本地传闻；
- 已结算 NPC 行动留下的余波。

LLM 只能在本地提供的候选人物、地点、物品、势力和事实集合内组合。集合外的名字、远方地点、秘密组织、法宝或真相一律拒绝。

## 两种生命周期

### A. 个人委托型

玩家不推进，任务就静置。适合送信、帮人找物、答应赴约等以玩家行动为必要条件的事。

- 没有世界截止时间；
- 不自动完成；
- 可以由委托人撤回，但必须有新的本地事实；
- 玩家接受后才注册为 active；未接受只是一段对话。

### B. 世界时限型

玩家不推进，世界也会自行结算或让机会失效。适合护送窗口、限时收购、即将离港的商队、持续扩大的现场危机。

- deadline 由本地规则按任务种类给出，LLM 不填具体回合数；
- 到期只写 offscreen 结果或 expired，不伪记玩家完成；
- 未公开的结果不进玩家任务栏，须经可信消息渠道获知；
- 不能抢先结算三级线承重事件或带正式 IF 的生死节点。

## 本地合同

LLM 只提交候选草稿；引擎注册时补齐并冻结合同：

```text
id                       引擎生成的稳定 ID
source.kind              npc_request | notice | item_clue | local_rumor | world_aftermath
source.factIds           已落账事实／回执 ID，至少一条
source.characterId       可选，必须已登场且可见
source.locationId        必填，必须是玩家当前地点
title                    4–18 字
objective                12–50 字，当前可执行，不写结果
lifecycle                player_dependent | world_timed
completion.kind          deliver | investigate | escort | recover | negotiate | defeat_local_threat
completion.targets       只能引用候选集合中的稳定 ID
reward.kind              inventory_transfer | currency | local_attitude
reward.budgetClass       trivial | minor | standard，由本地规则换算
createdAtWorldTurn       引擎写入
deadlineWorldTurn        仅 world_timed，由引擎计算
status                   offered | active | completed | failed | expired | withdrawn
receiptId                完成／失效时写入，保证幂等
generatorTrace           模型、提示版本、候选哈希，只供审计
```

LLM 不得直接决定实际物品 ID、数量、金钱数值、关系数值、deadline、任务 ID 或完成状态。它只能在本地提供的枚举与候选中建议。

## 验收与奖励

完成必须由本地可验证事实命中合同，例如：

- 指定物品的本地转移回执；
- 玩家与目标 NPC 同地且对话行动回执完成；
- 指定本地判定／战斗 resolution；
- 指定地点到达回执；
- worldActor 已裁定的局势结果。

叙事正文里的“我已经送到了”“敌人都死了”不能单独完成任务。

物品奖励统一走 `inventoryTransactions`，用 `transferId` 幂等发放；金钱和关系奖励必须使用封顶数值与独立 receipt，同一任务不得重放奖励。

## 生成门禁

候选草稿必须同时通过：

1. 来源接地：至少一条当前可见的本地事实。
2. 地点接地：目标发生在当前地点或已知相邻地点，不跳阶段、跨国或瞬移。
3. 人物接地：只用已登场、玩家已知的人物与势力。
4. 知识边界：不把 rumor 升为 confirmed，不泄露私密关系或未来身份。
5. 目标可验：能翻译为 allowlist completion.kind 和稳定 target ID。
6. 奖励可发：只落已有物品目录或封顶资源，不让模型造神器、功法、丹药。
7. 正典隔离：不能写主轴／二级／人物 event 的 done、void、IF、关系真值或世界结局。
8. 频率限制：同时 active 最多 3 条；同一来源、地点、目标组合有冷却和去重哈希。
9. 文字安全：目标只写当下动作，不预写成功、死亡、俘获、背叛或谜底。

## Demo 建议

先做一条 `npc_request + player_dependent` 的低风险纵切：五原商馆内，由已经在场的普通 NPC 请求把一件目录内普通物品交给另一个已登场人物。

验收只看物品转移回执，奖励只用少量金钱或本地态度，不碰三级线、正典生死、技能和关系真值。等这一条真机验证了“出现—接受—完成—幂等奖励—读档不重发”，再加 world_timed 型。
