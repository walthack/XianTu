# R2-16 确定性叙事事实回执 G1 + G2

日期：2026-07-31

## 目标

R2-14 已经建立负面边界：跨拍承接没有结构化来源时，正文只能定性描述损失。R2-16 补上正面通道：

- 事件数据可声明由本地动作结果确认的精确事实；
- 只有实际命中对应 `actionId + outcome`、且事件已经由引擎结算后，该事实才进入跨拍承接；
- LLM 可以逐字引用回执，但不能改变主体、数量或结果，也不能借一条合法回执夹带其他精确损失；
- 没有回执的事件继续沿用 R2-14 的定性边界。

这不是把世界真值写回权交给 LLM。回执由事件数据和确定性动作结果共同产生，正文仍然只是渲染消费者。

## 数据合同

事件级可选字段：

```ts
narrativeFactReceipts?: Array<{
  id: string;
  actionId: string;
  outcome: 'success' | 'partial' | 'failure';
  category: 'loss';
  claim: string;
}>
```

第一条纵切位于 `lcq.event.s04_02`：

> 武二郎与苏荔联手击杀九名鬼王峒武士

字段刻意放在 `playerCompletionContract` 外，因此添加展示事实不会改变合同 hash，也不会重置进行中的动作进度。

## 运行时边界

1. 动作尝试只快照与实际 `actionId + outcome` 匹配的回执；
2. 仅事件完成后的 `lastSettledBeat` 向下一拍携带回执；
3. 活跃事件和普通动作尝试中的回执会从通用 prompt state 剥离，避免完成前泄漏；
4. 承接 prompt 只投影已落账回执，并要求精确逐字引用；
5. 门禁先从句子中移除合法原句，再检查剩余文本中的精确伤亡／货损；
6. 改写主体、改写数量、增加另一方损失或增加尸体数量都会触发缓冲重写。

## G2

Codex 使用正式 8091 UI、真实 LLM 和临时存档槽，从 `lcq.event.s04_02` 执行固定主线动作：

- 本地动作尝试以 `success` 落账，`worldTurn 0→1`；
- `s04_02` 完成，`s04_03` 激活；
- `eventActionStates.s04_02.attempts[0]` 与 `lastSettledBeat` 各持有同一条事实回执，均无重复；
- JSON 存档读取后回执、完成事件和下一事件保持；
- 承接回合中模型没有选择引用“九名”原句，而是首次补写“草席下两具尸体”，真机由此发现尸体量词覆盖缺口；
- 补充负例与门禁后复跑，最终正文只保留“几具／几个／好些”等定性表述，不再出现额外精确损失。

精确回执是“允许引用”而非“必须引用”。本次模型没有逐字复述该事实，因此正向放行由确定性 G1 覆盖；G2 证明了回执的真实动作落账、存档持久性和额外精确损失的运行时重写。

临时槽已删除，角色列表、原手动槽与当前激活槽已恢复；`上次对话` 恢复为当前 `R2-13基准` 的完整进度副本。

## 结论

R2-16 G1 + G2 通过。后续事件如需允许精确数字，必须先有同类结构化回执；不得通过放宽全局数量正则解决。
