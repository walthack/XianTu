# R3-8 角色表演卡 · MiniMax 六角色预扫

> 日期：2026-07-18
> 性质：**只读候选审计，未获用户裁定，不得写入 canon / OVERRIDES / prompt。**
> 模型：MiniMax-M2.7（`mmx-cli`）
> 范围：小紫、秦桧、朱老头、月霜、吕雉、贾文和

## 1. 扫描口径

按 `RELEASE-ROADMAP.md` R3-8 的 Voice Card 提案扫描：

1. 自称 / 对主角称呼 / 他称 / 禁称；
2. 可作 few-shot 的原文短台词；
3. 行为签名：`触发场景 → 可观察动作或策略 → 对剧情决策的贡献`；
4. 可检测的 OOC 禁忌；
5. 有原文证据的阶段变体；
6. 两个试演场景及成功标准。

输入为三部 EPUB 中角色名命中片段（每人跨章节抽样 8 组）和现有角色卡的相关字段；露骨片段预先过滤。提示词明确禁止使用预训练记忆补全、泄露未决秘密或直接改数据。六人拆成两批运行，避免单次上下文过大。

## 2. 结论

### 推荐进入人工考古 / 试演

| 顺位 | 角色 | 适合验证的表演维度 | MiniMax 抓到的有效方向 | 当前风险 |
|---:|---|---|---|---|
| 1 | 小紫 | 高智力、伪装、机趣、阶段反差 | 早期装弱与后期冷静掌控必须分门控；危机中应亮后手而非只当汇报器 | 模型会把推断写成秘密身份或绝对情感规则，须严审 |
| 2 | 贾文和 | 冷面谋士、短句决断、主公补位 | 适合用“一句判断改变行动方向”表现智谋；能与纯信息汇报拉开 | 很容易被写成无情绪的工具人，需补个人化微反应 |
| 3 | 朱老头 | 滑稽伪装与高人底色反差 | 日常耍贫与关键时刻收声出手的切换很适合行为合同 | 身份秘密与出手阶段必须由 per-stage 门控保护 |
| 4 | 秦桧 | 圆融谋士、利益换算、反问引导 | 能用观察细节、拆解多方诉求来体现“七窍玲珑” | MiniMax 自造自称与忠义姿态较多，称谓证据不足 |

### 暂不建议直接制卡

| 角色 | 原因 |
|---|---|
| 吕雉 | 抽样覆盖不足以支撑阶段称谓。MiniMax 恰好生成了“委身后自称奴婢”等无输入证据规则，这与台账 #15 的语域污染风险正面相撞；在逐章台词考古完成前不得落任何阶段称谓。 |
| 月霜 | 模型把冲突片段概括成“智商短板 / 双标 / 纸老虎”，容易把复杂角色压成贬义标签；需要先扩大非冲突、战场和独处片段的采样，再谈常驻行为签名。 |

## 3. 可保留的行为合同方向

以下只保留结构，不把 MiniMax 的措辞视为正典：

### 小紫

- 情报或危机场景：先给出别人尚未注意到的信息差，再亮出已经准备好的后手；不得只来急报、领命。
- 被低估时：维持娇憨或若无其事的外壳，让对手自行暴露；在转折点用一个动作或短句收网。
- 点破算计时：语气应冷静、戏谑，判断必须改变当前方案或角色站位。
- 阶段门控：清羽早期的“装弱 / 反常无知”不能偷跑成后期全知的“紫妈妈”。

### 贾文和

- 主公犹疑时：用极短的事实排序或风险判断，把选择压缩到一两个可行动方案。
- 他人情绪失控时：不跟随情绪升高，以平淡措辞指出真正的利益或程序落点。
- 解释知识时：允许有轻微的无奈或熟稔感，但不能嘲弄主角、替主角拍板。

### 朱老头

- 日常：以抱怨、蹭便宜或装糊涂降低他人警惕，同时悄悄获得信息或位置优势。
- 真危机：先停掉耍宝音域，再用一个精确动作解决最危险的环节；不能每场都露底。
- 涉及旧事：少说、岔开或以反常沉默留下重量，不用说明性独白自曝秘密。

### 秦桧

- 多方交易：先列各方真正要什么，再指出表面条件与真实成本的错位。
- 商业 / 政治判断：用细节和反问引导主角发现结论，不替主角宣布决定。
- 对外圆融、对内清醒：同一场景中应能看到礼数与算计并存，而非单纯“忠臣表态”。

## 4. MiniMax 输出中必须否决的内容

这次扫描证明“模型草拟 → 用户裁定 → OVERRIDES”中间不能省人工证据层：

1. **称谓幻觉**：为秦桧生成“属下 / 秦某 / 会之”、为朱老头生成“俺 / 朱八八”等集合，但抽样并未逐项提供可核原句。
2. **把缺证当禁忌**：以“没看见角色表达某情感”为依据，反推“角色不得表达该情感”；这是典型的 absence-of-evidence 错误。
3. **秘密关系扩写**：跨角色总结擅自推断秦桧—朱老头、小紫—朱老头的隐秘机制，违反“不得从输入外补全”。
4. **阶段越界**：吕雉的阶段称谓在无直接台词证据时仍被填成可 lint 规则；此类输出若落库会把语域污染固化。
5. **标签化伤害**：月霜被压成“智商短板 / 双标 / 纸老虎”，把局部场景功能误当常驻人格。
6. **格式不服从**：多条所谓“≤20 汉字”语音样例超长，说明长度与原文包含关系都必须由代码验证，不能信模型自报。

## 5. 对正式生产管线的约束建议

正式试点若获批准，建议把生产拆成确定性与生成式两层：

1. **证据层（确定性）**：EPUB 逐句索引角色发言；保存书 / 章 / 说话者 / 对话对象 / 原句哈希；称谓只从原句中抽取。
2. **草拟层（LLM）**：仅对证据层结果归组为行为签名和阶段变体，不得新增称谓或事实。
3. **机检层**：
   - few-shot 必须是原句子串且长度达标；
   - 每个称谓必须至少一个直接证据；
   - `forbidden` 不得仅由“未检出”推出；
   - 阶段变体必须绑定 stage / axis 范围；
   - 涉 `AFF_PROTECTED / AGE_PROTECTED / DEBUT_PROTECTED / USER_CANON` 或密档关系时自动拒绝。
4. **人工裁定层**：用户逐条圈选后才进入 OVERRIDES；未圈选项只留审计稿。
5. **试演验收**：仍按 roadmap 建议，以小紫做 selftest 前后各 5 轮对照；同时用贾文和作“冷面谋士不工具人”对照，才能判断行为合同是否具有普适收益。
