## 2. 新发现：`done` 是最后一块仍由 LLM 直接掌握的世界真值

> 定性经 2026-07-20 晚复核后重写。先前写作「模型指令遵循度问题」与中途的「世界引擎无法自主推进」
> **均不准确**，已作废。权威边界的完整界定见 `PROJECT-STATUS.md` §2.3。

### 现象

同一引擎、同一基准记录、同一批玩家输入（机会卡自带 `actionText`），只换主叙事模型：

| 主叙事模型 | R1 诏令 | R2 入宫 |
|---|---|---|
| `deepseek/deepseek-v3.2`（OpenRouter） | turn2 `done=true`，得 `permission.lyg.jia_wenhe.exchange_judgement` | turn1 `done=true`，得 `permission.lyg.huo_zimeng.trusted_intelligence` |
| **`MiniMax-M2.7-highspeed`** | **7 轮未完成 → 六回合上限到期 → 场外结算，零权限** | **同上** |

两条路线均复现，非偶发。

### 定位：不是门禁拒绝，是没有东西给它拒

R1 结果快照遍历 `系统.历史.叙事[].stateChanges.changes[].newValue.command`：

- 全程执行 **30 条指令**
- 涉及 `s01_05` / `剧本模组` / `done` 的：**0 条**
- 实际发出的是功法、丹药、技能等物品类指令

模型**具备发指令的能力，只是从不发剧本推进指令**。`guardScenarioModCommands` 没拒绝任何东西。

### 引擎侧无过错，且已证明能独立推进世界

- 机会卡按 R2-10G 六回合上限 `trackedAtTurn=1 → resolvedAtTurn=7` 精确 `expired`，转场外，回执写明「未伪记为玩家亲历」，零权限。
- R3 不介入 11 轮，`s01_05/06/07` 三事件的硬截止、场外结算、回执、零权限**全部零 LLM 参与**完成；三者 `done` 始终 `false`、不进 `completedEventIds`，用独立标记记账。
- NPC 冲突裁定同理，结果只进回执与 effects，从不碰 `done`。

### 真正的问题：真值写入权仍在叙事层

`commandValidator` 已把 `worldTurn / worldPush / actorEngine / eventTimeline /
offscreenResolvedEventIds / chronicle / divergences / steeringCooldown` 全部列为引擎专属、LLM 禁写。
**`flags.event.*.done` 是唯一例外**——它同样直接决定 `completedEventIds` → 回执 → 权限。

`canonGuard.findScenarioFlagViolation` 只执法**资格**（只能 set、只能写 true、路径形态、事件唯一可解析、
不得越级完成非当前章节/活跃事件），不执法**属实**。在允许范围内，模型宣称完成即为完成。

全库 380 个事件的 completion 条件均为 done 标志形态（364 + 16 变体），引擎可计算的 **0** 个。

### 目标与边界

**目标**：让 380 个事件都不再依赖 LLM 直接掌握世界真值——把 LLM 从**写真值**降级为**提交证据**，
由引擎按完成合同独立裁定并自行写 `done`，该路径进入 FORBIDDEN_PATHS。

**不是目标**：让 380 个事件都自主场外跑完。玩家亲历仍要靠玩家玩出来。

### 候选方向（待用户选型，勿擅自开工）

1. **机会卡确定性完成合同**：`opportunities` 声明可计算完成条件，引擎结算 `participated`，LLM 只叙述结果。改动集中在机会卡层，不动 380 个事件数据。
2. **completion 支持引擎可计算路径**：让 `completion` 能引用 `actorEngine.opportunityStates.<id>.status` 等运行时状态。更通用，但需逐关改数据。
3. **结构化证据提交**：LLM 改发「玩家做了什么」的结构化主张，引擎裁定后写真值。最贴合目标，改动面最大。

倾向 1（可作为 2 的前身），但属架构裁定，须用户拍板。

### 归属

本项**不是 G2 遗留缺陷，应升格为 R2 主线架构项**。模型差异只是显影剂，不是肇事者。

## 3. reasoning 行为（本轮查明）

- **应用侧不发送任何 reasoning 控制参数**。主请求体只有 `{ model, messages, temperature, stream, max_tokens }`（`src/services/aiService.ts:1422`）。思考完全由模型默认行为决定。
- **MiniMax 侧默认开启且关不掉**。实测 `reasoning_effort=minimal`、`thinking={type:disabled}`、`enable_thinking=false` 四种变体，思考量均无实质变化，且 API **不报错——未知参数被静默忽略**。
- 应用只在接收侧处理：`stripModelThinking` 剥标签（含无闭合标签的截断情形，不会泄漏给玩家），`content` 为空时回落读 `reasoning_content`。

### 档位差异（真实提示词实测）

| 模型 | 思考量 | 结果 |
|---|---|---|
| `MiniMax-M2.7`（非 highspeed） | 14810 字，吃满 8000 token | `finish=length`，**正文 0 字**，单次 138 秒 |
| `MiniMax-M2.7-highspeed` | 935–1628 字 | `finish=stop`，正文正常 |

思考 token 与正文共用同一 `max_tokens` 预算。**非 highspeed 的 M2.7 会因思维链失控产出零正文**，玩家侧表现为等待数分钟后拿到安全兜底文案（慢速失败，非错误输出）。

**结论：不是要关思考，是不要把主叙事配成非 highspeed 的 M2.7。**

## 4. 对 R2-10K 的更正

R2-10K 头部记「执行：Claude（真机 Playwright + 真实 MiniMax-M2.7）」**有误**。该轮实际主叙事模型是 **OpenRouter 上的 `deepseek/deepseek-v3.2`**。

原因：驱动器通过 `localStorage.api_management_config` 注入 MiniMax，但后端 `user_config_api_management_v1.json` 是权威源，覆盖了主叙事指派；注入只生效在次级功能位上。该错误已在 R2-10K 头部就地更正。

**首轮状态层结论不受影响**（确定性引擎与模型无关），但「文本层无泄漏」这一条的适用模型应读作 deepseek-v3.2。

## 5. 测试基建注意事项

已同步写入 skill `xiantu-game-selftest`，此处只列要点：

1. **不要注入 API 配置**——后端权威，注入只污染次级功能位，会造成主叙事／次级各走一个模型的混合状态。要改就改后端 `user_config_api_management_v1.json`，并用**全量网络捕获**确认生效。
2. **落定判据 = 存档内容增长**（`叙事`条数或 `worldTurn`）。「输入框恢复」只是发下一轮的前置条件，拿它当判据会把成功轮误判为失败（实测：正文 918 字、worldTurn 已推进，判据仍报 false）。一轮约 135–160 秒。
3. **R1/R2 首轮必须用机会卡自带的 `actionText`**，否则六回合到期退化为场外结算，看似引擎缺陷实为驱动输入太弱。
4. 网络捕获**别按域名白名单过滤**——按 `minimaxi` 过滤曾显示「0 请求」，实际应用一直在打 OpenRouter。
