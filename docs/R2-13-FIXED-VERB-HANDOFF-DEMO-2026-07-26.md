# R2-13 固定动词与跨拍承接 Demo

日期：2026-07-26

## 目的

验证一种不改变世界引擎真值合同的交互表现：

- 玩家继续可以自由输入；
- 引擎持有的确定性动作不再显示“主线推进／主线判定”；
- UI 按既有动作文字派生“观察、交谈、前往、攻击、使用、修整、行动”与当前目标；
- 上一拍完成后，下一轮叙事先演出余波与因果承接，再进入新拍；
- 跨关启程同时出现在主阅读面和右栏，直接调用确定性切关，不经过 LLM。

纵切选用 `lcq.stage_04` 的 `s04_05 → s04_06`：易虎岸边送别之后，下一拍为请求乐明珠替凝羽解毒。

## 权威边界

固定动词是纯展示层：

1. 不向 `playerCompletionContract` 增加字段；
2. 不改变 `contractHash`、`actionId`、`actionText`、`timeCost` 或 outcome；
3. 点击后仍提交原来的确定性动作 payload；
4. 无法可靠分类时必须落入“行动”兜底，按钮不得消失；
5. 动词不承担位置、物品、战斗或事件资格门控。

跨拍承接只保存上一拍 `eventId + settledAtTurn`、引擎当时确定的 `targetEventId` 与是否已铺垫余波的 `bridgedAtTurn`。提示词通过事件表反查名称、地点和当前 objective；该记录只服务表现层承接，不参与事件激活、完成或时间线裁定。

## 同批安全修复

- 带 `playerCompletionContract` 的事件现与机会卡合同一样，是旧 LLM 事件对账不可跨越的权威边界。
- 切关期间禁用入口并加 Store 级互斥；开始 AI 回合后若关卡已切换，旧关结果和后台对账结果均丢弃，避免覆盖新关存档。
- 删除“隐藏确定性按钮、依赖 LLM 对账追认”的设置及实现；确定性完成路径始终可见。

## Demo 验收

- `s04_05` 三步显示为固定动词、短目标与“第 k/n 步”，且无“主线推进／主线判定”字样；
- 多步事件 prompt 只允许演出当前步骤；完整 Canon Rail 明确属于跨多轮结果，不得在一轮内摘要、并拍或抢跑；
- 完成送别后 `s04_06` 显示“交谈 · 乐明珠”；
- 确定性入口带“主线／机会”标签并与 LLM 自由选项拉开视觉层级，点击后预填可编辑的玩家自然句；
- 上一拍承接尚未消费时只压一轮下一拍按钮，自由输入始终可用；
- 新拍 prompt 同时包含上一拍、当前入口和“只演出不改真值”边界；
- 七类动词均有派生回归，原始 action payload 保持不变；
- 跨关入口只在 `nextStageReadyId === nextStageId` 时出现；
- 玩家合同事件不会进入 LLM 事件对账候选链。

## 2026-07-27 Fixup G1

已按 `docs/R2-13-FIXUP-HANDOFF-2026-07-26.md` 收口首轮真机发现：

- 引擎导出当前合同步骤，`storyContext` 注入“本拍分步”硬边界，并移除与之冲突的单轮全拍要求；
- 目标兜底不再使用长篇 `event.objective`；人工短目标与玩家自然句使用事件级 `presentation`，不进入合同哈希；
- “袭击事件／躲避袭击”不再误判为攻击，“查明／查清／识别／辨认”进入观察；
- 新旧拍交接期间暂缓下一拍确定性按钮一轮，但不压自由输入。

自动化验证覆盖提示词、合同哈希、按钮标签、动词反例、展示字段校验和交接窗口。R2-13 仍是交互语法 Demo，不是全量 UI 定稿；翻绿前须用真机从 `s04_05` 空进度开始确认：第一轮正文止于救起易彪与年轻军士，不出现“巨石／吞没／磕头”，并观察按钮密度、预填句及跨拍过渡是否自然。

## 2026-07-28 G2 首轮后收口

HEAD `c64102a` 的同源真机复验确认三步不再并拍、合同 hash 与 preparations 稳定、按钮延迟和自然预填句生效，但发现三处同属本 Demo 的缺口：后续步骤词仍可能被正文提前借用；空档轮右栏提前显示下一 objective；承接提示在空档轮后被清除，真正点击凝羽解毒时反而失去“送别→毒发”的桥。

本轮按同一边界修复：

- 事件级 `presentation.stepGuardTerms` 为逐拍高光声明后续保留词，不进入完成合同或 hash；真实渲染门禁会缓冲违规正文、定向重写，末次仍越界才本地降级。`s04_05` 首步硬拦“千斤坠／巨石正中／洪水吞没／认兄／磕头”等后续结果，但允许“洪流裹挟巨石”这类不构成易虎受创的环境描写。
- 跨拍状态改为两阶段：首个余波回合同时隐藏按钮和右栏 objective；成功铺垫后恢复入口，但保留上一拍身份；玩家真正触发目标事件动作时再次注入因果承接，正文落定后才消费。
- 成功发送后清空可编辑输入框；分步模板剥掉动作文本尾部标点，避免双句号。

自动化覆盖保留词正反例、两阶段状态机、按钮／任务栏同窗隐藏、目标动作触发承接、合同外 schema 引用和成功发送清空。R2-13 维持 `[~]`，只待同一真机路线复验上述三点后翻绿；人称统一与自由选项丰富度另列通用叙事质量项，不阻塞本 Demo。
