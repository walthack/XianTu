# 任务推进机制讨论汇总（R3-12）

**状态：讨论中，未实施。** 用户 2026-08-18：「现在继续深入下去可能走得太细节了，
容易把你们的方向限制得太死。」故本文只记录**已确认的事实**与**已表达的意图**，
不含实现清单。

标注：〔核实〕＝已读代码/数据确认；〔意图〕＝用户表达的设计想法；〔判断〕＝Claude 或 Grok 的意见。

---

## 一、用户要的是什么〔意图，原话〕

> 「我本来设想是，这游戏就按照一个**传统游戏的任务系统**：你走到什么地方、见到什么人，
>  触发一段剧情，然后这样依次推进。**当中的描写 LLM 可以进行发挥，但是任务链是死的**。」

> 「我们故事线希望跟传统大世界 RPG 一样，是一个线性的关系。但是传统 RPG 里
>  **你看到的场景、人物，或者是一些城镇里面的那些随机消息，这些都是写死的**。」

> 「**我不是很想依赖提示词这种软性的限制，因为它不可能百分之百可靠。**」

这与项目自己的既定原则一致：**确定性调度定「发生什么」，LLM 只管「怎么讲」**。

### 用户报告的真机故障（多次复现）

> 「走到一个地方，见到了我觉得应该见到的人，和他聊天，**他却帮我掰扯一些跟原先剧情
>  毫无关系的东西，然后把我误导到另外一条线上，而且这条线在原著中并不存在**。
>  默认这是一个违反剧本的行为。」

> 「一个 event 结束，玩家进行一些动作，LLM 会自己生成跟下一个 event 毫无连续性的东西，
>  然后玩家就失焦。」

### 用户当时想到的对策〔意图〕

> 「通过在右侧的任务栏，每一次提示你当前任务的 objective（该做哪些事情，或者是该往哪个方向走），
>  玩家找到了那个人或者是那个地方，然后去触发它。」

## 二、引擎现状〔全部核实，2026-08-18〕

### 2.1 任务链**已经是死的**

`runtime.ts` 激活循环：遍历本章 `chapterEventIds`，若 `conditionsMatch(event.conditions)`
且 `eventTimelineOpen()` → 推入 `activeEventIds`。另有 `railProfile.orderedEventIds` 有序轨道
优先走 `nextRailEventId`。

**全部 event 的 `conditions` 只用两类路径**：`flags.chapter.<X>.started`、
`flags.event.<前一拍>.done`。即 A 完成 → B 激活，链式推进。

⚠ `locationId` 在 event 上存在，但**完全不参与激活判定**（`runtime.ts` 里仅出现 1 次，另有用途）；
`relatedCharacterIds` 同样不参与。**所以「走到某地／见到某人才触发」目前不存在。**

### 2.2 玩家看到的一切都是软的

| 层 | 硬 / 软 | 实测 |
|---|---|---|
| 任务链（flag 链式激活） | **硬** | 见 2.1 |
| 玩家/LLM 看到的「当前可切入点」 | **软，且与引擎不同源** | 取自 `worldSimulation.situations`，规则是「数组里第一个未结清的」 |
| situation 覆盖率 | — | **421 个可达 event 中 146 个（35%）没有对应 situation** |
| situation 顺序 | — | 4 个关的数组不按 `axisSeq` 排 |
| 作者写好的环境内容 | **软** | 816 句 `omen.observableFacts`，覆盖 99% 的 situation，三种传播渠道（环境／信使／相关 NPC）——但提示词结尾写着**「软性可忽略」** |
| 「本关主线节点」 | 软 | 把**整关所有节点文案拼成一行**喂给 LLM，不是「当前这一个」 |
| 推进纪律 | 软，且**方向相反** | 提示词原文：「没有需要玩家逐拍完成的任务，也没有进度惩罚……可把上述方向**搁置任意多轮**……**不得替玩家决定下一步**」 |

**结论〔判断〕**：链是硬的，但玩家看不到硬链——他能看到的一切都是软的，
而且提示词还在明确要求 LLM 不要推进。真机失焦是这五行的必然结果，不是偶发。

### 2.3 「违反剧本」的执法层拦不住这类违规

现有四层全是**实体级**：

| 层 | 拦什么 |
|---|---|
| `stripNarrativeEntityTypeConflicts` | 人名被写成兵器／坐骑／功法／物品／同名新角色 |
| `stripNarrativeUnintroducedCharacters` | 提前登场的人物 |
| `guardScenarioModCommands` | LLM 直写受保护状态路径（JSON 指令层） |
| `buildScenarioCanonPrompt` | 提示词层的正典约束 |

**没有任何一层能拦住「NPC 聊一件原著没有的事，把玩家引去一条不存在的线」。**

### 2.4 事件本身的设计深度

- 421 个可达 event 中，**32 个（7.6%）**带 `worldActor`——含 `decisionCore`（NPC 议程、人格、
  可选动作、状态量、`canonPolicy.processFreedom`）与 `opportunities`（机会卡＝真分支，
  带 `stakes` 代价与 `futureHint` 长期后果）。
- 分布是 **22 个关每关 1–4 条**，四个子字段数量完全相等 → 像是**每关一条样板**（纵切），
  不是「做了 8% 没做完」。
- 其余 389 条只有一个通用完成动作。
- 用户对此的态度〔意图〕：「**不是所有的 event 都需要这样设计，有一些只是场景描写。
  只有比较重大的场景（比如"五军覆灭"这种）**」——即 8% 这个比例本身未必是问题，
  但「哪些该做成 8%」需要另行判断。

### 2.5 一处已确认的设计冲突

节点文案 `node.text` **同时**被三方使用〔核实〕：
- `RightSidebar.vue:485` → 直接显示给玩家
- `storyContext.ts:840` → 喂进 LLM 提示词

而 2026-08-18 上午按「句子契约」重写的 234 条文案，要求写清「带走什么」——
**这对审阅是需要的，对玩家却是剧透，对 LLM 则是提前给了结果**。
用户的表述：「任务描述会提示玩家和王哲进一步交谈，**但不会说进一步交谈会得到什么结果**」。

⚠ 一个字段同时服务「审阅可读」与「玩家不剧透」两个互斥需求——这是当前未解的结构问题。

## 三、已经提过但**尚未采纳**的方向

以下均为讨论产物，**用户尚未拍板**，且用户提示「不要走得太细节」：

- Grok 补充：`railProfile` 有轨走轨；`situations` 保留其 omen/结清职责；
  完成与激活须在同一 tick 以清掉空窗期；HUD 由引擎渲染；

- Claude 补充：那 816 句作者写好的环境内容应从「软性可忽略」转为供给侧素材——
  给够素材，LLM 就不必编。

## 三点五、**已定裁定**（用户 2026-08-18）

### ① 推进模型 A / B〔用户原话，已确认〕

> 「**设计 A**：正常情况下我们默认推进的方式。世界推进到一个节点，然后就等着玩家再继续。
>  玩家如果没有继续，那个节点就等着。
>  **设计 B**：如果在某些 event 中加入时间限制，而玩家其实没有去推进，一旦时间限制超过，
>  就走 B 方式。这好比汉朝那一段，如果我们没有入宫去亲眼见证刺杀皇帝，而是一直迟迟不肯推进、
>  在外面瞎逛，最后可能就会通过**一则传言**来告诉玩家：皇帝已经被刺杀了。」

**这就是引擎现有的模型**〔核实〕：A ＝ 无时限等待；B ＝ `offscreenResolution`
（`afterStallTurns` 超时 → 世界自行结算 → `worldDelta` 作为传言送达，且**不计作玩家完成**，
不给好感与声望）。用户举的汉宫例子已完整接线（seq 894／896／897／899 四拍，超时 7–9 回合）。

覆盖现状：421 条可达 event 中 **A 397 条（94%）／B 24 条（6%）**。
**哪些拍该转 B，判据未定。** 候选判据〔Claude 提，未采纳〕：「不依赖玩家也会发生的世界事件」走 B，
「非你不可、冲着玩家来的」走 A。

⚠ Claude 曾提「(b) 世界主动送线索把玩家拉回」，**用户否定了这个形状**：
不是"拉回"，是"**错过就是错过，世界照常运转，你只能听说**"。

### ② 深浅判据〔用户确认 Grok 版本〕

不问小说里重不重，问**这一拍之后世界会不会因玩家而分叉**。
试金石：**换一个合理玩家，下一拍是否仍是同一拍？** 是＝描写拍（浅），否＝抉择拍（深）。

> 用户：「这个"深浅牌"的想法，我觉得它的定义的确更准确。
>  **那些大场面如果不可控，其实不存在也无所谓，对世界走向的影响并不大。**」

实测水位〔严格按引擎可识别的分叉算〕：
```
真分叉（≥2 张机会卡）   29 条  6.9%
叙事变体              9 条  2.1%
── 深拍合计           35 条  8.3%
只是多步骤不是多选择    97 条  23.0%   （曾被 Claude 误算成深）
── 浅拍             386 条  91.7%
```
另查出 **20 条「名字像大事、玩家却改不了任何东西」** 的拍（秦军与罗马军团交战、木垒血战、
雪原鏖战、江州全面攻城、独柳树刑场…）——按用户裁定，这些要么给玩家能改的东西，要么合并/降级。

⚠ 未确认：Claude 认为「引擎看不见的分叉＝引擎保证不了的分叉」，故 8.3% 是真实水位；待用户确认。

### ③ 边界〔Grok 提，与用户表述一致〕

> **模型可以发明质感，不可以发明去处。**
> 执法只问一句：**这话有没有给玩家一个新的可执行下一步？**
> 有，且不在当前合法方向里＝违规；没有＝闲聊。

用户的同向表述：「地区风貌、人物外貌、性格我们有定义……但**这个人怎么行动、他当时怎么想，
我们并不会过多干涉**。NPC 我希望通过 LLM 让人觉得是活的。但他再怎么发散，
**应该也有一条途径能让我们找到那条预设的故事链**。」

因此**环境内容不做成封闭池**（Grok：「环境做成全封闭池，就变成可点的话本」）——
Claude 早先提的"供给侧封闭池"已收回。

### ④ 三方分家〔Grok 提，未采纳但方向已认可〕

| 给谁 | 写什么 |
|---|---|
| 制作人 | 这一拍吃掉什么、打开什么。只给人看 |
| 玩家 | 合法方向：去见谁、去何处。**不写带走什么** |
| 模型 | 此刻什么为真、什么不许发明、这人这拍要什么。**结束条件写成条件，不写成已发生的散文** |

## 三点六、**待加**（用户 2026-08-18 标记）

### 🔖 event 衔接：下一拍激活时，要用人话告诉玩家

> 用户：「在这一段错过之后，皇帝被刺杀了，**接下去该做什么事情？新的 event 提示或者是系统
>  应该给到玩家一个指引**……这个衔接部分可能我们还没有做完，或者是说我们现在做的不够好。」

实测〔核实〕：**没做完。** 引擎在事件激活时确实发 `event_activated` transition，
但它落成的是一条状态变更记录 `{ key:'世界.状态.剧本模组', action:'event_activated',
newValue: <内部 event id> }` ——**给玩家的是一个内部 id，不是「接下来该做什么」**。

对照：同一段代码里，好感与声望的引擎结算**特意转成了玩家看得懂的话**，注释写着
「引擎侧结算，必须进玩家可见的状态流——否则好感涨了玩家不知道为什么，因果就只存在于代码里」。
**同一原则在事件衔接处没有执行。**

所以「皇帝被刺 → 你在外面瞎逛 → 事后得知」这条链现在的实际表现是：
```
1. 超时 → 场外结算 → 传言「天子暴毙的消息已经传遍洛都…」    ✓ 有，且写得好
2. 下一个 event 激活                                  ✗ 玩家只看到一个内部 id
3. 下一轮「当前可切入点」                                ✗ 来自另一套 situations，35% 的拍没有
```

## 三点七、**主轴的定性**（用户 2026-08-18，重要——推翻了本文档早先几处判断）

### 主轴不是一条故事线，是两个通关条件

> 用户原话：「主线一开始我的想法就是从王哲托付之后的两个条件：
>  1. 武功达成六阳　2. 保护一名岳飞后裔。
>  **这两个条件都满足的情况下，玩家再回到太泉古镇那个出发点，然后进行故事的续写，
>  升华到系统对抗。** 已知的那四名后裔角色**都属于可选择项，并不是必须项**。
>  但是就跟《上古卷轴》一样，**你玩的大头还是那些支线，主轴的话会比较简单**。
>  何况现在主轴的续写我们还没有决定好，**任何剧情的扩写在现阶段都放成待办**。」

> 用户另一句关键背景：「**主轴在小说里面体现得也不是特别好。**」——属实：
> 主轴文档自己记着「原著中程宗扬**从未履行此托付**：全书修为最高见第四级入微境，
> 且他进太泉是为赤阳圣果救萧遥逸」。**主轴是我们设计的通关条件，不是从原著抽出的线。**

### 因此以下几条**不是缺陷**，此前的判断作废

| 早先报的「问题」 | 重新定性 |
|---|---|
| 主轴 seq 211→636 **断层 425 拍** | **非缺陷**。条件不需要连续；原著那段在讲别的（江州、临安、纸钞、鹏翼社） |
| 15 个血脉拍**没有一个是抉择** | **非缺陷**。四名后裔本就是可选项；那些拍是「这个人还活着／是岳血」的**证据**，不是选择 |
| 主轴 28 拍摊在 1399 seq，**50 拍才一个节点** | **非缺陷**。上古卷轴式：主线简单，大头在支线 |
| Claude 提的「脊由二级线轮值」方案 | **不需要**。用户已定主线就该简单 |

### 仍然是真缺陷的

| 项 | 说明 |
|---|---|
| `plan_counterattack`／`yin_yang_counter` 两拍 **`axisSeq` 为 null** | 排序当 0 → **主轴第一、二拍变成了全书后段内容**（太泉核心区躲潘金莲追兵）。实属 `lyl.taiquan_core_conflict` 关窗 666–667。**数据缺陷，待修** |
| 主轴尾部 3 条待扩（六阳古阵入口／小玲儿太泉／程赵之子） | 按用户裁定：**待办，现阶段不设计** |

### 终局落点与一处正典风险〔必须记清，否则会被当成正典依据〕

落点＝**太泉古阵**（数据中为 `liuchao.location.taiquan` 与 `lyl.location.taiquan_core`，
名为「古阵」非「古镇」；用户系语音输入，已确认指的就是太泉）。

⚠ 主轴文档已记录的核实结论：**「祭祀大阵＝系统入口」是我们的推断，不是原著**。
正典写的是「修为达六阳后前往太泉古阵**祭祀故人**」，**全书无任何"祭祀大阵"字样**。

> 用户 2026-08-18：「『祭祀故人』这个说法本来就很模糊，因为**岳飞也能算故人**，对吧？
>  所以**这是本来小说留的一个钩子，我们可以基于这一点之后再进行续写**。」

**故人是谁，正典未写明** → 这是原著留的空位，续写可用。
但「太泉＝系统入口」这一层**记为我们的设计，不得作为正典依据去推别的东西**。

## 七、一条方法教训：「用了不介绍」这个指标，口径错了四次

用户问「为啥不做成人物任务而一定要放进国家线？」——这一问把数字从 12 打到 2。
完整的翻车过程记在这里，因为**每一次错的都是判据，不是数据**：

| 轮次 | 判据 | 结果 | 为什么错 |
|---|---|---|---|
| 1 | 跨线首见 seq 落差 ≥200 | 27 处 | 落差大不等于缺陷——玩家若先走 A 再走 B，早就见过了 |
| 2 | 本线用 ≥3 拍且登场拍不在本线／主轴 | 17 处 | `gfirst` 把**隔离关**的 event 当成首次出现（谢艺就是这么被误判的） |
| 3 | 只算可达 event | 12 处 | 对了一半 |
| 4 | **把第三级人物插入也算进覆盖** | **2 处** | 前三轮**只看二级线**，而"介绍这个人"本来就是第三级的职责 |

最后只剩：唐国·吕雉（本线 4 拍，三级 0 拍）、宋国·秦桧（本线 3 拍，三级 0 拍）。
其余 10 处**第三级本来就覆盖了**——小紫在唐国段有 4 拍（离魂症／渭水闭关／没回来／被掳）。

**教训**：三级结构的任何"覆盖率"统计，都必须**同时算三级**。
只统计其中一层，得到的数字必然虚高，而且会诱导出错误的修法——
本轮就差点因此把南荒、洛都的 event 双喂进宋国线和唐国线，
与刚刚确立的「国家线跟的是玩家在这个国家的行动与见闻」自相矛盾。
