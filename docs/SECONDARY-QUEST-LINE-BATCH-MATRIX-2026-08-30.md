# 二级任务线分批实施候选矩阵（2026-08-30）

> 目的：选择第一条“固定主线 + 真实分支 + LLM 动态演出”的可玩纵切。
>
> 口径：数据事实取当前 `secondaryLines.ts`、`characterQuests.ts`、`canonRail.ts` 与 `divergenceLedger.ts`；“适合度／优先级”是本轮产品评估，不是新的 canon 裁定。本文不授权修改主轴、冻结事件 ID、隔离关或人物结局。

## 1. 选择原则

第一条纵切不比节点总量，优先满足：

1. 入口由“玩家知道那件事”的现成事件确定性解锁；
2. 默认路线可达，尽量不依赖隔离关；
3. 已有作者定义的分歧或明确可裁定的选择，不让 LLM 发明结果；
4. 选择至少持久改变关系、资源、后续场景或解决方式之一；
5. 能挂入至少一个人物任务插入段；
6. 能在 3–6 个承重事件内完成第一批 A／B 连续实玩，不要求先打穿整条长期线。

## 3. 推荐顺序

### A1：星月湖“谢艺命运 → 星月湖响应”

它最能一次证明四层能力：

- 固定主线仍完成杀龙与岳帅遗事交接；
- 玩家介入可形成生还／失踪分歧，默认正典仍保留自己的结果；
- 孟非卿与萧遥逸根据分歧采取不同动作；
- 同一结果的具体对白、救治过程、战后感官由 LLM 动态演出。

它先过 **G-1 来源完整性门**：从 EPUB 独立重建本纵切候选拍，逐拍核对 stage、二级线、人物线和死亡／生还／失踪后果；承重漏拍、错序与死亡依赖未查清前不进入实现。严格执行指南见 `docs/GROK-XINGYUEHU-G1-SOURCE-COVERAGE-GUIDE-2026-08-30.md`。

G-1 通过后再过 **G0 可达性门**：从当前默认可玩路线自然推进时，能否在不解禁 `lcq.stage_06`、不注入 flag、不调用测试 fixture 的情况下，由 `lcq.event.slay_dragon` 及后续本地合同激活 `lcq.if_xieyi_longrest` 或 `world.xieyi_absence.active`。当前 registry 仍以 `lcq.event.s06_03` 为 source event；若这一门不成立，星月湖暂不进入实现。

### A2：晋国“宫城鬼事”

若星月湖 G0 不成立，第一条改选晋国。它有精确知识锚、23 个 ready 节点、零隔离关命中，适合作为从零建立一条作者定义 A／B 支线的低风险样板。进入实现前必须先裁定：玩家在哪一拍选择什么、两边分别改变什么，以及在哪个固定事件重新汇合；不能让 LLM 临场创造政治结果。

### 后续复制顺序

1. 黑魔海／毒宗：验证秘密组织与人物状态分歧；
2. 汉国：验证生还 IF 对国家政局的长期承接；
3. 太泉／太乙：验证远征与宗派线；
4. 商道：在剧情支线样板稳定后接地区声望折现；
5. 宋国、昭南、唐国：待隔离与跨线边界更清楚后分段推进。

## 4. 第一条线的批次边界

| 批次 | 交付 | 验收 |
|---|---|---|
| G-1 | 原著拍覆盖审计 | 从 EPUB 独立建候选拍；逐项分类为固定事件、人物插入、分支变体、动态演出或有意省略；无承重漏拍／来源冲突 |
| G0 | 默认路线的入口与分歧可达性审计 | 不注入、不跳关；能指出真实触发回合与权威回执，或明确判不可达 |
| B1 | 本地分支骨架 | 选择、状态、关系／资源后果、存读档在零 LLM 下成立 |
| B2 | 3–6 个承重事件的 A／B 后续 | 两档出现不同任务目标、人物动作或可用资源；不是只换一句正文 |
| B3 | 人物插入段 | 相关人物在场／不在场时，同一上级事件产生合法不同过程 |
| B4 | 动态演出 | 同一分支多次运行具体演出不同，权威状态与锚点一致 |
| G2 | 连续真机 | A／B 两档各跑一次并读档续玩；同一分支复跑至少一次；无真值、知识、位置或物品漂移 |

## 5. 明确不做

- 不一次并行扩十条线；同一时间只允许一条纵切处于实现中。
- 不把 `reviewSummary` 直接投给玩家，不把 ready 节点数量当可玩进度。
- 不新增第四级任务系统，也不新增 `world_driven/player_driven` 平行 schema。
- 不为第一批解禁隔离关，不用测试 fixture、flag 注入或跳关证明“可玩”。
- 不重新打开清羽 Demo 的修辞、文风或性能打磨。
- 不让 LLM 决定人物生死、物品、关系终态、事件完成或分支回流。

## 6. 数据核对摘要

- `secondaryLines.ts`：当前运行时直接导入重算为 10 条线、382 个节点（374 ready／8 pending／0 new）；本矩阵逐线统计可精确加总。导读中的 383／375 已比当前源码多 1，后续应以本次直接计数为准。
- `canonRail.ts`：隔离关共 8 个；矩阵统计每条线的节点实际命中，不按线名推断。
- `characterQuests.ts`：人物任务只作为上级 event 的插入段；矩阵只记录与二级线节点真实 event id 相交者。
- `divergenceLedger.ts`：当前自动分歧 registry 有谢艺、碧姬、苏妲己、郭解、董卓五条人物状态规则。
- 本轮未跑测试、未做真机；矩阵只用于选批次，不证明任何支线已经可玩。
