## 0. 起点：一个提问

用户问「对比现有人物图片，角色的外貌文字描写是否充实到能让 LLM 生成立绘」。审计结果是**不够，而且缺的正好是画图最需要的那一半**：

- 48 个有官图的角色里，**18 个在 appearance 库查无此人**
- 有描写的 30 人中：肤色 28/30、体型 28/30，但**服饰只有 18/30、配饰只有 5/30**
- 没有官图的 118 人更薄：appearance 字数中位数 **39.5 字**，59 人不足 40 字，大量条目直接写着「原文未明确」

抽样对照（惊理）：文字 62 字全是身体描写，官图是亚麻金超长发＋黑底红火焰纹连体衣＋黑长手套——**文字里一个字都没有**。

## 1. 根因：不是模型不写，是检索没喂

旧抽取器 `extract-appearance-from-epub.mjs` 的关键词表：

| | 数量 | 内容 |
|---|---|---|
| 身体/体型词 | **21** | 胸、乳、肌肤、腰、腿、臀、玉、丰、娇… |
| 服饰词 | **5** | 裙、衫、罗衣、妆、衣着（无袍/甲/靴/冠/巾/簪/钗/镯） |

加上 `score = 3 × 关键词命中数`，而「玉」「丰」「娇」在情色段落里密度极高 → top40 段落被情色场景占满，**模型看不到任何穿着句**。

新脚本 `scripts/extract-portrait-visual-from-epub.mjs` 改为分层加权：服装形制 6／配饰 5／发型 5／颜色 4／面容眼 3／体型 1／**纯身体性征 0**。另加硬约束：`outfit` 只记衣物形制，半褪破损记其完整形态，只有裸露就留空（否则会写出「赤裸（无衣物）」「戴着乳环」）。

结果：84 人，full 16／partial 53／none 15，**服饰覆盖 41% → 68%，情色污染 0**。

## 2. 产物：单一数据源 + 分层

`character-canon/portrait-visual-master.json`（schema v2，**127 人**）

```
identity   换装换不掉的：发色/瞳色/五官/体型档位
           + marks（永久标记）+ trueForm（真身特征）
outfits[]  一人多套：服装/配饰/配色/随身器物 + 该套的发式
           scope: default | stage:<id> | phase:<label> | unassigned
```

**发色属 identity，束法随装束**（吕雉盘髻＋步摇／月霜高马尾／苏荔随意挽起）。

出图就绪度：**ready 65 ／ partial 39 ／ insufficient 23**。

构建：`scripts/build-portrait-visual-layers.mjs`（幂等，始终从两个源文件重建）。

## 3. 已投影进运行时（118 人）

`build-character-registry.mjs` 把两层注入 registry `staticProfile.visualIdentity` / `visualOutfits`，`characterResolver` 产出三条派生 note：

- **【体貌】**…——换装不改变这些特征
- **【装束】**…——此为当前常态装束，可随场景更换
- **【真身特征】**…——仅在其显露真身时可见，平时隐去；场内人物是否知情按【人物真身】规则判断，不得作为既知前提

这补上的正是 `storyContext` 规则 4 一直假设存在的数据——它要求换装时「保留刺青、饰物、发式等族裔特征」，但此前没有任何数据说明哪些属于「不能换掉的」，只能靠 `race` 字段猜。

**走 notes 而非覆盖 `appearance`**：后者是 no-force 语义（仅缺失时才填），角色已有 appearance 时分层数据根本进不去；notes 每次投影重建，且分标签比一整段清晰。

装束选择 = 导出的纯函数 `pickOutfitForStage()`：关卡绑定优先 → default → 只有未绑定变体时**什么都不注入**（宁可不写，也不臆断她穿了哪套）。

测试：`tests/portraitVisualProjection.test.mjs`（6 个）。

## 6. 三个值得记住的坑

1. **真身特征曾绕过门控泄底。** 狐尾/刺青提取进 `identity.trueForm/marks` 后**仍留在 `outfits[].props`**，而 props 是当常态装束注入 prompt 的——苏妲己的九尾狐身份会作为「她穿戴的东西」直接泄出去。凡提升到不变层的片段必须从可变层 strip 掉，已有测试守。
2. **单字正则在真身判定上误判率过半。** 初版 14 条 trueForm 有 8 条是误判：「鳞片胸甲」「翼状饰片」「月牙短戟」「翼钩（剔指甲用）」，还有一条匹配的是书名「清**羽**记」。收紧为「部位复合词＋装束词排除」后剩 6 条全对。
3. **裁定落到文档层 ≠ 落到字段层。** #142 定了月霜发色以原文为准，但数据里 `hairColor` 仍是官图的「栗棕」——和 #11 一模一样的失败模式。查一条改名/正名类裁定是否真落地，要查四层：**prompt ／ registry ／ 关卡 builtin+generated 数据 ／ 跨关记忆产物**，后两层最易漏。
