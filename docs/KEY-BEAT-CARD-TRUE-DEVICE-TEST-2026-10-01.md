## 一、这轮要回答什么

1. 谈期限这一拍的**推进卡片**是否醒目、好懂。
2. 在输入框里说"要换期限 / 答应条件"时，是否**只高亮卡片、不推进**，也不会被写成"谈成了"。
3. 和苏妲己闲聊时，正文是否**不再出现**「我准了」「成交」「期限定了」这类结果。
4. 点卡片后，**结果句**是否自然地接在正文之后，进度（HUD 第几步）是否同步。
5. 识别失败时，是否**停下来并给出一直可见的提示**，而不是降级成"正文谈成、进度没动"。
6. 卡片回合的**等待时间**（目标 ≤30 秒，本轮只记录，不作为通过门槛）。

## 二、环境与守卫（照上一轮做法）

- 服务：`http://192.168.50.51:8091/`（本机 `http://127.0.0.1:8091/`），**不要用 18097**。开测前确认页面加载的是最新 bundle（记录 md5 与大小）。

- 「模块拆分试玩」开关保持开启（与上一轮一致）。
- 调试日志开测时打开、结束时删除，复查为 null。
- 收尾核对：共享 API 配置、`characters.json`、`active_save.json` 的 md5 与开测前一致，save-storage 无写入。

## 四、测试项

每项都按"操作 → 看什么 → 记什么"。每个回合都记下：入口（卡片 / 自然输入 / 按钮）、输入原文、耗时、正文要点、HUD 步骤、关键状态。

### K1 卡片外观（R5-谈期限前，读档后不操作）
- **看**：输入框上方是否有「关键抉择」卡片，写着「以霓龙丝线索换三个月期限」，旁边标「第 1/2 步」；下方一行小字说明"点卡片才会推进剧情……"。
- **看**：正文末尾的小按钮里**不应再出现**同一个动作。
- **记**：截图；卡片是否一眼能看到、文案是否看得懂。

### K2 自然输入想推进 → 只高亮、不推进（读档 R5-谈期限前）
依次试这三句，**每句从同一个检查点重新读档**：
1. 「我用霓龙丝产地线索换三个月期限。」
2. 「宽限我一季，我把那丝的来路查到底，连人带货交到她手上」（上一轮 fx-pact2 的原话）
3. 「提出三个月期限。」
- **期望**：卡片变成高亮（橙色边框），输入框上方出现「这句话像是要推进当前的关键抉择。确认请点上方卡片；输入已保留。」；输入框里的字还在；**HUD 仍是第 1/2 步，没有新正文**。
- **也可能出现**：识别没判断成"想推进"，按普通对话演出一段——这时看 K3 的要求。
- **记**：每句实际属于哪种情况、耗时、HUD 步骤。

### K3 闲聊不写出结果（读档 R5-谈期限前）
- **操作**：连续 3 回合和苏妲己闲聊、试探，例如「你这商馆开了多久？」「霓龙丝在南荒哪一带？」「要是三个月回不来怎么办？」。
- **期望**：正文正常演出对话，但**不出现**「我准了」「成交」「依你」「期限定下」「从今日算起」之类；HUD 仍是第 1/2 步。
- **记**：如出现结果类句子，摘原句；如正文读起来缺了一句、衔接突兀，也记下（系统会删掉写出结果的句子）。

### K4 点卡片推进（读档 R5-谈期限前）
- **操作**：点卡片「以霓龙丝线索换三个月期限」。
- **期望**：正文写你提出交换的过程，**最后一句是固定的结果句**：「苏妲己没有点头，也没有再叫人动手。她只抬了抬下巴——霓龙丝和期限的事，她愿意听你说下去。」；卡片换成「当面订下三个月南荒之约 · 第 2/2 步」；HUD 同步到第 2/2 步。
- **再点第 2 步**：正文最后一句应为「南荒之约就此订下：三个月内，你南下采回霓龙丝；逾期不归，受炮烙之刑。」；卡片消失；事件进入下一拍（拒赌路线下契书一拍已结案，下一拍是「谈定六十金铢」；继续赌局路线下，下一拍是「落败签下卖身契」）。
- **记**：两次的耗时；结果句和前面正文衔接是否自然（自然 / 有点突兀 / 前后矛盾，附原句）；正文里是否**重复**写了结果。

### K5 识别失败时停下（遇到就记，不刻意制造）
- **期望**：如果识别没及时完成，**不推进、不演出**，输入框上方出现一直不消失的提示「这一步关系到当前剧情进度，行动没能识别，本回合没有推进。输入已保留，请点选上方选项，或换个说法再发送。」；改输入或重新发送后提示消失。
- **不通过的信号**：正文写成谈成而进度没动（上一轮 fx-pact2 的现象）。
- **记**：触发时间、输入原文、控制台里识别请求的 finish reason 和耗时（上一轮 Jev 曾把 1024 token 全用在推理上）。

### K6 拒赌回归（读档 R5-赌局窗口 / R5-拘拿窗口）
- 赌局窗口：输入框只读、横幅「剧情分支需要做出决定」、不选选项发不出去；点「拒绝这场赌局」后被拿下，锁解除。
- 拘拿窗口：用自然语言反抗 / 逃跑 / 服软，三条都应结算为扣押、未签契。
- **新增核对**：三条路线结束后，存档里 `event.gamble_bond_signed.outcome` 应为 `refused`（`done=true` 只表示这一拍已结案）。
