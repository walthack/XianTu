| 关卡副本（生成物） | `src/modules/scenarioMods/builtins/data/lcq.*.json` | 由 `sync-builtin-mods.mjs` 从关卡源同步过来，canon-authority-overlays 也在这一步叠加。我查过，overlay 不改人物字段，所以不要改副本 |

**结论：下面每一条都改"卡源"或"关卡源"，改完执行 `npm run canon:build` 重新生成注册表和副本。** 例外：关卡里的 `personality` 会被 `apply-character-cards-v3-to-mod.mjs` 用卡覆盖，所以 personality 只改卡源。

**哪些字段会真正注入提示词。** 依据是今天 12:24 前的工作区代码 `characterResolver.ts` 和 `characterRagService.ts`，这两个文件今天上午还有人在改，以最新代码为准。人物盘点里写的"RAG 不门控"已经过时，实际情况如下：
- 关系、入伙、情节、结局（relationToProtagonist / joining / keyEvents / ending）：**有门控**。只有两种情况会注入：①本关投影显式写了这个字段；②角色有 `allowed-after-turning-point` 关系链，并且本关有投影、但投影里缺这个字段，这时回落到静态卡。小紫、卓云君、梦娘、阿夕、潘金莲、泉玉姬属于第②种。
- 称呼、谈吐、底线、目标、软肋、绝技、性格（formsOfAddress / speechStyle / principles / goals / weaknesses / signatureAbilities / personality）：本关投影里**缺这个字段就回落静态卡**；**本关没有投影时，全部用静态卡**。RAG 的"性格"也按这条规则走。
- identitySummary 有两条注入路径：①关卡 origin 为空、投影 identity 也为空时，拿它当 origin；②`storyContext` 里的「别名与实体定锚」（`findRegistryIdentitiesByContext`，最多 180 字）。第②条在提到名字，或提到"星月湖"、而该人物身份里也有星月湖时触发。
- 关卡 profile.notes 里的【性癖】【身体】【功法约束】【剧情弧】原样注入，除非本关投影写了 `blockedStageNotePrefixes`。
- embedText 只用于向量召回，本身不注入。但它和卡同源，随卡一起修正即可。

**严重程度**：**A＝剧透／违反裁定**，**B＝事实错误**，**C＝写偏**。同级内按 demo 影响排序。
