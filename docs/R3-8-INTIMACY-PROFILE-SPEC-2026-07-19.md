# R3-8B · 亲密档案层规格（表演层扩展，非决策维度）

- 日期：2026-07-19
- 来源：用户提问"重要角色是否需要身体特征/性癖"+ Claude 推荐方案 + 用户拍板
- 定位：**R3-8 角色表演卡（Voice Card）谱系的亲密向扩展**；与 NPC 确定性决策内核（`docs/R2-10-NPC-DECISION-CORE-SPEC-2026-07-19.md`）无依赖，实施时点跟表演卡纵切同批
- 动机（用户原话口径）：亲密关系女性角色目前感觉都差不多，需要差异化

## 1. 架构定位：决策内核管"她会背叛谁"，本层管"她在帷帐里是什么样"

身体特征与亲密偏好**不进 NPCState**——它们不改变世界行动的选择，不参与效用评分，塞进决策器只会污染评分函数。本层是纯表演/档案数据，消费路径与表演卡相同（storyContext 注入 → LLM 渲染）。

## 2. 数据结构：intimacyProfile

挂在角色人工正典档案上，与表演卡"称谓/声线/行为签名/禁忌"四字段同族：

```jsonc
{
  "intimacyProfile": {
    "physical": "…",            // 身体特征叙事化：主要来源=appearance-draft 接线（立绘管线同源），缺口人工补
    "preferences": ["…"],       // 偏好：亲密情境下的主动性、节奏、语言习惯、癖好
    "hardLimits": ["…"],        // 硬禁忌：LLM 不可越线的表演约束（与表演卡"禁忌"同机制）
    "scenario": "…",            // 触发情境：什么关系阶段/场合下这些偏好才显现
    "revealTiers": [            // 揭示层级：好感/关系阶段逐层解锁，见 §4-3
      { "tier": 1, "unlockedBy": "…", "reveals": ["…"] }
    ],
    "source": "canon | authored" // 来源标记，见 §4-4
  }
}
```

**差异化是本层存在的唯一理由**：每名角色的 preferences/行为签名必须与其既有性格、声线、出身一致且互相区分——亲密中的样子是既定人设的延伸（骄纵的骄纵、克制的克制、危险的危险），不是换了个场景就趋同的通用模板。

**正典身体边界（hardLimits 强制条款，2026-07-19 用户点名）**：全库存在一族"元红/身体边界"类正典设定，是亲密场景中 LLM 最易顺笔写破的正典事故点，起草时**必须**从 keyEvents/裁定提取并写入 `hardLimits`，验收盲测须含"边界不被写破"用例。已知清单（起草时按全卡复核，不限于此）：潘金莲＝元红保留、仅用后庭；乐明珠＝处女身、卡在临门一脚、仅后庭；吕雉＝暗修处女功法保持处子之身作博弈筹码、贸然采补被反噬；梦娘＝身负禁制无法插入（仅非插入方式）；李师师＝正典无肉体关系（精神之恋，档案不设 intimacyProfile 但须标注该边界防越写）。

**起草取材规则**：必须读全量材料（registry 完整字段含 keyEvents/principles/weaknesses、personality-consolidated 含 override 层、人物卡 md），**不得只看 relationToProtagonist 关系摘要**——潘金莲"受虐性幻想+誓约"三层结构、乐明珠元红边界均只在 keyEvents 中，关系摘要一行体现不出。

## 3. 验收标准（差异化盲测）

1. 首批角色两两对比，intimacyProfile 无一条目雷同；偏好可从该角色正典性格/经历讲出因果。
2. **盲测**：取同一亲密情境让 LLM 分别按 N 名角色档案渲染，去掉名字后读稿能认出是谁；认不出=该角色档案打回重写。
3. 硬禁忌违规能被表演门禁退回（复用现有机制，检测/清洗清单同步登记新标签）。
4. 常规（非亲密）场景 prompt 中 0 注入、0 泄漏。

## 4. 四条纪律（缺一不可）

1. **年龄硬门禁（validator 执法，非写作约定）**：`intimacyProfile` 只允许出现在**实际年龄成年**的角色档案上，校验器强制、接 `canon:build`，与裁定 lint 同待遇。门禁按实际年龄判定，不按外貌原型（童颜巨乳/不老仙姬等成年角色原型按既有裁定保留，见 `character-canon/` R1-3 终审口径）。R2-9 修净的年龄数据是本门禁的依赖。
2. **注入门控**：只在"亲密场景 + 成人内容开启"双条件下注入 storyContext，常规叙事路径零出现。三个理由：token 成本；R2-9 教训＝任何注入块都可能被 echo 进正文——本层标签一律低显著度措辞，且**上线同时**登记进协议泄漏检测+清洗两份清单（勿重蹈检测/清洗错位）；发布面隔离要求成人内容不得从常规路径泄出。
3. **知情边界=玩法面**：性癖是隐私，与机密身份同待遇——其他 NPC 与玩家默认不知，通过游玩逐层揭示。`revealTiers` 接好感阶段化（R3-5）作亲密内容解锁门：关系深入→偏好逐层显现，比"档案写了就全知"更有代入感，也天然防一次性倾倒。
4. **来源双轨、只做小名单**：原文有据的直接用（source=canon）；无据的按 OVERRIDES 人工正典流程补写（personality 管线先例），source=authored，**全部经用户圈选/审定后生效**。首批名单已由用户圈定 18 名（见 §5.1），不给 302 人 registry 铺，后续按实际游玩需求增补。
