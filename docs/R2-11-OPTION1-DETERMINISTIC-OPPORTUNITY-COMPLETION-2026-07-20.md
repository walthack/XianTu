# R2-11 方案①：机会卡确定性完成合同

日期：2026-07-20
状态：G1 工程纵切完成，待 R1/R2 真机复验

## 结论

方向符合 `PROJECT-STATUS.md` §2.3：确定性引擎决定发生什么，LLM 只负责怎么讲。
本批把 `s01_05` 从“模型愿意发 `done` 才算参与”改为“玩家本人逐回合提交行动，程序满足合同后写 `done`”。
这不是让玩家点卡即领奖，也不是让所有事件自动场外完成。

## 合同

- `ScenarioStoryOpportunity.completionContract.kind = player_action_sequence`
- 每一步声明 `matchAny` / `matchAll` 与可选 `rejectIf`
- 每个成功结算的玩家回合最多推进一步；一条包含全部关键词的输入不能跳完合同
- 进度、去重轮号与 ready 状态进入存档，JSON 重载后继续
- R1“新帝第一道诏令”为三步：进入昭阳宫 → 选择政策优先项 → 承担公开站队后果
- R2“让朝廷进入昭阳宫”为两步：证明定陶王安全 → 协调北军/凉州军不拔刀入宫路线

## 写入权

1. `processGmResponse` 在一次 AI 回合成功返回后只把本轮玩家输入交给本地合同判定器。
2. 判定器不读取正文、`tavern_commands` 或模型评价。
3. 全部步骤满足后只标记 ready；`advanceScenarioRuntime` 在引擎事务内写事件完成 flag。
4. `canonGuard` 拒绝 LLM 直接写 `s01_05.done`。
5. 旧 `eventReconcile` 在引擎专属事件处停止，不能替它补 flag，也不能越过它提前补后续事件。
6. 同轮完成与场外截止竞争时，已 ready 的玩家路线优先，不会被误记为 offscreen。

## G1 证据

- R3/R1/R2 同源重放不需要 LLM 或网络；R1/R2 改用真实分步玩家行动完成。
- 单句覆盖全部关键词仍只推进第一步；同一世界回合不同文本重复调用也不能推进第二步。
- 否定/撤回输入不推进。
- JSON 往返后完成，回执为 `participated`，权限只授予一次。
- 模型直写完成 flag 被拒绝；旧事件对账候选链在 `s01_05` 截止。
- validator 拒绝空匹配器、重复步骤与非标准事件完成条件。
