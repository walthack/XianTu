# R2-11F：事件结果反馈闭环 G1（2026-07-21）

## 结论

`s01_09` 的本地判定结果不再只负责完成事件。引擎会按 `success / partial / failure` 的确定性结果，经过白名单合同写入 NPC 态度、NPC 知识、玩家知识与长期经历；LLM 正文和命令没有这些状态的写入权。

R2-11 的可计算亲历完成覆盖由 `4/380` 增至 `5/380`。

## 合同边界

- `relationships`：只能调整指定人物、目标和维度，结果钳在 `-100..100`。
- `npcKnowledge`：只写稳定 fact id，去重后排序。
- `playerKnowledge`：沿用 R2-10B 最小账本，只接受 `confirmed / rumor` 与 `player / public`。
- `memories`：生成稳定 episode id，附事件、动作与结果标签，复用既有按显著度保留 12 条的长期记忆机制。
- validator 在装载时校验人物引用、数值范围、知识字段和记忆显著度；runtime 仍做防御性钳位。

## 纵切证据

`s01_09` 宣读诏书：

- success：吕雉对程宗扬的 trust `+6`，记住诏书程序顺利完成，玩家确认自己亲历了程序，并写入高显著度长期经历。
- partial：trust `-2`，NPC 与玩家分别记住程序留下争议，并写入政治代价经历。
- 完全忽略：仍按绝对截止场外结算，不伪造上述亲历反馈。

## 自动化

- success／partial 的态度、双方知识和长期经历落账。
- 态度 effect 越界及未知 actor 引用拒绝装载。
- 原有本地判定、合同热更拒绝、LLM 越权、绝对截止场外结算回归保持通过。
