# R3-5 / R3-6 正典消费盘点与纵切

日期：2026-07-17  
范围：技能、地图、装备、货币四个消费点；地点检索/风貌纵切；长期记忆 B 设计冻结。

## 结论

本轮没有重造已有系统。盘点确认货币双轨与装备数值消费已经落地；真正缺口是“自由漫游地点没有稳定消费正典风貌”和“可见判定不消费已核验的六朝技能”。本轮补齐这两个纵切，并把更大的地图边界、装备国别生成和长期记忆 B 留在后续。

## 地点纵切

### 运行时行为

1. `canon.locations[].region` 进入 Scenario Mod TypeScript schema、JSON Schema 和 validator。
2. 严格初始化将其映射为原生 `世界.信息.地点信息[].地域`，不丢失国别/文化圈。
3. story prompt 先按玩家位置描述做最长地点名匹配，再以精确坐标兜底。
4. 即使没有活跃事件，自由漫游也会注入当前地点的地域、description 与 features。
5. 同地正典角色仅在已经登场时进入聚焦召回；已有社交关系仍可按当前位置补召回。

### 安全门

- 不因地点匹配自动创建 NPC。
- 不召回尚未登场的未来角色。
- 不改变事件、主轴、分歧或存档完成键。
- 角色常驻地不足时宁可不召回，不凭国别猜人。

现有数据概况：2281 个关卡地点实例全部有描述，1535 个带 region，1091 个描述不少于 80 字；1616 个角色实例中 443 个已有 `locationId`。因此本轮先打通消费链，角色常驻地补档另列数据任务。

## 技能判定纵切

技能因子必须同时满足四个条件：

1. 当前 Scenario Mod 正典技能表中存在；
2. 玩家存档的 `角色.技能.掌握技能` 已掌握；
3. 玩家本轮行动明确点名技能；
4. 技能名称/描述与判定类型语义相符。

若正典描述包含“未传授、未掌握、不可使用”等否定信息，即使技能 ID 被旧数据错误挂给玩家也不给加成。单次只取最高一个因子，数值为 6–12（随熟练度离散增长），避免多技能堆叠压过本地骰点。存档里模型自造但正典表不存在的技能无效。

## 长期记忆 B：设计冻结，不接运行时

长期记忆 B 未来采用分层、按需、带来源的注入合同：

1. **公开身份层**：姓名、已公开身份、当前阶段可见外观。
2. **已共同经历层**：玩家与角色均参与、已经发生并已落账的事件/任务。
3. **角色私有知情层**：仅该角色按阶段和证据解锁的事实。
4. **绝密层**：`RELATIONSHIPS-SECRET.md` 与裁定 #81–89；在独立知情图谱实现并回裁定簿解锁前，禁止进入普通关系、全局花名册、长期记忆或常规 prompt。

未来运行时的硬约束：

- 只检索已经登场或已有关系的身份，不以地点创建新身份。
- 每条记忆保留 source/event/stage provenance，分歧事实必须读取当前世界线。
- 先按当前人物、地点、事件过滤，再做语义排序；禁止全库倾倒。
- 设置条数和字符预算；同源去重，晚期资料不得回灌早期关卡。
- 玩家不知道、NPC 不知道、世界尚未发生的事实均不得注入。

本轮只冻结上述合同，不实现全局花名册/长期记忆运行时，避免在知情图谱未完成时制造剧透通道。

## 验收

- validator 与 JSON Schema 接受字符串 region、拒绝非字符串。
- strict initializer 将 region 映射为原生地点 `地域`。
- 自由漫游能获得当前地点风貌，且未登场同地角色不泄漏。
- 只有明确点名且来源可核的已掌握技能进入判定卡。
- 未传授技能、未点名技能和存档自造技能均不给加成。
- 全量 `canon:build` 与 production build 必须通过。
