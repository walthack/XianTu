## 1. 判定口径（用户 2026-10-14 批准的规则 + 我的操作化）

- **停靠点**只在两种情况成立：玩家有至少两种结果真不同的选择；或玩家必须亲眼见到的世界事实改变。其余降为**过渡**，折进下一场开头。
- 标签：**承重**（必须亲眼见的世界事实改变）／**选择**（玩家有多个方向要拿主意）／**过渡**（信息交代、赶路、结果已定的衔接）／**色彩**（可选材料）。承重、选择＝停；过渡＝折叠；色彩＝可选。
- 「选择」标签按**玩家面对的决定局面**打，不要求数据里已有不同结局；另设一列「二选类型」如实标注数据里到底有没有分叉（见 §3）。
- 被折叠拍的 `justHappened` 只来自该拍既有事实（事件库 axisBeat／fixedFacts／动作文本）并对 EPUB 断言；不写连接情节。
- 保护项：战斗合同挂钩的事件与动作 id 不动；`FIXED_QUEST_OBJECTIVE_OVERRIDES`／`resolveFixedQuestObjective` 钉死的 objective 不动；合规标记内容只标不改；不在 rail 的事件（裁定170）不动。

## 2. 落点：改了哪些字段、哪些现在生效

新增 `sceneBeat` 标注（引擎目前不读，**惰性**）+ 04b 停靠点上三个**引擎已在读**的字段：

| 字段 | 谁在读 | 现在生效？ |
|---|---|---|
| `event.sceneBeat`（新增，整事件覆盖里带上） | 无（预留给引擎/界面） | 否，惰性 |
| `event.objective`（改写为局面/提问句） | 任务栏、主线日志、`derivePlayerLine` 取 actionText 不受影响 | 是（仅 04b 停靠点；钉死项未改） |
| `action.sceneObjective`（当下张力） | `readLocalMemoryCapsule`→叙事包 `currentObjective`（原先缺省时回落到动作 label，会把答案递给叙事） | 是（04b） |
| `action.previousBeat`（承上＝折叠事实） | `AIBidirectionalSystem` 南荒叙事包「上一拍要点」（仅 `isNanhuangSceneStage`） | 是（04b） |
| 动作 `label`/`actionText`/`outcomeText`/id | 参与 `contractHash` | **一个字没改**（见 §9 理由） |

stage_02：**只加 `sceneBeat` 标注，没改任何引擎在读的字段**。原因：① stage_02 走 legacy 叙事管线，`mustAppear.objective` 会被 `narrativeHasObjectiveSemantics` 当必现语义校验，改 objective/sceneObjective 可能让叙事被拒；② `previousBeat` 在 stage_02 没有消费者（只认南荒三关）；③ 18 个事件的 objective 本来已是局面句（10-01 那轮改过）。

**结论：战斗类停靠点之后可以走 sceneModule/host；非战斗停靠点之后做不到纯 host，需要给 `AIBidirectionalSystem.ts` 开一个一行的钩子（冻结例外，须用户批准）。数据层已就绪。**

已核实：
- `runtime.ts` 已导出 `getCurrentStoryEventActions`、`recordStoryEventStructuredAction`、`advanceScenarioRuntime`；`host/controller.ts` 的 `closeHost` 已经在场面收束后用这三个函数结算停靠点并 `advanceScenarioRuntime`，在这之后追加「循环结清下一个 `sceneBeat.kind` 为 transition 的事件」不需要改 runtime。
- 过渡拍的多步事件（prepare→attempt）要按 `requiresPreparation` 顺序逐步调用；折叠拍里有 7 个是多步事件（拔除鱼叉稳定乐明珠伤势、收拢商队确认使者抵达、处置鬼王峒眼线、古道废墟迎击鬼战士、谈定六十金铢、紫溪太乙拦船、黑石滩渡河）。
- `applyStepSceneLedger`（`fixedEndingNarratives.ts`）可以落账本，但**只对南荒三关生效**（`isNanhuangSceneStage`），stage_02 不走；且每次调用会**覆盖** `ledger.lastBeat`，多个过渡连跑后只剩最后一个，需要改成追加或另写 `justHappened` 字段。
- 叙事包读「上一拍要点」的位置在 `AIBidirectionalSystem.ts:816`（冻结），但它已优先读 `card.previousBeat`——所以本稿把折叠事实写进 `previousBeat`，**04b 现在就能走通「刚刚发生」这条读取路径**，不需要引擎改动。

做不到／有风险：
- 非战斗停靠点（谈判、见证、选择）的提交点在 `AIBidirectionalSystem.ts:2794` 的 `recordStoryEventStructuredAction`；它之后没有可挂的外部钩子。纯 host 无法在那之后自动结清过渡拍。`previewLegacyPilotSettlement`（`legacyNarratorPacket.ts`）是克隆后试结算，只服务当拍叙事包，不持久化。
- 过渡拍每个动作带 `timeCost`，自动结清会推进世界回合；若同场有 `timeline`／`pressure`／`fatalOutcomes` 类期限，需要先确认不会被折叠拍的回合数误触发（04b 过渡拍上我没看到这类字段，stage_02 的 `s02_03` 有 `offscreenResolution`）。
- 过渡拍里有物品/路线回执／特判的，自动结清必须照原动作落账：`charge_sudaji_fee`（无物品结算，但有固定叙事文本）；`s04b_18` 有 `xiaozi_first_appears` 披露特判；`playtests.json` 的 `qingyu` 试玩终点是 `baihu_shangguan_escape`，所以它被我标为承重不折叠。
- 未知字段 `sceneBeat` 是否会被存档规整丢弃，我只核了加载与 `reconcile` 相关测试通过，没做真机存读档验证。
