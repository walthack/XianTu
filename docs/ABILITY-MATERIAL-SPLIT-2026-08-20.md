>
> **本文只是待审清单，`character-registry.json` 一字未改。**确认之后才谈落地。

## 由来

`character-registry.json` 的 `staticProfile.signatureAbilities` 当初抽取时
**把「会什么功夫」和「带什么家伙」混在同一个数组里**：

```
南霁云  ["凤嘴刀（数十斤重）", "刀法刚猛剽厉，已达刚柔并济之境"]   前者兵器，后者刀法
惠远    ["方便铲", "日月铲"]                                两件都是兵器
玄萝    ["阴阳合欢术", "阳钧宗功法"]                          两条都是功法
```

将来做「玩家找高好感角色学功法」（backlog P4-1）必须先拆开——**兵器学不了，功法才能学**。

## 口径

判的是「**能不能教**」，不是词面。两可的一律进「其他」并写明歧义，不硬选。
`raw` 原样保留，规范化只写进 `normalized`——**分类不改写正典文本**。

## 机检结果（Claude 复核）

| 项 | 结果 |
|---|---|
| 角色覆盖 | 161 / 161，无遗漏 |
| 条目覆盖 | 367 条全部分类 |
| `raw` 被改动 | **0 条**（逐字比对原数组） |
| 分类分布 | 技法 132 ／器物 149 ／其他 86 |

## ⚠ 这份素材的天花板

`signatureAbilities` 是当初一次性抽的**短标签，不带原文依据**——
只有 `boss-ability-scan/` 那 22 个 boss 有逐条带证的精扫。
所以拆完能得到「谁会哪些功夫」的可用清单，但**每条的正典依据仍是空的**。
真要做「学功法」，还需回原文补证（管线现成：`scripts/scan-boss-abilities.mjs`，
其 system 提示为「只依据片段判断，每一项必须给 ≤40 字原文短证；片段没有的写"原文未见"」）。
