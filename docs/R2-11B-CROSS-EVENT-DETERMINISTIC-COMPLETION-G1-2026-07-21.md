# R2-11B：s01_06–08 跨事件确定性完成合同 G1

- 日期：2026-07-21
- 范围：`lyg.event.s01_06–08`
- 基线：R2-11 `s01_05` 方案①纵切
- 结论：三种事件结构的 `done` 写入权已收归本地引擎，覆盖从 1/380 扩至 4/380。

## 1. 为什么不能复制 s01_05

`s01_05` 的事件结果就是玩家完成入宫、选策或协调路线，玩家行动序列全部满足后可以立即落账。
`s01_06/07` 不同：事件同时包含郭解、董卓的正典死亡。玩家完成护送或接住边警，只能证明玩家参与，
不能凭输入提前宣布死亡已经发生。因此完成合同增加两种确定性收束：

- `immediate`：步骤完成后由 runtime 立即写 `done`，用于玩家对话本身构成事件结果的结构；
- `timeline_deadline`：步骤完成只标记 ready，直到事件声明的绝对硬截止到达才由 runtime 写 `done`。
- `expiry=persistent`：只给无截止、不得场外完成的唯一引擎入口使用，避免机会过期后永久卡轴。

validator 强制 `timeline_deadline` 必须绑定 `event.timeline.deadlineTurns`。LLM 仍不能直接写这些事件的完成标记，
旧事件对账也不能跨过任一已迁移事件。

## 2. 三个合同

| 事件 | 结构 | 玩家步骤 | 真值落账 |
|---|---|---|---|
| `s01_06` 郭解之死 | 三步护持 + 正典硬截止 | 确认路线 → 护送定陶王 → 完成交接/承担护持 | ready 后等待资格第 6 回合；不会因玩家输入提前写死郭解 |
| `s01_07` 董卓之死 | 三步军情承接 + 正典硬截止 | 核对来源 → 保留未核实属性 → 交给持续联络线 | ready 后等待资格第 5 回合；不会因交接军情提前写死董卓 |
| `s01_08` 盛姬线索 | 两步持久秘密对话 | 与阮香凝私下核验 → 区分亲知/反应/推断 | 不静默过期；对话合同完成后立即落账并进入玩家知识 |

两条死亡线在截止前仍允许裁定 #95 的显式生还 IF 抢先替代；本合同没有改变登基脊柱或默认正典结果。

## 3. G1 断言

- 每个成功玩家回合最多推进一步，拒绝/撤回文本不推进；
- `s01_06/07` 全部步骤完成后，截止前 `done` 仍为 `false`；
- 到达硬截止后结果为 `participated`，不进入 `offscreenResolvedEventIds`；
- `s01_08` 只在私下核验和认识论分层两步都完成后结算；
- `s01_08` 未追踪超过 8 回合、追踪后再过 7 回合仍保留唯一完成入口；
- 三条权限各只授予一次，JSON 重载后不重复落账；
- `s01_06/07/08` 的 LLM `done` 指令全部被 `canonGuard` 拒绝；
- 缺少 deadline 的 `timeline_deadline` 合同被 validator 拒绝。

回归入口：`tests/r2_11_cross_event_completion.test.mjs`。
