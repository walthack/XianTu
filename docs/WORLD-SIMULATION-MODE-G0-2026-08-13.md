# 六朝世界模式 G0 规格

> 日期：2026-08-13  
> 状态：G0 设计与首个纵切重分类完成；**尚未修改 runtime、prompt、schema、Mod 数据或存档**  
> 首个纵切：`lyg.dingtao_beijing` 的 `lyg.event.s01_05–07`  
> 关联基线：Canon Rail、R2-0 IF、R2-9 世界引力、R2-10 NPC 决策内核、R2-11 确定性完成权、R2-17 认知探索  
> 用户目标：重现六朝世界，让玩家用自己的方式发展剧情；既不能逐拍重演，也不能让 LLM 脱离六朝因果生成一套陌生仙侠。

---

## 0. 决策摘要

本项目新增一个与现有玩法并存的实验方向：**六朝世界模式**。

它不在“忠于原著”和“自由生成”之间取折中值，而是重新分配约束位置：

1. **世界真值硬**：人物身份、能力来源、知识边界、势力、地理、既成事实与少量承重锚点仍由本地数据和引擎持有。
2. **行动表达宽**：玩家可自由调查、交涉、潜入、护送、站队、隐瞒、等待或放弃介入；表达不必等同预写按钮文案。
3. **过程由人物推动**：NPC 依据自己的目标、资源、知识、关系和当前压力行动，不因“下一拍轮到他”而行动。
4. **原著是默认未来**：无人显著改变承重条件时，世界在 NPC 行动与期限结算下自然形成原著大势；不要求玩家亲自补演每一拍。
5. **大改写必须接地**：只有本地结算已经改变承重前提时，才产生待确认的 IF；玩家输入、LLM 正文和正确猜测均不构成世界改写。
6. **分歧一旦落账就承认**：确认后的 IF 不得被系统暗中纠正、梦醒抹除或重新写回旧结果。

一句话合同：

> 锁住六朝世界的因果语法，不锁住原著逐拍发生的录像。

## 1. 模式边界与兼容策略

### 1.1 两种模式并存

| 模式 | 定位 | 运行中心 | 原著拍点地位 |
|---|---|---|---|
| `canon_companion` | 现有“原著同行线” | 唯一 Canon Rail 叙事锚点 | 逐拍 `mustReach`，现有行为不变 |
| `world_sim` | 新增“六朝世界模式” | 当前局势、压力、NPC 行动与稀疏锚点 | 默认预测与演出素材，不逐拍拥有完成权 |

兼容纪律：

- 旧存档缺少模式字段时一律解释为 `canon_companion`。
- G1 不支持同一存档中途切换模式；需要体验 `world_sim` 时创建隔离测试存档。
- 不批量翻转现有 396 个事件的 `critical`，不删除 Canon Rail profile，不改冻结 `event.id`。
- 世界模式的结果不得回写或污染同行线存档。
- G1 通过前不改变新角色默认模式，不部署到共享测试服。

### 1.2 本项不做什么

- 不做全量经济、人口、军队或几百名 NPC 的连续模拟。
- 不让 LLM 决定事件是否发生、谁死亡、谁知道秘密或 IF 是否成立。
- 不要求每个 Stage 都有重大 IF。
- 不把 R2-17 的知识按钮数量当成自由度指标。
- 不先迁移 37 个 Stage；第一个纵切未通过，不进入全库审计。
- 不把现有 `canon_companion` 降级为错误方案；它继续适合作为原著重演／同行玩法。

## 2. 世界模式的内容单元

世界模式不再把所有内容压成同一种“事件”。一个 Stage 至少区分以下五类单元。

| 单元 | 回答的问题 | 是否阻塞推进 | 是否允许改写 |
|---|---|---:|---|
| `situation` 局势 | 现在有哪些压力、人物和冲突正在运转 | 否 | 可改变局势值和人物行动 |
| `structural_anchor` 承重锚点 | 哪些大势是当前世界线必须保留的 | 是，直到满足或进入获准分支 | 只有存在正式分支合同才可改 |
| `forkable_outcome` 可分叉结果 | 若无人有效干预，某个枢纽默认如何收束 | 否，由期限或行动结算 | 仅由已审 IF 替代 |
| `opportunity` 介入机会 | 玩家当前能介入什么、代价是什么 | 否，可忽略或过期 | 只写声明过的后果通道 |
| `reference_beat` 原著参考拍 | 原著如何具体演出这一局势或结果 | 永不阻塞 | 只作表演素材，不写真值 |

这五类不是要求修改现有事件的互斥枚举。G1 推荐在 Stage 下新增独立的 `worldSimulation` 合同，并通过 `sourceEventIds` 引用现有事件；同一个源事件可以同时为局势、锚点和参考拍提供证据。这样不破坏旧 Rail，也避免为了新模式复用 `critical` 的旧语义。

### 2.1 为什么“可分叉结果”不能继续叫硬锚点

郭解之死与董卓之死都重要，但裁定 #95 已批准正式生还 IF。它们在世界模式中必须是：

- 默认会发生；
- 玩家不介入时由世界按期限结算；
- 玩家尝试不等于改变；
- 本地行动真正使人物进入 `alive / longrest / incapacitated`，并经玩家确认后，才由正式 IF 替代；
- 无论死或生，都不能取消定陶王继统这条更高层的脊柱。

把这类枢纽继续当作不可变锚点，会让 IF 成为系统例外；把它降成毫无约束的自由事件，又会让 LLM 任意复活。`forkable_outcome` 正是两者之间缺失的语义。

## 3. 权威分层

| 层 | 权威来源 | LLM 权限 |
|---|---|---|
| 世界本体 | canon、registry、地图、势力、能力与物品来源 | 只能引用，不得新增冲突实体或能力 |
| 承重锚点 | `structural_anchor` 本地状态谓词 | 不得满足、取消或代写 |
| 枢纽结果 | 本地行动结果、期限结算、正式 IF 合同 | 只能演出已经落账的结果 |
| NPC 决策 | `decisionCore` 的目标、资源、知识、关系、行动库与评分 | 只能渲染最终选择和可见信号 |
| 玩家行动 | 玩家输入＋可见判定＋本地条件 | 可理解表达，不可把意图写成成功事实 |
| 玩家/NPC 知识 | `playerKnowledge`、`npcPrivateKnowledge` | 只按 holder、状态与披露范围演出 |
| 过程余波 | 关系、警觉、资源、伤势、路径、回执、记忆 | 只消费已落账状态，不得补账 |
| 表演 | 对话、动作细节、感官、节奏、镜头 | 可自由发挥，但不得新增权威事实 |

硬规则：

1. 玩家输入是行动提案，不是事实写入。
2. LLM 正文不是锚点、死亡、生还、知识升级或关系变化的证据。
3. NPC 决策器只能选择数据声明的行动，但玩家表达不要求逐字匹配行动标签。
4. 自由输入未匹配权威后果通道时，可以产生观察、对话、拒绝或无结果叙事；不能静默升级成世界变化。
5. 所有影响后续选择的变化必须有本地回执；仅换形容词不算路径差异。

## 4. 运行循环

世界模式每个玩家回合按以下顺序结算：

```text
玩家提出行动
  → 解析对象、地点与行动类型
  → 检查知识、位置、资源、时机与世界边界
  → 必要时显示可见判定并由本地引擎结算
  → 写入一次性行动回执与白名单余波
  → 唤醒受影响的 NPC／势力
  → NPC 决策内核选择、冲突并结算行动
  → 更新局势值、人物记忆、机会与世界时钟
  → 检查承重锚点和可分叉结果
  → 若将替代默认枢纽，生成 pending divergence
  → LLM 按“已结算事实”渲染本轮
```

### 4.1 三种普通结果

| 结果 | 判定 | 处理 |
|---|---|---|
| 局部变化 | 改变关系、伤势、路线、知识、资源或站位，但承重条件仍成立 | 直接落账，继续世界线 |
| 默认大势 | 玩家未改变承重前提，世界行动或期限到点 | 场外／亲历结算默认结果，不伪记玩家完成 |
| IF 候选 | 本地成功结果会替代一个已有正式分支的枢纽结果 | 暂停权威写入，要求玩家确认后激活 IF |

### 4.2 不允许第四种“隐形纠正”

若玩家已经通过合法结算救下某人，系统不得：

- 让同一人物下一段无来源暴毙；
- 把结果解释成梦境、误会或短暂幻象；
- 因后续 Rail 到点而覆盖人物状态；
- 只改正文，不写 IF／分歧账本；
- 为了回轨删除已经发生的关系、代价或见证记录。

## 5. 锚点与 IF 的确定性合同

### 5.1 目标数据形态

以下为 G1 的目标合同，不代表当前 schema 已实现：

```ts
interface ScenarioWorldSimulation {
  version: 1;
  situations: ScenarioWorldSituation[];
  structuralAnchors: ScenarioStructuralAnchor[];
  forkableOutcomes: ScenarioForkableOutcome[];
  referenceBeats: ScenarioReferenceBeat[];
}

interface ScenarioStructuralAnchor {
  id: string;
  summary: string;
  sourceEventIds: string[];
  successWhen: ScenarioCondition[];
  impossibleWhen?: ScenarioCondition[];
  defaultResolutionId?: string;
  branchIds?: string[];
}

interface ScenarioForkableOutcome {
  id: string;
  sourceEventId: string;
  defaultWhen: ScenarioCondition[];
  defaultResolutionId: string;
  replacementBranches: Array<{
    branchId: string;
    localEvidence: ScenarioCondition[];
  }>;
  preserveAnchorIds: string[];
}
```

设计纪律：

- `summary` 只给作者和玩家解释，不参与模糊文本判定。
- `successWhen / impossibleWhen / localEvidence` 只读取引擎专属状态。
- `sourceEventIds` 保留来源追溯，不授予旧事件完成权。
- `defaultResolutionId` 优先复用已有 `offscreenResolution`，避免并行真值源。
- `branchId` 必须指向已验证的 IF；无正式分支时不得临时生成永久世界线。
- 跨 Stage ID 全局唯一，碰撞 fail-closed；旧 `event.id` 继续 append-only。

### 5.2 待确认分歧

`pendingDivergence` 只能在以下条件同时成立时建立：

1. 本轮行动已经由本地引擎结算成功，而非 LLM 自称成功；
2. 结果命中 `replacementBranches.localEvidence`；
3. 对应 `branchId` 已存在且状态允许运行；
4. 所有 `preserveAnchorIds` 仍可满足；
5. 同一行动结果尚未确认、取消或应用，重载不重判；
6. UI 明示替代的默认结果与主要长期后果。

确认后原子地完成：写人物／世界状态、写分歧账本、激活 branch、关闭默认结果。任一步失败都不得部分写入。

取消只表示玩家不执行这项会造成分歧的最终行动；已经支付的准备成本如何处理，必须由行动合同预先声明，不能由 LLM 临时决定。

## 6. NPC 决策内核如何接管过程

现有 `worldActor.decisionCore` 已具备 G1 所需的大部分地基：

- 小规模承重 NPC 状态；
- 已知事实与私密知识隔离；
- 局势白名单；
- 候选行动、资源成本、效用评分；
- 冲突、反制、多回合行动；
- 分层唤醒、记忆与跨事件继承；
- `invariant / forbiddenBefore / processFreedom`。

G1 的关键改造不是扩大数值维度，而是改变它的宿主：

| 当前 | 世界模式 |
|---|---|
| `decisionCore` 依附唯一当前 Rail 事件 | `decisionCore` 依附当前 `situation` |
| 世界 push 帮当前拍点增加演出 | 世界 push 推动局势和锚点接近结算 |
| 当前事件切换时重建 actor state | 局势生命周期内持续，跨参考拍不重置 |
| 机会服务“完成当前事件” | 机会服务玩家介入世界压力 |

防止行动库重新变成另一种脚本：

- NPC 行动库只规定“能对世界做什么”，不规定每回合台词和镜头。
- 同一行动应能在不同关系、路线和玩家介入下产生不同可见过程。
- 高分但违反承重边界的候选必须明确淘汰并留审计回执。
- `force_succession` 这类故意违反 `invariant.cancel_enthronement` 的高分候选只作负向门禁样本，永远不得进入实际结算池。
- 扩量仍只覆盖每关约 5–15 名承重 NPC；次要角色走轻量反应，不建立全量数值档案。

## 7. 防止“陌生仙侠漂移”的世界护栏

世界模式放宽剧情过程，不放宽世界本体。G1 prompt 与验证层至少维持以下六道边界：

1. **实体闭包**：重要人物、势力、地点、功法、物品优先来自 registry／当前 Stage；陌生专名不能因 LLM 一句话进入世界状态。
2. **能力来源**：角色只能使用已掌握、当前可用且语义相符的能力；不能因“仙侠常识”补出法宝、雷劫、系统任务或陌生宗门。
3. **力量尺度**：行动后果不得超过人物境界、资源、地理和在场条件；宏观变化须由局势／锚点合同承接。
4. **人物内核**：NPC 选择必须来自目标、知识、关系和资源；LLM 不得为了戏剧效果把人物突然改成另一种性格。
5. **认知隔离**：秘密只向 holder 和已获知玩家投影；读者元知识、模型预训练记忆和正确猜测均不升级账本。
6. **语汇与国别风貌**：继续执行汉／唐／宋／秦／晋分国风貌、太泉认知差、南荒／昭南等既有裁定；世界模式不是通用修仙沙盒。

漂移信号只负责报警和收窄可见材料，不得自动把玩家拖回某个原著场景。高漂移时的正确动作是拒绝无来源世界事实、让在场人物按自身目标回应，或要求玩家在现有资源内重新表述。

## 8. LLM 输入合同

世界模式每轮只投影与当前局势有关的最小材料：

```text
当前地点与可见环境
当前局势压力与公开状态
本轮已结算的玩家行动回执
本轮已结算且玩家可见的 NPC 行动
在场／被点名人物各自实际知道的事实
有效关系、伤势、资源、路径与短期记忆
仍不可改变的承重锚点
当前允许表演的 reference beat（如有）
禁止新增的事实、实体、未来与精确数字
```

不再把一串未来 `mustReach` 当作本轮必须演出的剧情提纲。

`reference_beat` 的使用规则：

- 只有当对应结果已经由引擎结算或当前确实进入该现场，才可投影。
- 玩家缺席时只生成消息、余波或他人行动，不补演“玩家亲眼见证”。
- IF 已替代默认结果时，旧参考拍立即失效，由 branch replacement node 提供新材料。
- 半预制高光仍可保留，但它是“这个已发生结果怎样演得好”，不是“为了演这段而强制结果发生”。

## 9. UI 最小形态

G1 不重做全界面，只替换世界模式下右栏的叙事中心：

### 当前局势

- 一句话压力摘要；
- 1–3 条玩家可见的正在发生变化；
- 距离重要期限的自然语言提示；
- 不显示内部 `eventId`、分数公式或“主线完成”。

### 可介入机会

- 当前能做什么；
- 为什么现在；
- 可见代价与可能影响；
- 可以忽略，忽略后世界仍继续。

### 世界变化

- 最近的确定性回执；
- 玩家亲历／场外获知明确区分；
- IF 确认后显示世界线变化及仍被保留的承重事实。

自由输入始终保留。结构化入口是可靠的行动 affordance，不是唯一允许的措辞；自由输入匹配同一对象、时机和行动语义时，应走同一预检与本地结算，而不是降级成纯闲聊。

## 10. 定陶王纵切重分类

### 10.1 更高层正典边界

`yange.story-spines.json` 的 `arc_dingtaowang_enthrone` 表明：

- 本段完成定陶王政治继统；
- 后续 `yange.45.3 / yange.46.2` 仍有登基大典与继统收束；
- G1 不得把 `s01_05` 的昭阳宫拥立与后段完整大典合并成同一场景，也不得提前演出后段赵飞燕助行功与程宗扬突破。

因此本纵切硬锚点命名为“**定陶王政治继统成立**”，而不是“全套登基大典已经演完”。

### 10.2 `lyg.event.s01_05`：拥立局势

| 维度 | G0 分类 |
|---|---|
| `situation` | `world.lyg.s01_05.enthronement_imminent`：军事控制转成朝廷承认的新秩序 |
| `structural_anchor` | 定陶王政治继统成立；新君身份不可被当前普通行动替换 |
| `reference_beat` | 董卓在昭阳宫拥立；贾文和提出大赦、选材、迁都等方案 |
| `opportunity` | `first_edict`、`court_entry` 两张既有机会卡 |
| 默认缺席结果 | 复用 `offscreen.r2_9.lyg_event_s01_05`；玩家不介入也完成政治拥立，但不伪记亲历 |

硬事实：

- 定陶王成为新君；
- 董卓、贾文和、霍子孟、吕雉均按各自动机参与权力交接；
- `force_succession` 因命中 `invariant.cancel_enthronement` 被淘汰；
- 不提前演郭解、董卓生死或阮香凝秘密。

过程自由：

- 玩家走哪条入宫路线、是否在场；
- 偏向凉州军强制秩序或汉廷正式程序；
- 第一诏优先项、公开站位与失去的另一项机会；
- 霍子孟、董卓、贾文和与吕雉如何评价玩家；
- 军事紧张与合法性以何种组合收束。

结果回执至少保留：`route / allegiance / policyPriority / witnessed / obligations / permissions`。这些回执必须在后续场景被实际消费，而不是只改变一句形容词。

### 10.3 `lyg.event.s01_06`：郭解枢纽

| 维度 | G0 分类 |
|---|---|
| `situation` | `world.lyg.s01_06.assassination_window`：剑玉姬逼近，郭解护持新君 |
| 上层锚点 | 定陶王安全并继续继统；程宗扬承担护持责任 |
| `forkable_outcome` 默认 | 郭解重伤身亡，稍后公开消息；复用现有期限与 offscreen resolution |
| 正式替代 | `lyg.if_guojie_longrest`：郭解生还／长养，托孤改为受限辅政 |
| `reference_beat` | 剑玉姬重创郭解、临终托付；只有默认结果已结算时可演 |
| `opportunity` | `royal_escape`：确认路线、护送新君、移交护持责任 |

过程自由：

- 撤离路线、耳目接应、玩家是否亲历；
- 玩家保护新君、牵制剑玉姬、救治郭解或放弃介入；
- 成败造成的伤势、关系、警觉、见证范围与后续责任。

IF 门槛：

- “我要救郭解”不触发；
- 普通成功保护新君也不自动触发；
- 只有经过本地对抗／救治合同后，郭解确定进入 `alive / longrest / incapacitated`，才建立 `pendingDivergence`；
- 确认后激活现有 branch，并继续保留“定陶王由程宗扬护持、登基照常”；
- 失败、部分成功或 `missing` 不得冒充生还 IF。

### 10.4 `lyg.event.s01_07`：董卓枢纽

| 维度 | G0 分类 |
|---|---|
| `situation` | `world.lyg.s01_07.liangzhou_succession`：董卓无法久持，边警与旧部需要承接者 |
| 上层锚点 | 董卓退出洛都争权；贾文和收束凉州旧部；定陶王继统不变 |

过程自由：

- 边警交给谁、如何标示未核实；
- 凉州旧部撤离次序、补给与有限联络；
- 玩家是否承担传递、后勤或见证责任；
- 贾文和如何评价、使用或防备玩家。

IF 门槛：

- 本地救治成功使董卓进入 `alive / longrest / incapacitated` 才建立候选；
- 生还不等于恢复权力，branch 必须同时写入“不得回京争权／由贾文和收束旧部”；
- 若玩家只接住军情、改善后勤或在送别时陪伴，均属于局部变化，不进入 IF；
- 默认死亡和生还 IF 都必须保留边警与旧部余波。

### 10.5 局势衔接，而非玩家逐拍打勾

当前旧数据为：

```text
s01_05.done → 激活 s01_06
s01_06.done → 激活 s01_07
```

世界模式目标改为：

```text
政治继统成立（亲历或场外）
  → 刺杀压力进入可结算窗口
  → 郭解枢纽已结算（默认／IF／非生还后果）
  → 凉州承接局势进入窗口
```

衔接依据是世界状态和 outcome ledger，不是要求玩家分别点击三个 `done`。来源顺序仍保留，但玩家缺席、换路线或以不同身份介入不会卡死。

## 11. G1 验收矩阵

同一正式 fixture 至少确定性重放以下路线：

| 路线 | 预期大势 | 必须保留的差异 | IF |
|---|---|---|---|
| A 完全不介入 | 定陶王政治继统；郭解、董卓按默认结果结算 | 三次均标场外，玩家无亲历权限 | 无 |
| B 偏凉州军 | 定陶王政治继统 | 凉州站位、政策优先项、关系与后续权限 | 无 |
| C 偏汉廷程序 | 定陶王政治继统 | 入宫路线、正式背书、霍子孟／吕雉关系 | 无 |
| D 尝试救郭解但失败 | 新君安全；郭解默认结果 | 失败原因、伤势／代价、NPC 记忆长期保留 | 无 |
| E 确实救下郭解并确认 | 新君安全、继统不变 | 郭解转受限辅政、游侠网络与程宗扬共同护持 | `lyg.if_guojie_longrest` |
| F 确实救下董卓并确认 | 继统不变、董卓退出洛都 | 贾文和收束旧部、董卓长养、边警继续承接 | `lyg.if_dongzhuo_longrest` |

每条路线都必须验证：

- 决策全程可重放，同输入同输出；
- JSON stringify／parse 后状态与哈希一致；
- LLM 0 次参与也能完成全部世界结算；
- LLM 无法写 world turn、锚点、outcome、IF、人物生死或知识状态；
- 玩家缺席不伪记亲历，不授予机会奖励；
- reference beat 不抢跑、不在 IF 后复演旧结果；
- 关系、知识、伤势、路径和人物记忆至少有一个后续消费点；
- 旧 `canon_companion` 的现有测试逐字节不回退。

### 11.1 真机体验门

自动门通过后，真实模型至少检查：

1. 不读攻略时能否理解“世界在动，我可介入但不必补任务”。
2. 两条非 IF 路线是否真的改变后续互动，而不只是按钮标签不同。
3. 自由表达是否能命中与结构化入口相同的本地合同。
4. 尝试救人失败时，模型是否承认失败而不偷偷送成功。
5. IF 确认后，模型是否稳定承认生还与相应限制。
6. 连续自由行动 8–12 回合是否仍像六朝人物在行动，而不是生成陌生宗门、法宝或系统任务。

## 14. G0 结论

定陶王关已经具备理想纵切所需的几乎全部既有资产：成熟的 NPC 决策器、局势值、机会卡、世界期限、场外结算、人物记忆、分歧账本以及郭解／董卓两条正式生还 IF。

真正缺失的不是更多事件或 prompt 约束，而是一层新的运行语义：

> 让 `s01_05–07` 成为三个相连的世界局势，其中只有“定陶王政治继统”是硬锚点；郭解与董卓的结局是有默认值、有本地证据门槛、可由正式 IF 替代的枢纽；原著逐拍文本只在相应结果已经成立时负责演出。

G1 若不能让 A–F 六条路线在同一世界因果下稳定成立，就不得扩量。
