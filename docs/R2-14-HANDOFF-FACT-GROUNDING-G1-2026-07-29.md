# R2-14 跨拍叙事事实接地 G1

日期：2026-07-29

## 问题

R2-13 最终真机中，余波轮在没有存档、正典或本地回执依据时，补造了“死三人／共四人、伤七人、三辆车、两匹骡子”等精确损失。正文没有回写世界状态，确定性合同也没有被污染，但玩家仍会把阅读面中的精确数字理解成已发生事实。

## V1 边界

当前引擎没有结构化损失回执，不能可靠回答“哪一个精确伤亡数字已经接地”。因此 V1 不从正文、事件摘要或相同数字碰撞反推真值：

1. 只在 `lastSettledBeat` 的余波铺垫与目标动作触发两种承接 prompt 中启用；
2. 精确伤亡、伤者、失踪者、财货、车船和牲畜损失改用定性表述或“仍待清点”；
3. 普通参与人数、正常物件数量及不含损失语义的数字不受影响；
4. 带明确消息来源、并明确标为未核实的角色传闻可以演出，但不得写回世界状态；
5. 首稿违规进入既有缓冲重写，末次仍违规才使用本地安全正文；
6. 不新增事件字段，不改变 completion contract、hash、进度或跨拍生命周期。

将来若本地判定、effects 或事件回执提供结构化损失事实，再扩展为“只放行回执中声明的精确值”；在此之前不建立脆弱的正文数字白名单。

## G1 验收

- R2-13 两阶段承接 prompt 均含 `renderGuard.rejectUngroundedHandoffLosses=true`；
- 真机原句的四种形态必须被拦：死亡人数、伤者人数、车辆损失、牲畜损失；
- “仍待清点”、普通“两人扶行”、无损失语义的“三辆车继续前行”必须放行；
- “探子据报伤七人、消息尚待核实”作为有来源 rumor 放行；
- marker 会开启渲染缓冲，违规草稿不得直接进入显示与存档；
- R2-13 的合同 hash、preparations、按钮时序和完成权不受影响。

## 非目标

- 不解决所有叙事幻觉；
- 不把所有中文数字都列为禁词；
- 不从 LLM 正文生成权威损失回执；
- 不回填全库事件；
- 不重新打开已经通过的 R2-13。

## 实施结果

G1 已落地：

- 两种跨拍承接 prompt 都注入限定 marker 与定性改写要求；
- 语义门禁只检查“精确数量 + 人员伤亡／财货损失”组合，不检查裸数字；
- 新门禁复用既有首稿缓冲重写与末次本地安全正文；
- 关卡级 `allowUnverifiedQuantities=false` 优先于承接层 rumor 豁免，组合提示词不会被新规则削弱；
- 定向回归 23/23、`type-check`、`canon:build`（512/512、37 关）与 production build 全绿；
- completion contract、事件数据、runtime schema 与 builtin 内容均未改变。

1. `processGmResponse()` 成功后给响应写入客户端 `transactionCommitted=true`，明确区分“生成失败、尚未落账”与“事务已经提交”；

3. 已提交响应不再因任何模型附带字段而重新执行玩家行动；
4. 生成失败或尚未落账的响应仍要求非空 `mid_term_memory`，继续走既有结构重试，不削弱 R2-1 失败恢复；
