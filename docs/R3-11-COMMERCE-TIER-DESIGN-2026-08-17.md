## 1. 意图（用户原话）

> 「商业线单独做成一条二级线，我本来的设想是后期通过**商业版图的扩展**
> （攻略各个国家获得**地区声望**）来获得**稳定的金钱／物品**。」——2026-08-17

这句话定义了本线与另外八条的结构差别：

**它不是第九条平行故事线，是下游汇聚层。**
其余八条线打下的地盘，在这条线上结算成收入。

`reputationLedger.ts` 的文件头当初就是这么立项的〔核实〕：

> 【为什么必须先做】它是商队经营层的前置。经营层的定义是「别处的地位在此处折现」，
> 若地位本身由模型随手给出，折现出来的就是模型心情，不是玩家的经营成果。

即：**本设计的前置已经在 2026-08-16 做完了**，当时就是为它做的。

## 3. 商道线的故事脊椎（已落地，供折现层挂载）

```
seq 134  以一笔兵器生意化开阁罗那边的刀兵      ← 锚：第一次发现生意能办武力办不成的事
seq 359  织坊换局：拿下第一处自己的产业        ← 第一处不动产
seq 404  凑出十万金铢军资
seq 465  把粮价算成一盘棋
seq 496  定下常平仓火计
seq 534  接管鹏翼社，第一次手里有了整个商社     ← 第一次有组织
seq 550  发临安粮战令
seq 575  问清纸钞是怎么回事
seq 578  让纸钞能纳税——自己发的钱，官府认了     ← 第一次有货币权
seq 618  拿水泥换一纸休战
seq 644  开盘江程氏第一次股东大会：分红、发股、定主业  ← 第一次有股权结构
seq 885  用自己发的钞去买田                  ← 钱变成地，即变成权
```

主语一路在变：**换钱 → 换军资 → 定粮价 → 接管商社 → 发行货币 → 开股东大会 → 买田**。
这是全书唯一一条把「有钱」变成「有权」的链。

折现层的**倍率台阶**就取这条弧上的四个质变点〔推断〕：
`织坊`（不动产）→ `鹏翼社`（组织）→ `纸钞纳税`（货币权）→ `股东大会`（股权）。

## 4. 折现层设计〔推断〕

### 4.1 形状：与既有两处结算同构

照抄 `settleSharedExperienceAffinity`／`settleEventReputation` 的三条纪律，挂进同一个
`advanceScenarioRuntime`：

1. **只算玩家亲历**——`offscreenResolvedEventIds` 不计入版图。
2. **幂等**——收益是**状态的函数**，不是累加记账。`regionStanding` 本身已是派生量、
   无历史包袱，折现层照此设计，则旧档无补发／重复计算问题。
   （好感那边踩过补发的坑，不重蹈。）
3. **走引擎通道**——收益由引擎给，模型只负责叙述「这个月商号送来了多少」。

### 4.2 收益公式（初值，结构定死数值可调）

```
每回合收益 = Σ(各地区) 立足度(0..100) × 地区系数 × 商道台阶倍率
```

- **立足度**：`regionStanding()` 现成〔核实〕。
- **地区系数**〔推断〕：富庶程度不同。宋国（临安、纸钞、粮战主战场）> 汉国（洛都）
  > 唐国（长安）> 晋国 > 昭南 > 塞外。初值建议 1.5／1.2／1.2／1.0／0.8／0.5。
- **台阶倍率**〔推断〕：未过 `织坊换局` = 0（本线未开，不产生收益）；
  织坊 ×1／鹏翼社 ×2／纸钞纳税 ×4／股东大会 ×8。

**为什么倍率在商道线上、系数在地区上**：这样两条轴各管一件事——
「你在多少地方站住了脚」由其余八条线决定，「你有多会把地位换成钱」由本线决定。
两者相乘，才是用户说的「商业版图的扩展」。

### 4.3 产出物

- **金钱**：结进 `currencySystem` 钱包，用既有币种，不新增。
- **物品**〔推断，第二期〕：地区特产按立足度概率产出。**第一期不做**——
  物品产出要接背包与掉落表，是另一个面；先把钱这条打通。

### 4.4 玩家可见

必须进玩家可见的状态流——既有两处结算都返回 `grants` 明细正是为此〔核实〕：

> 「引擎侧的变化必须能进玩家可见的状态流，否则因果只存在于代码里。」

商贾线的明细形如「宋国商号本月解来 X（立足度 60）」，让玩家看得见钱是**哪来的**。

## 5. 待裁定的设计问题（实施前必须先定）

### ⚠ P1：玩家对版图有没有能动性？

`regionStanding` 目前由 `STAGE_ORDER` 走过比例**派生**〔核实〕，即
**「主线打到哪，就在哪有分量」**——玩家无法主动选择经营某地。

用户的原话是「通过商业版图的**扩展**」，"扩展"读起来像是玩家的动作。两条路：

| | 甲：保持纯派生 | 乙：加可投入分量 |
|---|---|---|
| 含义 | 打到哪赚到哪 | 玩家可选择在某地投入，换更高立足度 |
| 改动 | 折现层即可，`regionStanding` 不动 | 需给立足度加第二个来源（本线节点／玩家行动） |
| 幂等 | 保持（纯状态函数） | 破坏——投入是历史，要记账，旧档要处理 |
| 与用户原话 | 「攻略各个国家获得地区声望」对得上 | 「商业版图的扩展」对得上 |

**我的倾向：先甲后乙。** 甲能立刻跑通、零历史包袱，且已经满足「攻略国家 → 稳定收益」这句；
乙的经营深度等甲跑起来、手感有了再加，届时也更知道该让玩家投入什么。
但这是用户的判断，实施前须确认。

### P2：收益节奏

每回合结算会让数字频繁跳动。是否改成「每 N 回合／每季」解一次账，更像商号送钱？〔推断，倾向后者〕

## 6. 不做什么（边界）

- **不做经营模拟**——不建交易品价格表、不建供需模型。与世界引擎的既定方向一致：
  确定性调度定「发生什么」，LLM 只管「怎么讲」，而**经营层只定"多少"，不定"怎么经营"**。
- **不新增币种**。
- **不动 `regionStanding` 的派生性**（除非 P1 裁定走乙）。
- **不把变现能力写进现有节点文案**——在折现层落地前，商道线的节点只是故事。

## 7. 记一条方法教训

本文档上一版把「地区声望不存在、无任何引擎侧计算」当**核实事实**写出并提交进代码注释。
错因：按中文 `声望` grep，只捞到类型定义与初始化 0，就下了结论；
而引擎侧模块用英文命名（`settleEventReputation`／`reputationLedger.ts`／`regionStanding`），
整个已实现的机制在检索结果之外。

**这个仓库中英混用命名，单语言 grep 的阴性结果不构成"不存在"的证据。**
断言某能力不存在之前，中英双查，或直接看 `advanceScenarioRuntime` 挂了哪些结算。

> 「商战线设想是 **开盘江程氏第一次股东大会：分红、发股、定主业 为一个阶段**，
>  之后进入**大地图上跑商模式**（**选择某个角色，让他行动去另外一个地点交易，

>

### 两层并存，不是二选一

本节初稿把它写成「推翻 §4」，**是错的**，已按用户更正改写。两者性质不同：

| | 第一层：折现（§4） | 第二层：跑商（本节） |
|---|---|---|
| 触发 | **自动**，每回合结算 | **玩家操作**，选人派出 |
| 性质 | **底盘收入**——你在多少地方站住了脚 | **一次性收益**——这一趟跑成了赚多少 |
| 依据 | `regionStanding` × 地区系数 × 商道台阶 | 派谁去、去哪、路上遇上什么 |
| 玩家感受 | 「商号每月解来多少」 | 「这趟我押对了」 |

**join 点：立足度既是底盘收入的乘数，也应当是跑商的门槛与成功率来源。**〔推断〕
在某地毫无立足度，就不该跑得通那条线——这样第一层自然喂养第二层，
八条线打下的地盘同时决定「躺着收多少」和「能往哪跑」。

### 这对 §5 的 P1 意味着什么

P1 问的是「玩家对版图有没有能动性」，甲＝纯派生／乙＝可投入。
既然两层并存，**答案不是甲或乙，而是：第一层保持甲，第二层给能动性。**

这恰好保住了 §4.1 第 2 条纪律——**折现层仍是纯状态函数、幂等、旧档无补发**；
「玩家做过什么」的历史记在跑商那一层（派遣是有始有终的一次行为，本来就该记账）。
即：P1 的顾虑（乙破坏幂等）通过分层被绕开了，两层各自保留自己该有的性质。

### 阶段界线：股东大会

> 「**开盘江程氏第一次股东大会：分红、发股、定主业 为一个阶段**」

即商道线现有节点 seq 644 **是这条线的阶段分界**：
之前是「一笔笔做生意」（兵器→织坊→军资→粮战→接管商社→发行纸钞），
之后才进入**经营模式**。与 §3 的四级台阶吻合——股东大会正是最后一级（股权结构）。
