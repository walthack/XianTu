## 1. 当前机制

当前 R2-11 纵切已经把 `s01_05.done` 写入权收归引擎，但推进交互仍是过渡态：

1. 点击右栏机会卡后，模组预写的整段 `actionText` 进入行动队列。
2. 后续主界面 `action_options` 由 LLM 生成，仅为普通字符串。
3. 玩家点击普通选项，只是把字符串填入输入框；选项不携带 `opportunityId / stepId / actionId`。
4. AI 回合成功返回后，本地合同以 `matchAny / matchAll / rejectIf` 匹配玩家文本，每个世界回合最多推进一步。
5. 全部步骤满足后，由 runtime 独占写事件 `done`。

该机制证明了“完成真值不依赖 LLM”可以成立，但文本匹配只能作为自由输入兼容层，不能成为最终主要交互。

## 2. 已确认的问题

- LLM 未生成贴合当前步骤的选项时，玩家不知道如何稳定推进。
- 玩家表达了正确意图，仍可能因措辞不同而不命中。
- 普通对白可能偶然包含关键词并误推进。
- 引擎只记录步骤序号，无法可靠保存“安民 / 选材 / 定都”等具体选择。
- 当前机会卡没有显示步骤进度、剩余时间或行动时间成本，静默失效会破坏信任。
- `steeringCooldown` 可以暂停停滞计数；如果它也冻结关键事件，玩家长期闲逛可能卡死世界线。

## 3. 设计原则

1. **世界事件不冻结**：关键事件受不可被支线冷却暂停的绝对世界时间截止约束。
2. **玩家可安排时间**：事件窗口要预留合理的闲逛、社交、准备和修炼预算。
3. **机会成本必须可见**：显示当前步骤、总进度、剩余时间和行动时间成本。
4. **推进动作由引擎声明**：LLM 可以提议和润色，但不能决定一个选项是否属于机会步骤。
5. **自由输入继续有效**：自由文本可映射为结构化动作；无法可靠映射时按普通行动处理，不误推进。
6. **错过不等于卡死**：截止时按 `participated / partial / offscreen` 确定性收束并继续事件链。

## 4. 推荐交互：引擎选项与 LLM 选项合并

玩家主动追踪机会后，主界面固定插入当前步骤的引擎选项；其余位置继续显示 LLM 生成的自由选项。

示例：

- `【推进·1/2】向霍子孟提交定陶王安全依据`
- `【准备】先向宫门守军核实情况`
- `询问吕雉对霍子孟的判断`
- `与吕雉修炼`
- `暂时离开昭阳宫`

引擎选项必须携带结构化元数据，而不是只有显示字符串：

```text
source: opportunity_engine
opportunityId: opportunity.lyg.s01_05.court_entry
stepId: prove_emperor_safety
actionId: submit_safety_evidence
timeCost: 1
contractHash: ...
```

点击后，引擎先校验该选项仍属于当前合同与当前步骤，再登记动作。LLM只接收适合叙述的玩家行动文本，负责演出过程与反馈。

## 5. 一个步骤允许多个真实选择

合同步骤不能只声明关键词，还应允许声明多个结构化动作变体。

例如诏令线“选择政策优先项”应提供：

- `prioritize_relief`
- `prioritize_talent`
- `prioritize_capital`

选择结果必须写入机会回执或独立状态，供后续态度、局势值、NPC记忆与编年史消费；不能只把 `completionStepIndex` 加一。

## 6. 尝试、判定与完成分离

不同动作采用不同结算策略：

- 到场、选择、承诺：玩家明确执行即可完成。
- 战斗、潜入、说服、协调：先进入本地判定，再按结果记为完成、部分完成或失败。
- 条件不足：显示缺少的地点、证据、权限、资源或剩余时间；可允许玩家先选择准备动作。

建议统一状态：

```text
未开始 → 已尝试 → 完成 / 部分完成 / 失败 → 下一步骤
```

LLM正文不能把“尝试”提升为“完成”。

## 7. 追踪与执行分离

- **追踪**：表示玩家关注该机会；原则上不耗时、不推进。
- **执行**：玩家选择当前步骤的具体动作后，才消耗时间并进入结算。

当前“追踪即把整条路线 actionText 加入行动队列”的过渡行为，实施本设计时应拆除，改为追踪后展示当前步骤选项。

## 8. 时间窗口与收束

每个关键事件声明绝对世界截止；机会是否仍可接由“剩余时间是否足够完成剩余步骤”计算。

UI至少显示：

- `进度：1/3`
- `当前步骤：明确政策优先项`
- `时间：尚宽裕 / 正在收紧 / 最后机会`
- `预计还可进行 3 次重要行动`
- `本动作耗时：1`

玩家闲逛或修炼会正常消耗世界时间，但不会被暗中惩罚；玩家能够事先判断是否仍来得及介入。

截止时：

| 结果 | 条件 | 收束 |
|---|---|---|
| `participated` | 全部步骤完成 | 完整路线影响、回执与权限 |
| `partial` | 完成过有效步骤但未完成合同 | 保留关系、经历和局部影响，不授完整权限 |
| `offscreen` | 未有效介入或完全错过 | 世界自行结算、零权限、不伪记亲历 |

`steeringCooldown` 只能抑制主线催促和停滞提示，不能暂停绝对事件截止。

## 9. 实施门禁

当前真机验证结束前不改变生产实现。后续实施须满足：

1. 换叙事模型后，引擎推进选项仍存在且语义不变。
2. 追踪本身不被误算为完成步骤。
3. 点击引擎选项不依赖中文关键词。
4. 过期或跨步骤的旧选项在发送时被本地拒绝。
5. 自由输入可映射到结构化动作，但模糊文本不误推进。
6. 具体选择、失败、部分完成和时间成本进入可重放状态。
7. UI明确显示进度与剩余窗口，机会不得静默失效。
8. 到达绝对截止后事件链必然收束，不受 `steeringCooldown` 冻结。
9. R1 / R2 / 闲逛至截止三路线均有零 LLM 状态层重放，并补真机体验验收。

## 10. 非目标

- 不把所有自由行动改成任务按钮。
- 不取消 LLM 提供的情境化、创造性行动选项。
- 不让 LLM 生成或修改权限、时间成本、步骤结果与世界真值。
- 不在当前真机验证中途更换基线。
