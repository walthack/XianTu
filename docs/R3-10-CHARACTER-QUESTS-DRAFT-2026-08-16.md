## 0. 口径

### 0.1 第三级不许抢上级的 event

人物任务是最低一级。两件硬事：

1. **不许抢已被上级认领的 event。** 主轴 `MAIN_QUEST_NODES` 与八条二级线 `nodes[].eventId` 认领过的，人物任务只能挂在它下面当插入段，不能把它算成自己的节点。
2. **主场是无人认领的那一大块。** 事件层 396 条。用户表写认领约 65；本轮核 `eventId` 字面：现成 `ready` **76** 条已落地 id，另有 `new` 建议 id **36** 条（尚未落地，但已认领）。人物线从剩下那一大块长。

「认领」以 `eventId` 字面为准（含 `status: 'new'` 的建议 id）。`pending` 无 id 的槽不算认领。

同一 event 可以双喂：上级读组织／权力，本级读这个人向你开的口。禁止两条线抢同一句 `objective`。

### 0.2 活侠传式插入

每一拍写成：

```
〔在 <真实 event id> 期间〕 → 这个人向你提出／暴露了什么 → 你的处置 → 后果落在哪
```

不写「第几关第几步」。

### 0.3 标记

| 标 | 含义 | 该给什么 |
|---|---|---|
| `✅ 已有` | 可达关里已有 event，四字段承载同一件情节事实 | 真实 id ＋ `axisSeq` |
