# Demo 试玩说明与 agent 观察清单

本轮目的：实际玩一段连续游戏，找出任务线与预期的差距。**能通关不等于任务设计合格；先观察、记录，不边玩边改。**

## 玩家：怎么开始、怎么玩

1. 打开游戏首页 → **星月湖任务线试玩** → **从飞机落地开始**。已有进度就选「继续落地连续档」。不要选折叠区的海神殿旧三幕短版。
2. 新档应从草原落地开始，段强在附近；一路保留中间旅程，接到星月湖的阶段结局。它不是完整游戏，也不是整个星月湖故事完结。
3. 按自己的理解玩：看正文与当前目标，用自然语言描述行动，或使用建议动作。遇到判定、地图、背包或「继续旅程」，按游戏界面操作。**不必研究攻略，不必每次选“正确答案”。**
4. 不知道做什么、为什么去下一处、为什么信任某个人，直接说出来。觉得选择没区别、节奏拖沓，也照常反馈；不需要先判断是不是 bug。
5. 可以分次玩，通过正常存档、续玩继续。到阶段结束卡就结束本轮，不必追完后续章节。不要为了重开覆盖已有试玩档或正式档。

可选：展开「体验反馈」，选标签并写一句感受，导出本地 JSON；**刷新或离开前先导出，不假定未导出的草稿会保留。**也可以直接口述，由观察 agent 记录。

## 观察 agent：重点看什么

第一轮优先观察玩家自然走完一条路线，不要求穷尽分支。若由 agent 代玩，也要按玩家可见信息决策，不照内部事件表点击。

| 观察项 | 要回答的问题 |
|---|---|
| 目标是否清楚 | 玩家知道现在要做什么、为什么做、去哪里找谁吗？是否只能靠提示按钮猜？ |
| 任务是否承接 | 上一段的结果如何引出下一段？转场、人物相识、行动动机是否有交代？有没有突然换任务或跳地点？ |
| 选择是否有价值 | 选择前能理解大致代价和差异吗？选择后能感到后果吗？是否只是不同文案通向同一结果？ |
| 失败能否继续 | 失败、拒绝或暂不行动后，有可理解的反馈与下一步吗？是否卡死、反复要求同一动作？ |
| 人物与事实是否连续 | 人物是否记得前事、知道不该知道的信息？正文与任务、背包、关系、判定结果是否矛盾？ |
| 节奏与阶段收获 | 有没有连续“听说明—确认—再听说明”？玩家何时开始不耐烦？结束时能否说出自己改变了什么？ |

在自然停顿处，少量问三句即可，不要每回合打断：**“现在想做什么？”“为什么选这个？”“刚才的选择改变了什么？”**先记录玩家自己的理解，再解释。

同时记录实际等待时长、空响应、重复正文、按钮无反馈、存读档丢失或重复结算；把“界面故障”和“故事不好理解”分开。

## 观察 agent：注意边界（含剧情验证细节）

- **不代替玩家理解剧情。** 玩家未求助时不提前讲解正确路线；求助后只给最小提示，并记录哪里需要外部帮助。由人操作时，不擅自替人点击。
- **走真实界面。** 不改存档、完成旗标、命运或骰点，不跳关，不用测试成功按钮，不用脚本直调结算代替游玩。只读查状态可用于事后定位，不能充当玩家已看懂的证据。
- **保护现场。** 不重置已有档、不改源码或 API 配置、不重启共享服务；需要这些动作时先说明并取得授权。等待响应时不要连续发送；重试前记录原状。
- **谢艺只按生存／死亡理解。** 生存内部可表现为长养，不应写成“失踪”。特别留意正文虚构“补心丹已生效”，或把认领护送／调查说成已经完成，把开放资源说成物品已到账。字段正确但正文错误，仍是问题。
- **看故事连续性，不看编号连续性。** 旧 03／05／06 阶段仍隔离，由替代阶段承接；编号跳过本身不算缺剧情，玩家感知到因果缺口才需要记录。
- **结束边界要准确。** 本轮止于星月湖组织支持：长版在 `lcq.stage_07_qingyuan_jiankang` 的 `event.xiao_opens_resources.done` 真实完成后显示结束卡。不要求后续宫变或整章清空。
- 存读档优先用正常界面，在合适停顿处保存、退出再续玩，核对位置、当前任务和已获得物品是否保持。未实际验证就写“未测”。第二条分支另行安排，不覆盖第一轮现场。
- 截图、反馈和日志不带 API 密钥、令牌或无关个人数据。出现存档损坏、串档、不可恢复卡线时停止推进并保留证据；普通叙事问题记录后继续。

## 怎么记、怎么回报

每个问题只记一小条：

> 场景／时间：　玩家操作：  
> 玩家原话或期望：　实际结果（短引文／截图）：  
> 影响：阻断推进／误导选择或结算／体验问题  
> 证据：已观察；原因是推断还是已定位；能否按上述操作复现

结束后只需交付：

1. **实际玩到哪里**：使用入口、是否出现阶段结束卡、是否真实存读档；未走分支明确标“未测”。
2. **最值得修的三项**：各附现场证据、对玩家的影响、一个最小修改建议。区分程序 bug、文案误导、任务设计缺口。
3. **体验判断**：玩家能否说清主目标、记住一次有意义的选择、理解上下段联系，以及最想退出的地方。

当前已有实现和自动化证据，**不代表连续浏览器＋真实模型试玩已通过**；本说明也不是验收结果。相关实现边界见 [长版试玩说明](./LANDING-TO-XINGYUEHU-PLAYTEST-2026-09-21.md)。
