## P3 · 新建，依赖前面的东西

### P1-4　声望没有确定性模型，全凭 LLM 自觉 ⚠ **P3-1 的前置**

用户指出（2026-08-16），已核实：

| 事实 | 证据 |
|---|---|
| 引擎无任何确定性写声望处 | 全仓 `声望` 出现处均为初始化 0（`gameStateStore.ts:393`、`sectSystemFactory.ts:98/159` 等） |
| 声望是 LLM 可写路径 | `commandValidator.ts:34` 列入白名单 |
| 唯一约束是文字指引 | `storyContext.ts` reputationLine：救人除害 +30~300、斩强敌 +100~1000、震动一方 +200~2000 |
| 档位只做展示 | `reputationTier`（籍籍无名 → 传说人物，8 档） |

**给多少全凭模型当场决定。** 这违反项目自己的原则——确定性调度定"发生什么"，LLM 只管"怎么讲"。

**同一仓库里已有正确做法可照抄**：好感有确定性结算——`affinityLadder.ts` ＋
`runtime.ts:2418`「共历事件好感结算」（R3-9 §7），并以 `已结算共历好感的事件` 防重复。
声望应比照：**承重事件完成 → 引擎给确定性增量**，LLM 只负责叙述扬名的过程。

**为什么是 P3-1 的前置**：商队经营层的定义是「别处的地位在此处折现」。
若地位本身由模型随手给出，折现出来的就是模型心情，不是玩家的经营成果。

### P3-1　商队经营层的两样机制

**已核实的现状**（2026-08-16）：

| 项 | 状态 |
|---|---|
| `角色.属性.声望` | 全局单值，可用 |
| 「人望」 | `src/` 中查无此词（应为声望的别称） |
| WorldFaction `声望值 -100~100` | **schema 有、数据没有**——存档 `世界.信息.势力信息` 仅 4 条，0 条带 `声望值`，`可否加入` 全无，`位置`＝「位置未定」 |
| 分地区立足度 | 不存在 |

**结论**：全局声望今天就能挂（粗粒度）；按势力需先填数据；按地区可**从势力位置派生**，不必新开字段。
兑换规则（立足度 → 货源价差／消息灵通度／可引荐对象）仍需设计。
