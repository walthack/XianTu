# R2-11C · 结构化机会推进动作 G1

日期：2026-07-21

## 结论

机会卡已从“追踪后把整段 `actionText` 塞进行动队列”升级为追踪／执行分离。追踪本身不耗时、不推进；当前步骤的推进按钮由本地合同生成，携带 `opportunityId / stepId / actionId / timeCost / contractHash`，不依赖 LLM 生成 `action_options` 或中文关键词。

## 首个纵切

`lyg.event.s01_05` 两条路线已接入：

- 诏令线固定提供入宫、政策选择、公开承担三步；安民／选材／定都分别保存为可重放的 `completionChoices`。
- 入宫线固定提供提交安全依据、协调不拔刀通行次序两步。
- 引擎按钮与 LLM 自由选项并列；自由文本仍沿用旧匹配器作为兼容入口。

成功 AI 回合后才消费结构化动作。旧按钮跨步骤、机会过期、合同热更或同回合重复提交均由本地拒绝；LLM 正文和命令仍不能推进或完成事件。

## G1 证据

- schema/validator 强制动作 id、显示文本、行动文本与当前 `timeCost=1`；
- JSON 重载后具体政策选择仍在存档；
- 旧步骤按钮不能推进新步骤；
- 原 R1/R2 自由文本合同继续兼容；
- `canon:build`、TypeScript 与 R2-11 定向测试通过。
