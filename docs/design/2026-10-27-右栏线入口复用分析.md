> 目标（用户 2026-10-27 08:54／08:56）：给玩家一个「当前这条线下一个目标」的提示。对象是当前在走的国家线或势力线，告诉玩家下一步去哪、做什么。不是把所有能去的线排成一列。这是**提示，不是说明**：只给方向（去哪、找谁、打听什么），不让玩家看了就知道接下来会发生什么。

## 0. 结论速览

1. 能直接复用的是三样东西：主线指南针的「去哪·见谁」指针（`questCompassPhrases`）、跨关读数（`orderedDoneEventIds`、`line.*`、`acq.*`、`identity.*`、`unlock.*` 这些账本路径），以及太泉锁定视图（`secondaryLineEntryView` 的锁定分支）。
2. 旧二级线的**判定**部分要改造。锚要改为读编年史，不能再读本关的 `completedEventIds`。「哪条线接得到」要改成「当前是哪条线、它的下一拍是什么」。旧 `entryHint` 文案**大多不合**新的防剧透口径（见 §4.3），不能原样搬过去。
3. 右栏「可投的门路」这一整块（列表形态）、`questLineView.secondary` 拼进来的那部分，以及主线轴的 `MAIN_QUEST_NODES` 和按 `STAGE_ORDER` 解析层级的做法，都不适合乱序并行，**用作提示时废弃**。代码不删：开关已关，代码留着；`secondaryLines.ts` 还承担 `unlock.*` 和 `lineCriticalFrozen`，见 §1。
4. 推荐方案：右栏主线区加一张「当前线」卡，只写一行下一步（去处＋动作＋人）。别的线只在折叠区列出**线名**，不写提示。太泉没解锁时也只在折叠区出现，标「时机未到」，缺项句沿用已定文案（§5）。
5. 提示数据不新增存档字段，靠一张「线的下一步表」（内容包数据＋texts 键）加现有账本路径求值。切关时能保持，前提是读编年史（§5.3）。

## 3. 已知缺陷

1. **锚只在锚关显示。** `resolveAvailableLines` 读的是 `rt.completedEventIds`（`secondaryLines.ts:938`），可切关时 `createScenarioProgress` 会按新关重建它（`runtime.ts:3137`；`strictInitializer.ts:355` 的注释也写明「completedEventIds 按新关重置」）。跨关携带的只有编年史、相识账、身份账、`questLineState`，以及 `line.*`／期限等 flags（`strictInitializer.ts:404-454`）。结果是：用事件锚的线（10 条全都声明了 `anchorEventIds`）只在锚事件所在那一关亮，下一关就消失。地点锚和人物锚已经被事件锚架空（`:943-945`），救不回来。修法是改读 `orderedDoneEventIds(rt)`，它以编年史为准，再补上本关的完成（`playerLedgerRules.ts:405-432`），`done.*` 也是这个口径。`questLineContext.ts:16` 合并了 `travelLedger.doneEventIds`，同样不读编年史，也有这个问题。
2. **当前目标只认旧单链。** `objective` 只在 `secondaryLinesAtEvent(event.id)` 命中时才出（`sidebarLineEntries.ts:36`、`:52`），也就是只有当前焦点事件恰好是该线节点时才有。离开节点，这条线就只剩一句 `entryHint`，没有「下一步」。
3. **entryHint 带剧透**（逐条见 §4.3）。
4. **太泉标签**是「远征」，不是国家线（`sidebarLineEntries.ts:47`），和 `NATION_LINE_IDS` 的口径不一致。
5. **主线轴层级没人用。** 层和节点的设计还在（`mainQuestAxis.ts:198-436`），但 UI 和 prompt 都不读。现在右栏的主线区只显示焦点事件的指南针，没有「长期方向」那一行。
6. **id 不统一**：zhaonan 和 nanhuang、地区中文名和 lineId 混用（§2、§1-14）。
7. **lineOutcomes 规则表为空**（`player-ledger-rules.json` `lineOutcomes: []`）：在判档事件写进规则表之前，「线已收束」永远读不到，太泉的「还差 X 条」也不会减少。

## 4. 提示文案口径与防剧透规则

### 4.1 口径

- **提示，不是说明。** 只给方向：**去哪、找谁、打听什么**。玩家看了提示，不能知道接下来会发生什么。
- **只写中性的去处＋动作**，不给事件定性，不点名结果。用户原例（08:56）：
  - ✗「去建康打听宫里的怪事」——「怪事」是对事件的定性，等于剧透。
  - ✓「去建康打听宫里最近有什么事」——只有中性的去处和动作，不给事件定性，不点名结果。

### 4.2 防剧透规则（写文案和审稿都按这个）

1. **知情门**：提示只能用主角**当时已知**的信息（`knows.player.*`、`acq.*`、`done.*` 都满足才能提）。主角还不知道的人名、地名、组织名一律不出。这是必要条件，但不是充分条件：已知的东西也要守第 2–4 条。
2. **不定性**：不用评价、归类事件性质的词，例如怪事、闹鬼、阴谋、勾结、猎杀、危机、要打起来了、覆灭、背叛。
3. **不预告**：不写后续会发生什么、会得到什么、还会遇到什么（例如「往下还有织坊、粮仓、钱庄」「江州之后可找某某」）。
4. **不点名结果和动机**：不写谁做成、谁死、谁的真实意图、「其实是为了……」。
5. **句式**：〔去{地点}〕〔找／见{人}〕〔打听／看看／问问{中性对象}〕，最多一句，最好不超过 20 字。中性对象只用「最近有什么事」「那边的情形」「这件事」这类不带判断的说法。
6. **人名和地名**：优先用主角已经知道的称呼（相识账里的名字）。只听说、没见过的人，用「那个人」「他提到的人」这类指代，或者只给地点。
7. **由头不进提示**：入口卡的「由头」槽（乱序方案 §3-1）是写给模型和正文用的，不在提示里展示。
8. **系统缺项句**（如太泉「还差 X 条国家线收束」）属于门槛说明，不是剧情提示，可以出现，但只能放在锁定视图里。

## 5. 推荐复用方案

### 5.1 玩家看到什么

- **右栏主线区**（`RightSidebar.vue:191` 那一块）在现有主线指南针**上方**加一张「当前线」卡，三行以内：
  1. 线名（只在锚已知后显示，比如「晋」）；
  2. **下一步**一句，按 §4 口径，比如「去建康，打听宫里最近有什么事」；
  3. （可选）长期方向一行：主线轴第 2 层文案（王哲托付，主角已知）。
- **当前线怎么定**：焦点事件所在关 → 国家线（§1-14 映射）。如果焦点事件不在任何国家线上（例如自由探索），就取**最近一次推进过的、还没收束的**线（编年史里该线节点最新一条）。都没有，就不显示卡片，只留主线指南针。
- **其他已知的线**：卡片下方一个默认收起的折叠行「别处还有事（N）」，展开后**只列线名**，不写提示。只列锚已知、未收束的线。这样满足「不是把所有能去的线列一排」：默认看不到列表，展开了也没有内容提示。
- **太泉「时机未到」**：不当「当前线」，只放在折叠行里。没解锁时灰显，标题和缺项句直接复用 `secondaryLineEntryView` 的锁定分支（`secondaryLineEntry.ts:48-60`），文案已定（含本次去掉「主角自语：」那条）。解锁以后，它和别的线一样只列线名；玩家走进太泉节点后，它才成为当前线、出下一步。太泉的锚是 s02_01 王哲托付，正常开局都知道，所以它会一直在折叠行里。

### 5.2 「下一步」从哪读

新增一张**线的下一步表**（内容包数据，文案走 texts 键，不进代码；结构可以参照 `SecondaryLineEntryHintKeys` 的「键＋when」附句写法，`secondaryLines.ts:111-122`）：

```
{ lineId, step: [{ id, when: ScenarioCondition[], until: ScenarioCondition[], hintKey }] }
```

- `when`／`until` 只用账本路径：`done.*`（是否已做）、`line.*`（收束了就整线不出）、`acq.*`（重逢或初见换说法）、`identity.*`（身份决定找谁）、`knows.player.*`（知情门）、`unlock.*`（太泉）。按顺序取第一条 `when` 全满足、`until` 不满足的一步。
- **数据源对照**：

| 来源 | 用来做什么 |
|---|---|
| 锚（旧 `anchorEventIds`，改读编年史） | 这条线是否「已知」：未知的线不出现，也不进折叠行 |
| 入口卡（乱序方案 §3-1） | 「出发地／重逢名单／身份」三槽决定**提示里的去处和人**；「由头」槽不进提示（§4.2-7） |
| `lineOutcomes`（`readLineOutcome`） | 有档＝已收束，这条线从卡片和折叠行里撤掉（要不要留「已了结」见 §6-Q6） |
| `lineUnlock`（`lineUnlockStatus`） | 太泉能否成为当前线，折叠行里要不要灰显 |
| 身份账 `identity.*` | 换「找谁」，比如有商号身份时找掌柜，没有时找东家，不改去处 |
| 主线指南针 `questCompassPhrases` | 当前线的下一步正好是焦点事件时，**直接用它的「去X · 见Y」**，表里这一步可以不写 hintKey |

- **校验**：沿用 validator 的账本路径校验（`unlock.*` 只许在 conditions/activation 里用；这张表求值时要传存档，所以 `unlock.*` 在这里能读到。新表的求值入口要像 `runtime.ts` 的 `resolveConditionValue` 那样把 save 传进去，不能走 `evaluateLedgerCondition` 的无存档路径。这一条和 28b28594 收紧变体 when 是同一个原因）。文案缺键时，沿用 `LCQ-PCK-005` 记码，并兜底不出这一步（不要退回带剧透的 entryHint 原文）。

### 5.3 切关能否保持

能保持，前提是**所有判定都读跨关账**：编年史（`orderedDoneEventIds`）、相识账、身份账、`line.*`／期限 flags，这些都已经跨关携带（`strictInitializer.ts:404-454`）。不能读 `rt.completedEventIds`（§3-1）。地点只用来生成「去X」的指针（当前就在X就省掉，同 `eventNarrativeView.ts:212`），不参与判定。不新增存档字段。
