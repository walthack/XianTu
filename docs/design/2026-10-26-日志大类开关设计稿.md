## 4. 调用接口

新文件 `src/modules/diagnostics/debugLog.ts`（只依赖 `./config`、`./redact`、`./debugCategories`，符合 diagnostics 的依赖约束）：

```ts
export type DebugCategory = typeof DEBUG_CATEGORY_IDS[number];
/** 大类是否打开；用来包住代价高的整段调试代码。 */
export function debugEnabled(category: DebugCategory): boolean;
/** 大类打开时打一行 `[dbg:<id>] msg` + 脱敏后的 data；data 可以传函数，关着时不求值。永不抛错。 */
export function debugLog(category: DebugCategory, msg: string, data?: unknown | (() => unknown)): void;
/** consolePatch 登记原始 console.debug（没有就用 console.log），绕开旧的 consoleDebug 隐藏逻辑。 */
export function setDebugConsole(fn: ((...args: unknown[]) => void) | null): void;
```

- **输出**：只走 `setDebugConsole` 登记的原始控制台。没登记时（node 测试、试玩页没加载 consolePatch）退回调用当时的 `console.debug`。consolePatch 改写过的 debug/log 不会把这条记成 SYS-000，所以调试日志**永远不会生成 LCQ-SYS-000**。
- **脱敏**：`data` 过 `redact(data, diagnosticsConfig())`。密钥照 redactKeys / redactPatterns 处理；玩家原文类字段（textKeys）照 `textChars=0` 只保留长度。要看原文，用已有的 `freeAction.debug.playerTextLog` 专用通道，不在 debugLog 里另开口子。
- **不做的事**：不写 logStore、不落盘、不进诊断导出和反馈包、不弹 toast、不去重、不带码、不读 `diagnostics.enabled`。
- **和 `utils/debug.ts` 的关系**：`DebugLogger` 保留下来作旧接口，本稿不改它。等它的 9 个调用方迁完后，再讨论要不要把它变成 `debugLog` 的薄壳（§7）。

### 与错误码 / errorCodeGuard 的关系

| 问题 | 规定 |
|---|---|
| 异常该用哪个 | 要排查、要留痕的 → `logError(码, err)` / `logEvent`（要登记码）。只供开发时观察的 → `debugLog`。两者不能互相替代 |
| catch 守卫 | `debugLog` **不算**已处理：`LOGGING_CALL`（`errorCodeCatchScan.mjs:81`）只认 `log(Error|Event|EventOnce|GateRefusal|Console)`。`debugLog` 这个名字天然匹配不上，也**不要**把它加进去。catch 里只有 debugLog → 守卫照样报 |
| 豁免标记 | 守卫新增的 `// lcq-allow-console: 原因` 和现有的 `lcq-allow:` 互不通用：`ALLOW_MARK` 要求 `lcq-allow` 后面紧跟冒号，`lcq-allow-console:` 匹配不上 |
| 码字面量 | `debugLog` 的参数里不许写 LCQ- 码（免得让人以为带码的事件也受大类开关控制）；源码里码字面量要登记的规则照旧 |
| 始终开启 | `log.ts` 和 `codes.ts` 一行不改；测试锁定“大类全关 → logError 照样进 store、落盘、打控制台”“大类全开 → logEvent 条目和级别线不变” |

## 6. 旧代码迁移策略（不必一次迁完）

- **新代码**：从 T1 合入起，一律用 `debugLog` 或 `logEvent`，守卫拦住新增的裸 console。
- **存量**：靠棘轮慢慢收紧。按大类分批迁，每批一个提交，提交里同时收紧 consoleGuard 基线。推荐顺序（量大、零风险的在前）：`init`（CharacterCreation 28 处 + characterCreationStore 67 处）→ `save`（indexedDBManager 40 处、characterStore、gameStateStore）→ `ai`（aiService 83 处、tavern）→ `ui`（dashboard 237 处）→ 其余。顺手改到某个文件时可以迁，但**不强制**，免得别的任务范围膨胀。
- **改写规则**：

| 原写法 | 改成 |
|---|---|
| 不在 catch 里的 `console.log / info / debug / table / group` | `debugLog(大类, msg, () => data)` |
| 不在 catch 里的 `console.warn / error` | 确实是异常 → 登记新码，然后 `logEvent`；只是观察 → `debugLog` |
| catch 里的 `console.*` | 只能改成 `logError(码, err)` 或补 `// lcq-allow: 原因`。**不能改成 debugLog**：catch 指纹会变，errorCodeGuard 会把它当成新增未处理的 catch 报错 |
| `DebugLogger.log(component, …)` / `debug.log` | `debugLog(大类, …)`，component 并进 msg 前缀 |
| 单功能开关（`dad_debug_tavern`、`?debug`） | 改读 `debugEnabled(大类)`，删掉原开关 |

- **旧开关去留**：设置面板的 `debugMode / consoleDebug` 继续管**还没迁的**裸 console（consolePatch 不动）；全部迁完以后再议要不要下线。`performanceMonitor` 以后并进 `perf`。`freeAction.debug.*` 本次保留（见 §10）。
- 迁移中被消掉的 errorCodeGuard 基线条目，可以用 `UPDATE_ERROR_CODE_BASELINE=1` 收紧，diff 同样只许减少。
