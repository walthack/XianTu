## 2. 数据结构

### 2.1 存档（新文件 `src/modules/scenarioMods/identityLedger.ts`）

```ts
export type PlayerIdentityStatus = 'active' | 'revoked';

/** 一次账目操作。history 是幂等依据：同一 (eventId, op) 只记一次。 */
export interface PlayerIdentityOp {
  eventId: string;
  op: 'grant' | 'reinforce' | 'revoke';
  atStageId?: string;
  atWorldTurn?: number;
  backfilled?: boolean;
}

export interface PlayerIdentityRecord {
  identityId: string;              // 与外层键相同，冗余存一份，便于迁移时校验
  status: PlayerIdentityStatus;    // 由 history 最后一条 grant/revoke 决定，存下来便于直接读
  acquiredAtEventId: string;       // 先到先得：第一次 grant 的事件，之后永不改写
  history: PlayerIdentityOp[];     // 只追加
  backfilled?: boolean;            // 首条记录来自旧档回填（照相识账本写法）
}

/** 存档位置：世界.状态.剧本模组.playerIdentities；键＝identityId */
export type PlayerIdentityLedger = Record<string, PlayerIdentityRecord>;
```

- **kind、所属国/势力、展示名不进存档**，只放在配置里的身份定义（2.2），按 id 查。理由：这些都是身份的静态属性，存两份会走样（方案二「展示名放在配置里」的同一原则）。
- 类型不加进 `RuntimeState`（那在冻结的 runtime.ts 里），读写处用局部类型收窄，照 `updateAcquaintanceLedger` 的写法（`runtime.ts:3447`）。`acquaintances` 字段目前也是这样处理的。

### 2.2 身份定义（配置，id 总表）

新文件 `mod-kit/entity-catalog/identities.json`，形状同 `factions.json / endings.json`：

```ts
export interface PlayerIdentityDef {
  id: string;          // liuchao.identity.<域>.<名>，如 liuchao.identity.song.baochao_zhushi
  name: string;        // 展示名，只在这里
  kind: string;        // 取值必须在 story.identity.kinds 里（office/title/merchant/sect…）

  factionId?: string;  // 所属势力 id（entity-catalog/factions.json）
```

## 3. 写入点

### 3.1 规则表（新文件 `mod-kit/player-ledger-rules.json`）

```ts
interface IdentityGrantRule {
  eventId: string;
  identityId: string;
  /** 本身份已经 active 时怎么办。缺省 'reinforce' */
  whenHeld?: 'reinforce' | 'redirect';
  /** whenHeld='redirect' 时改授的身份（如「分号」） */
  redirectIdentityId?: string;
}
interface IdentityRevokeRule { eventId: string; identityId: string; }
interface LineOutcomeRule { eventId: string; lineId: string; outcome: string; } // outcome ∈ story.lineOutcome.tiers

interface PlayerLedgerRules {
  version: 1;
  identityGrants: IdentityGrantRule[];
  identityRevokes: IdentityRevokeRule[];
  lineOutcomes: LineOutcomeRule[];
}
```

首版的 `identityGrants / lineOutcomes` **留空数组**，具体身份和收束事件等总策划给清单再填。样例只写进测试夹具。

### 3.2 同步函数（幂等）

```ts
// identityLedger.ts
grantPlayerIdentity(ledger, { identityId, eventId, stageId?, worldTurn?, backfilled? }): 'granted' | 'reinforced' | 'reactivated' | 'noop'
revokePlayerIdentity(ledger, { identityId, eventId, ... }): boolean
isIdentityActive(ledger, identityId): boolean
applyIdentityRules(ledger, orderedDoneEventIds: string[], rules, ctx): number   // 纯函数，返回改动条数

// lineOutcomes.ts
syncLineOutcomes(runtime, opts?): number   // 写 runtime.flags['line.<lineId>.outcome']
lineOutcomeTiers(): readonly string[]      // 读 GAME_NUMBERS.story.lineOutcome.tiers
```

处理顺序：按完成顺序逐个事件处理（`orderedCompletedEvents`，§4.2）。同一个事件先执行撤销，再执行授予。配置里同一个 (eventId, identityId) 不能同时出现在授予和撤销里，校验会拒绝。

### 3.3 先到先得与冲突

| 情况 | 处理 |
|---|---|
| 没有记录 | 新建记录：`status=active`，`acquiredAtEventId=eventId`，history 记一条 grant |
| 已 active，`whenHeld='reinforce'` | 不重复授予。history 追加 `reinforce`，**`acquiredAtEventId` 不变**。变体用 `identity.<id>.from` 判断来源，用 `done.<后到事件>` 写「注资／加固」 |
| 已 active，`whenHeld='redirect'` | 原身份不动，改授 `redirectIdentityId`（如晋地分号），按「没有记录」处理 |
| 已 revoked，又被授予 | `status` 改回 active，history 追加 grant；`acquiredAtEventId` 不变 |
| 撤销 | `status=revoked`，history 追加 revoke。**记录保留**，供变体读取「曾持有」 |
| 幂等 | 任一记录的 history 里已有 (eventId, op) 就跳过。redirect 规则要同时检查原身份和改授身份的 history |
| 收束档 | `line.<lineId>.outcome` 已有值时不覆盖（`story.lineOutcome.writeOnce=true`），记一条 console.warn。值不在 tiers 里时拒写并 warn |
