## 4. Grok 并行任务（三项，均不碰运行时）

> 调用方式见 memory `grok-build-cli-invocation`：审计类用 agent 模式
> `--permission-mode plan --reasoning-effort medium`，**不要用 low**（实测会 placeholder 凑数）。

### 任务 A：148 种 `relation` → 12 主类映射表（对应 §4）

- **输入**：`src/modules/scenarioMods/builtins/data/*.json` 里所有 `playerRelationships[].relation`（31 个文件、约 400 条、148 个不同取值）
- **受控主类**：`陌生 相识 同僚 盟友 主从 师徒 血亲 恩义 情侣 道侣 敌对 仇雠`
- **产出**：`docs/R3-9-RELATION-VOCAB-MAP.md`，每行 `原值 → 主类 ｜ 保留的自由修饰 ｜ 置信度`
- **要求**：原始字符串的质感不能丢（`真正臣服的母狗侍奴` → 主类 `主从` + 原文入 note）；**噪声条目单独列一节**（如 `无直接关系（根据证据，窥基与程宗扬无直接关系记载）`）
- **不做**：不改任何 JSON，不建代码模块

### 任务 B：关卡初始好感标定方案（对应 §6）

- **输入**：同上的 `playerRelationships[].favorability`（32 种散值：-90/-80/-70/-60/-55/-50/-45/-40/-30/-20/-10/-5/0/5/10/15/20/25/30/35/40/42/45/48/50/55/60/65/70/75/80/90）
- **标定规则**（规格 §6.1，按关系来源推导）：素未谋面 0｜同场无交情 5–15｜一次正面交集 20–30｜共过患难 40–55｜长期同盟 60–75｜生死与共 80–90｜立场对立未结怨 -10~-20｜结过怨 -25~-50｜血仇 -60~-90
- **产出**：`docs/R3-9-FAVORABILITY-CALIBRATION.md`，逐条给 `现值 → 建议值 ｜ 依据（该角色与主角在此关的关系来源）｜ 是否跨档`
- **要求**：**每档只用区间中值与两个端值三个数**，消灭 42/48 这类无意义精度；跨档的（如 60→39）单独列出待人工复核
- **不做**：不改 JSON

### 任务 C：可获得角色的征兆覆盖盘点

- **背景**：玩家要通过传闻/征兆找到错过的 NPC，但征兆挂在承重事件上，未必覆盖每个可获得角色的登场事件
- **输入**：`stanceProfiles.ts` 的 45 人名单 ＋ registry 的 `joining` 字段 ＋ 各 stage 的 `situation.omen`
- **产出**：`docs/R3-9-OMEN-COVERAGE-AUDIT.md`：每个可获得角色 → 其登场/加入事件 → 该事件所在 stage 有无征兆 → 缺口清单
- **不做**：不写新征兆（那是内容生成，Grok 实测不稳），只出盘点
