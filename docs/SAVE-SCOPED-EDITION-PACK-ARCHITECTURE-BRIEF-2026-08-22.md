## 结论候选

当前优先候选是：**制作期生成并审核演出变体库，新档用 seed 确定性绑定 `slotId → contentId`，同一存档持久化选择与揭示／消费回执；每回合先由本地引擎结算事实，再用固定骨架或一次短 LLM 调用渲染。**

它不是“开局随机生成另一个六朝世界”，也不是预写未来多回合剧本。人物性格、初始设定、核心动机、知识边界、正典故事线、事件锚点、关键结果、地点／物品／完成合同继续冻结；差异只来自合法环境牌、传闻顺序、连接性演出、过程纹理和已有合同支持的局部后果。

## 问题与目标

- 当前主回合可能串行执行长 prompt、800–1000 字正文、结构化指令、门禁重写和可选润色；换 Flash 仍受长输入、长输出与多次调用拖累。
- 希望不同新档具有可辨认但正典安全的体验差异；同一存档读档后不得换人物、洗牌、复活已消费内容或泄露未获知事实。
- 自由输入必须保留，但 LLM 只可发明质感和接话，不可发明去处、任务、物品、人物真知、事件完成或世界结果。

## 三种方案

| 方案 | 判断 | 原因 |
|---|---|---|
| A. 制作期预生成／审核变体库，新档 seed 组合 | **首选** | 开局可 0 LLM；可在构建期审正典与知识边界；读档与崩溃一致性可由纯函数和回执保证 |
| B. 新档时由 LLM 生成存档专属内容包 | 暂不采用主路径 | 增加开局等待；运行时内容无法预审；失败重试、版本升级和未来文本失效协议复杂 |
| C. 固定库＋新档少量生成＋游玩后台补写 | 只保留窄义惰性绑定 | 允许用原 seed 在首次进入地点时绑定库内 `contentId`；不允许后台 LLM 预写下一拍／下一地点全文 |

Grok 4.6 的独立只读意见明确选择 A，并建议把 B 仅作为离线制作工具：模型生成候选，审核通过后才进入 A 的库。Codex 综合判断与此一致；Claude 独立复核后给出 `GO-WITH-CHANGES`，要求按可逆阶段推进，并把现有取消路径部分提交风险作为独立 P0 工作包处理。

## 冻结层与可变层

| 冻结层 | 可变层 |
|---|---|
| 人物性格、设定、动机、声线底线、保护字段 | 同一性格内的动作、措辞和场面调度 |
| 人物私知、玩家知识权限、rumor／confirmed 分账 | 合法信息的揭示顺序和来源表现 |
| 三级任务、Canon Rail、事件 ID、锚点与关键结果 | 固定锚点之间的环境牌、连接骨架和过程纹理 |
| zone／route、物品 catalog、transferId、完成合同 | 已审核传闻牌、环境牌、机缘模板的抽取顺序 |
| 本地判定、移动、奖励、关系与世界账本 | 本地已结算事实的一次短叙事渲染 |

**反假选择规则：** 没有合同差、信息差、成本差或延迟后果差的变体，不进入选择 UI，只能作为表现纹理。纯换天气、形容词或对白措辞不能单独算“新档不同”。

## 数据合同候选

权威选择应挂在 `世界.状态.剧本模组` 运行态，而不是可重建的 `系统.缓存`。最小结构：

```text
editionPack
  version
  seed                    # 建档后只读
  generatorVersion
  sourceModVersion
  slots[]
    slotId
    contentId             # 永久对应同一 payload；修文用新 ID
    poolId
    inputHash             # seed + slot + 版本 + eligible IDs
    contentHash           # 检测库漂移
    status                # selected/revealed/consumed/invalidated/substituted
    revealedAtTurn?
    consumedAtTurn?
  receipts[]
    receiptId
    inputHash
    phase                 # pending/committed/failed
```

一致性要求：

1. 读档只恢复已存 `contentId` 与状态，不重跑抽取。
2. 新增槽位可用原 seed 惰性绑定；不得改变已有槽位。
3. 库项缺失时只替换／作废该槽并写回执，不牵连全档洗牌。
4. 崩溃重试复用同一 `inputHash` 与 pending receipt，不换随机盐。
5. 未 `revealed` 的 payload 不得进入 UI、`createScenarioPromptState` 或 `buildScenarioStoryPrompt`。
6. 如果未来允许 LLM 在运行时生成，必须保存完整输出；seed 不能保证 LLM 可复现。首版不建议开放。

## 热路径候选

```text
玩家输入
→ 本地分类与风险预检
→ 建立可恢复快照／pending receipt
→ 本地实际落账
→ 编译短 RenderPacket
→ 固定骨架，或一次 120–280 字短 LLM 渲染（硬上限候选 400）
→ 门禁失败使用本地安全骨架，不再整篇重写
```

现行事件／五原动作在发给模型前已解析为“预结算”，但实际 `settleWuyuanOpenWorldSelection`／`recordStoryEventStructuredAction` 仍在 `processGmResponse` 阶段写账。候选架构要求 Claude 特别评估：是否及如何把**实际落账**安全提前到模型调用之前，同时保持重试、取消、回滚和存档兼容。

延迟优化必须与演出版同时评估，否则只是把等待挪位置：停用主回合分步第 2 步、默认关闭润色、缩短正文、减少整份存档／百科式 prompt、门禁失败走骨架回退。以上均是提案，不是当前批准改动。
