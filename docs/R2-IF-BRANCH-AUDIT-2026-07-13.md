## 发现

1. 谢艺、小紫、苏妲己伏诛与燕歌英逝双枢纽现在拥有 `fork.eventId` 与 `runtimeActivation` 的双合同；小紫只在碧姬被对账为生还/长养/失能时激活，苏妲己只在 `dead` 时激活；郭解/董卓只在生还、长养或失能时激活。英逝后郭解必须受限辅政，董卓不得回京争权、贾文和必须收束凉州旧部；定陶王登基照常。
2. 其余 10 条目前没有完整的运行时触发—可见余波链，因此仍是正典设计稿或待补余波的资产，不是当前可验收内容。
3. 多条写的是“长养离场”或“代价换人”，但没有至少一条后续人物行动、任务、势力或地图变化；这类分支即便触发，玩家也感觉不到选择的重量。
4. 两条死亡结局证明 schema 能表达 terminus，但目前没有独立的结局展示/存档收束流程，不能当作可交付玩法。

## R2 重整规则

- 自动触发必须同时具备：`fork.eventId`、来源为对账事实、可解析的角色/世界状态谓词、后续至少一个可见余波合同。
- 没有当前 stage/event 的分支只能标 `future_stage`，不计入可玩分支数量。
- 单纯“某人还活着但继续退场”默认由分歧账本承接；只有后续有真实重返/报恩/追债/势力变化时才升级为 IF。
- 新增分支不按书均分或凑到固定数目；优先补四类缺口：玩家等价完成、救援/死亡逆转、重大反派提前出局、玩家缺席造成的世界级后果。
