# R2-10H 跨书异构扩量 G1

日期：2026-07-20  
范围：清羽、云龙各一个承重事件，复用 R2-10B–G 的同一确定性内核。

## 结论

世界/NPC 引擎已不再只存在于燕歌 `s01_05–08`。首批跨书样本落在：

- 清羽 `lcq.event.s10_04_left_army_review`：势力级、无硬截止的 `emergent` 军机复盘；
- 云龙 `lyl.event.s05_09`：本地级、5 回合窗口的押运遇劫。

两者共用同一 NPCState、行动库、局势白名单、分层唤醒、机会生命周期、长期记忆和回执协议，但使用不同时间结构、局势键、行动组合和场外边界。

## 清羽样本

孟非卿按星月湖势力 cadence 唤醒，小紫按当前在场/受影响关系唤醒。两人分别从公开复盘与暗查接触链推进：

- 局势：`supplyContinuity/leakRisk`；
- 不变量：左武军已经覆灭，江州大战压力继续；
- 禁止提前坐实：泄密真凶、江州战争胜负；
- 机会：由资源复盘/暗查行动触发“补上江州军机断点”；
- 时间：`emergent`，玩家不介入不会仅因等待而自动完成。

## 云龙样本

云苍峰按云氏势力 cadence 调度资产与联络，云丹琉作为本地关键人物处理护送和反击：

- 局势：`cargoSecurity/escortPressure`；
- 不变量：押运遇劫且损失惨重、云丹琉与程宗扬组织反击；
- 禁止改写：全部金铢无损追回、杀手网络被彻底肃清；
- 机会：由收拢资产/护住押运队行动触发“接住伊水押运余部”；
- 时间：`window`，资格后第 5 回合按原轴“损失惨重”场外结算，不伪记玩家完成或授权。

## 自动验收

`tests/r2_10h_cross_book_scale.test.mjs` 覆盖：

1. 两书 core 经过真实 `JSON.stringify/parse` 往返后逐字节重放；
2. 两书生产 runtime 连续三轮 JSON 往返，整份存档字节串与决策哈希均一致；
3. 两种局势白名单、行动组合和 wake audit 独立；
4. 机会从本地决定触发，不依赖 LLM；
5. 清羽 emergent 等待 8 回合仍不被强制结算且零权限；
6. 云龙 window 到期只落 offscreen 状态、回执和时间线，零权限；
7. 两份 Mod schema 全绿，prompt 保留各自未来禁区。

命令：`npm run test:g1:npc`。

统一二审曾指出旧测试只用 `structuredClone + deepEqual`，不足以支持“JSON 重载后逐字节重放”的报告措辞；上述第 1、2、5 项是修复后的真实证据。收口详情见 `docs/R2-10I-SECOND-REVIEW-CLOSURE-2026-07-20.md`。

## 扩量边界

本提交证明“同一内核可跨书、跨事件结构复用”，不是把 37 关全部改为重模拟。后续扩量继续遵守：

- 每次只选有原轴证据、人物在场和明确不变量的承重事件；
- 先 G1 确定性数据，再进入 G2 模型演出；
- 未经逐拍复核的隔离关不因引擎扩量自动回接 Canon Rail；
- 共享服、外测与总项翻绿仍受现有 G2/发布门禁约束。
