# 可替换模型的模块框架

用户要求：功能模块独立，模型可以更换；不固定品牌或强制三种不同模型。此次只完善已有模块链路的调用框架，不扩大剧情迁移范围。

## 固定什么，配置什么

固定模块的输入输出合同、结算权限、执行依赖；配置API连接、供应商、模型名称、功能分配和输出预算。供应商协议由现有AIService适配，模型输出由模块验证器检查。切换支持的供应商／模型配置无需修改业务代码；不同模型是否能满足同一输出合同、速度和质量仍须实测。

- `moduleModelRuntime.ts`：通用模块定义与执行器，依赖注入API解析／功能开关／传输，不包含品牌或模型名称判断。
- `gameModelModules.ts`：对接现有API管理配置，将逻辑模块映射到既有功能类型。
- AIService：接收本次API配置快照，仍统一处理协议、取消、截止、重试和输出截断；在途请求及其重试不会因为设置变更而偷偷换模型。
- 调度和验证：仍由已有回合事务控制；`dependencies`记录模块依赖，执行器本身不会自动执行任意DAG。正文提交后才运行后台模块。
- 回执：记录configId／provider／model，无API key；HUD和导出记录可查看实际路由。品牌特有的思考标签改为通用命名空间标签清理。

| 模块 | 现有API功能配置 | 执行时机 |
|---|---|---|
| narrative（演出） | main／主流程API | 本地预结算之后，前台 |
| memory（摘要） | memory_summary／记忆总结 | 正文提交后，后台 |
| quality（检查） | text_optimization／文本优化 | 正文提交后，后台 |

当前这三种实测模型仅是配置样本。所有模块可以共用一个配置，也可以分配不同连接／不同模型。新增模块在注册表中声明其功能类型、请求预算与依赖，复用同一执行器；不需增加模型名称分支。

## 如何换模型

在游戏「API管理」中建立或编辑连接，填写该服务支持的模型ID，再在功能分配中选择：主流程、记忆总结、文本优化。修改分配后新任务即使用新配置；已经启动的任务继续使用启动时的配置。后台恢复／重试会作为新任务读取最新分配。

原功能开关继续生效，关闭文本优化不会为了凑三个模型强制调用。原API管理失效分配回退默认的兼容行为保留；执行器要求最终解析出的配置启用且模型／URL非空。未自动修改用户API、模型分配、正式存档或已有存储结构。

## 验证

框架单测覆盖：三个模块共用同一模型；各自切换不同供应商和任意模型名称；请求启动后修改配置不会影响快照；新任务读取新配置；关闭／未配置／未知模块不发请求；读取连接预算；新增模块注册；失败保留原错误类型和不含密钥的模型信息。

受控浏览器在隔离档中将main从fixture模型切换到alternate-narrator，同一输入输出合同仍可生成、结算、保存、恢复；辅助任务失败／迟到／关闭功能仍隔离。该证明是框架和路由兼容验证，不代替所有模型的真实能力与性能验证。

## API设置入口与模块策划交接（2026-10-01）

API管理 → 功能分配 → 回合模块模型，集中配置「剧情演出」「回合记忆」「质量检查」。先在同页API配置列表新增／编辑连接和模型，再在模块下拉框选择；修改自动保存，可共用同一配置。两个后台模块有启用开关，切换模型不会自动启用检查。新配置用于后续任务，在途任务仍使用启动时的配置。

这三个入口共享原有 main／memory_summary／text_optimization 的分配与开关，因此原功能也同步变化；当前并非每种剧情动作都走模块链路，覆盖范围仍遵循隔离试玩说明。酒馆环境保留主流程设置锁定。运行时职责、输入输出合同与唯一结算入口保持不变。

用户计划在本轮交付后交模块策划继续打磨，本线程不代发任务。建议按同一策划轮次记录：

- 系统策划：明确每个模块的必需输入、输出验收、依赖和失败处理；按现有三模块纵切逐步扩大覆盖，验证切换模型、切档、刷新和迟到隔离。
- 剧情／事件策划：打磨场景材料、步骤承接、人物知情和关系边界；检查建议保留证据，引入新模型时先验证正文及摘要合同。
- 联合验收：复用真机矩阵，记录至少20真实回合，区分模块链路与原链路、前台耗时与后台完成时间；每轮共同更新 PLANNING-ROUNDS.md 的交付、证据、未测项和跨组依赖。

策划可调整模块材料和预算，但不能绕过确定性结算、正典保护、输出验证或版本隔离。新增模块先定义合同和依赖，再登记到统一模块表；无需新增品牌分支。

入口验证：8091／18097受控浏览器的三模块模型选择、未启用配置保护、原设置同步、后台开关和刷新恢复通过；类型、单页构建、37关及1119测试（1114通过／5跳过／0失败）、diffcheck通过。均为隔离配置与受控界面验证，本轮无真实模型调用。
