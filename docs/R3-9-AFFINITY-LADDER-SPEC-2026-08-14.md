## 1. 问题定义：不是"缺功能"，是"缺语义"

好感数值早已存在且到处在用，但没有任何一层定义过它"是什么意思"。以下四条为**当前代码实测**（非推测）：

**1.1 玩家好感没有分档语义。** `社交.关系.<NPC>.好感度` 是裸 `number[-100,100]`，缺失补 0（[`dataValidation.ts:125`](../src/utils/dataValidation.ts)、[`dataRepair.ts:561`](../src/utils/dataRepair.ts)）。提示词里那套五档表（深仇/敌对/中立/友好/至交）是给 **NPC↔NPC 的 `关系矩阵.edges.score`** 写的，与玩家好感无关（[`npcRelationRules.ts:13`](../src/utils/prompts/definitions/npcRelationRules.ts)）。

**1.2 四套阈值各写各的，无单一真值源。**

| 位置 | 阈值 | 用途 |
|---|---|---|
| [`intimacyProfiles.ts:24`](../src/modules/scenarioMods/intimacyProfiles.ts) | 20 / 55 / 80 | 亲密档案 revealTiers |
| [`storyContext.ts:412`](../src/modules/scenarioMods/storyContext.ts) | ≥30 | 人格底线是否喂给 LLM |
| [`storyContext.ts:879`](../src/modules/scenarioMods/storyContext.ts) | ≥20 / ≤0 | 关系-好感失配检测 |
| [`CharacterDetailsPanel.vue:771`](../src/components/dashboard/CharacterDetailsPanel.vue) | ≥60 / ≥20 / ≤-20 | UI 三色显示 |

四处对"高好感从哪开始"的答案分别是 55、30、20、60。

**1.3 `与玩家关系` 标签是自由文本，且从不随好感演进。** 58 个关卡 JSON 里 31 个带 `playerRelationships`，共 **148 种不同的 `relation` 取值**——从 `朋友`、`君臣`、`主从` 到 `真正臣服的母狗侍奴`、`囚徒·摇摆抗拒·屡试逃脱`，以及明显的生成噪声 `无直接关系（根据证据，窥基与程宗扬无直接关系记载）`。代码注释已记录实测事故：标签"敌对"却好感 35 且主动双修（[`storyContext.ts:868`](../src/modules/scenarioMods/storyContext.ts)），现有对策只是检出后交 LLM"剧情内收敛"。

**1.4 关卡侧数值无标定。** `favorability` 散布 -90~90，峰值 5（91 次），其次 80(51)/60(43)/10(38)/50(36)/30(35)/25(33)。因为没有档位定义，"5 与 10 的区别""60 与 80 的区别"目前不承载任何设计意图，是生成时的随机落点。

**结论**：本次细化的产物不是新系统，而是**给已在跑的数值补一套单一真值源的语义**，并把四处散落阈值收编过来。

## 2. 三条设计原则

1. **好感只改变"人物如何对待玩家"，不改变"人物是谁"。**（沿用 R3-9 已批准口径）角色画像、阶段人格、动机锚、知识门禁、正典边界不可被好感改写。高好感 ≠ 无条件服从与泛用温柔化；低好感 ≠ 失去智性与泛用恶女化。
2. **单一真值源。** 阶梯定义只允许存在一份（§3 常量），现有四处阈值全部改为引用它。任何新门禁不得再自带魔数。
3. **分辨率分层。** 数据标定与解锁用 **7 档阶梯**（够细，能承载 148 种关系的差异）；表现层投影为 **3 档姿态**（够粗，LLM 才渲染得稳，也是 R3-9 要求的 A/B/C 对照）。两者是投影关系，不是两套系统。

## 3. L1：好感阶梯（地基）· 待拍板

### 3.1 七档定义

| 档位 | 区间 | 一句话语义 | 玩家侧体感 |
|---|---|---|---|
| **仇雠** | -100 ~ -60 | 已认定必须除掉你 | 见面即冲突，不接受交涉 |
| **敌意** | -59 ~ -25 | 视你为对手，可谈但每句都在算计 | 交涉需筹码，情报只出不进 |
| **戒备** | -24 ~ -10 | 不信任，保持距离 | 场面话，拒绝任何实质请求 |
| **陌路** | -9 ~ 19 | 无所谓，按公事公办 | 默认起点，谈的是事不是人 |
| **相识** | 20 ~ 39 | 认得你，愿意搭话 | 小忙可托，尚不涉利害 |
| **信重** | 40 ~ 59 | 把你算进自己的盘子里 | 愿透底、愿担有限风险 |
| **亲厚** | 60 ~ 79 | 关系本身有分量 | 主动照拂，肯为你破例 |
| **生死** | 80 ~ 100 | 你在她/他的底线之内 | 逆势相随，代价自负 |

> ✅ **待定项 A 已定（2026-08-14 用户裁定）：采用 8 档**，不合并「仇雠+敌意」。理由＝负向侧实测有 -90/-80/-70/-60/-50 五个值在用，压成一档会丢分辨率。上表即最终档位表。

### 3.2 三档姿态投影（R3-9 表现层消费）

| 姿态 | 覆盖档位 | 好感区间 |
|---|---|---|
| **低（疏离/敌对）** | 仇雠·敌意·戒备 | ≤ -10 |
| **中（常态）** | 陌路·相识 | -9 ~ 39 |
| **高（亲近）** | 信重·亲厚·生死 | ≥ 40 |

### 3.3 滞回（防"1 点翻脸"，路线图明确要求）

跨档需**同时**满足：越过阈值 **≥3 点**，且新档位维持 **≥1 个游戏日**。否则姿态保持原档。实现为纯函数 `projectStance(fav, lastStance, lastChangeAt)`，边界稳定策略随之落地。

### 3.4 变化速率约束

| 约束 | 值 | 理由 |
|---|---|---|
| 单回合净变化上限 | ±15 | 现有提示词的"好事+5~+20"上沿偏高，一次对话就能跨档 |
| 单次重大事件上限 | ±40 | 保留"救命/背叛"的冲击力，但不足以一步登天 |
| 触犯人格底线 | -30 ~ -60，且强制降至 ≤ 戒备 | UI 已如此宣称（[`RelationshipNetworkPanel.vue:357`](../src/components/dashboard/RelationshipNetworkPanel.vue)）却无代码执法，本次补上 |
| 时间衰减 | **不做** | ✅ 待定项 B 已定（2026-08-14 用户裁定）：好感不因时间流逝无声流失 |

#### 3.4.1 事件驱动降档（替代时间衰减，用户 2026-08-14 补充口径）

用户裁定不做时间衰减，但**保留"因某些重大事件而降低"**。两者的区别是本节存在的理由：时间衰减是无声流失，玩家察觉不到也无从应对；事件驱动降档有明确因果，玩家能理解"我做了什么导致她冷下来"，这才是关系系统该有的反馈。

因此降档一律**挂事件、不挂时钟**，且全部走 §7 的确定性引擎裁定（不交 LLM 自由裁量）：

| 触发事件 | 降幅 | 附加效果 |
|---|---|---|
| 触犯该角色人格底线 | -30 ~ -60 | 强制降至 ≤ 戒备（见上表） |
| 背叛／出卖（泄其机密、将其交予敌手） | -40 ~ -60 | 强制降至 ≤ 敌意；写入 NPC 长期记忆 |
| 见死不救（其明确求援而玩家拒绝且造成实损） | -25 ~ -40 | 记忆留痕，后续求援门槛提高 |
| 立场背离（玩家投入其敌对势力） | -20 ~ -35 | 与 §3.5 cap 联动，可同时压低天花板 |
| 违背明确承诺 | -15 ~ -25 | 重复违背时逐次加重 |
| 当众折辱其身份／尊严 | -15 ~ -30 | 权力位角色（如吕雉）取上沿 |

三条纪律：**①** 每条都须能在正文中找到对应事实，不得凭氛围扣分；**②** 单次仍受 §3.4 的 ±40 重大事件上限约束（底线触犯是唯一例外，可达 -60）；**③** 降档同样走 §3.3 滞回，避免一次事件后反复横跳。

> 具体事件到清单的映射由实现阶段按关卡数据补全；上表是分类与幅度基准，不是穷举。

### 3.5 上限 cap（人物立场决定天花板）

某些角色在特定阶段**不可能**到高档。cap 写在角色正典档案，由校验器执法，LLM 越不过。示例：吕雉在其未确认玩家可用于飞羽族存续之前，cap = 相识(39)。**待定项 C：首批 cap 名单**，建议只给六朝主线中"立场先于情感"的十余人设，不铺全库。

### 3.6 现有四处阈值的迁移

| 现值 | 迁移后 | 说明 |
|---|---|---|
| intimacy `shallow: 20` | = 相识入口 20 | 不变 |
| intimacy `deep: 55` | → **60（亲厚）** ✅ 待定项 E 已定（2026-08-14 用户裁定） | 55 卡在信重中间无依据，改对齐亲厚入口。**注意这是行为变更**：`TIER_FAVOR.deep` 解锁点从 55 抬到 60，好感落在 55–59 的存档将不再显示 deep 层。**实测影响面＝16 名档案角色中的 11 名**（潘金莲／凝羽／乐明珠／云如瑶／小紫／月霜／云丹琉／赵飞燕／阮香凝／吕雉／申婉盈），仅这一窄区间受影响，60 以上与 55 以下行为不变 |
| intimacy `bonded: 80` | = 生死入口 80 | 不变 |
| 底线门控 `≥30` | → **40（信重）** | "把你算进自己盘子"才透底线，语义更顺 |
| 失配检测 `≥20 / ≤0` | → 姿态高(≥40) / 姿态低(≤-10) | 改用姿态档，与标签词表联动（§4） |
| UI `≥60 / ≥20 / ≤-20` | → 按 8 档全部上色 | UI 是玩家唯一能看到阶梯的地方，应显示档位名而非裸数字 |

## 4. L2：`与玩家关系` 受控词表 · 待拍板

> **范围边界（路线图约束）**：R3-9 G1 明令"优先沿用现有好感值与 `与玩家关系`／记忆，**不为首版擅自扩 schema**"。本节的 `relationNote` 新字段与主类词表因此**不进 R3-9 G1 首版**，归入 R3 项 5「细粒度打磨」的数据层工作，按 §8 顺序单独走。R3-9 G1 只消费**既有**的 `与玩家关系` 字符串。

148 种自由字符串是 §1.3 失配事故的根因。方案：**标签 = 受控主类 + 自由修饰**。

### 4.1 受控主类（12 类，覆盖实测 148 值）

`陌生` `相识` `同僚` `盟友` `主从` `师徒` `血亲` `恩义` `情侣` `道侣` `敌对` `仇雠`

### 4.2 与档位的合法域

每个主类声明允许的好感区间，校验器检测越界并要求收敛：

| 主类 | 合法区间 | 越界处置 |
|---|---|---|
| 敌对 / 仇雠 | ≤ 19 | 好感升入相识以上 → 强制 LLM 演进标签（如 `敌对`→`亦敌亦友`） |
| 情侣 / 道侣 | ≥ 40 | 好感跌破 → 演进为 `情侣·离心` 或降级 |
| 主从 | 全域 | 主从可以是恨着的服从，不设限 |
| 其余 | 全域 | — |

这把现在"检出后交 LLM 自由收敛"升级为"确定性检出 + 受限收敛目标"。

### 4.3 迁移

148 值 → 12 主类的映射表由脚本生成、人工复核；原始字符串保留在 `relationNote` 字段不丢失质感（`真正臣服的母狗侍奴` → 主类 `主从` + note 原文）。**噪声条目**（如 `无直接关系（根据证据…）`）单独列出清洗。

## 5. L3：反应矩阵（R3-9 G0）

### 5.1 吕雉 · 不可变底色（取自正典，任何档位不得改写）

- **人格**：老谋深算 / 手段狠辣 / 权欲极强 / 冷漠高傲 / 好强倔强（`personality-consolidated.json`，source=card）
- **动机锚**：飞羽族存续。一切顺从与合作都是交易与守护，**不是情感**（`intimacyProfiles.ts` hardLimits）
- **权力位**：太后/太皇太后，仪态人前不可破
- **正典边界**：暗修处女功法，处子之身是博弈筹码，不得写破
- **语域双态**：「哀家/我」（威严）↔「奴婢」（柔媚卑微）——语域切换本身就是关系深度计

### 5.2 吕雉 · 同一动作 × 三档姿态

**测试动作：玩家主动告知一条关于霍子孟布局的关键情报。**（取自实测台账场景，`docs/PLAYTEST-FEEDBACK-LEDGER.md`）

维度**严格限定为路线图 R3-9 声明的五项**，不自行增列：

| 维度（路线图口径） | 低（≤-10） | 中（-9~39） | 高（≥40） |
|---|---|---|---|
| **① 语气与称谓** | 「哀家」，称玩家全名或官称 | 「哀家」，称姓氏 | 「我」偶现，直呼其名 |
| **② 善恶意解释倾向** | 默认你在借她的手；先问你为何要我知道——判定这是不是套 | 默认你在换筹码，合理；收下不表态，另寻渠道验证 | 默认你在给她争取时间；当场判断真伪并说出依据 |
| **③ 主动披露深度** | 零。反向套你的来源 | 给出一条她本就要公开的对价 | 主动交代自己在这局里的位置与顾虑 |
| **④ 协助／冒险意愿** | 不协助，但会记下这条情报 | 有限：出人不出名，可随时切割 | 肯押上飞羽族的暗线 |
| **⑤ 拒绝与设限方式** | 冷诮，直接点破你的算计 | 程式化推脱，留门 | 说明利害后拒绝，并给替代方案 |
| **全档不变** | 权力意识始终在线；决策以飞羽族存续为轴；仪态不破；不会因高好感而放弃自身筹码 |

**高档不等于服从**：高好感下她仍会拒绝——只是拒绝时会告诉你为什么，并给替代路径。这是本矩阵最重要的一格。

### 5.3 对照 NPC：贾文和（防写成吕雉专用 if/else）

选择理由：与吕雉在**性格与权力位两轴都相反**——吕雉是权力持有者、被动交易、情感语域丰富；贾文和是依附型谋士、主动风险规避、语域冷硬。已有表演卡硬合同（[`voiceCards.ts:29`](../src/modules/scenarioMods/voiceCards.ts)）可直接接。

**同一测试动作**，同样只走五维：

| 维度（路线图口径） | 低 | 中 | 高 |
|---|---|---|---|
| **① 语气与称谓** | 短句冷淡，「蠢材」级冷嘲频率最高 | 短句冷淡，就事论事 | 仍是短句冷淡——**他不会变热** |
| **② 善恶意解释倾向** | 默认你的情报是给主上添乱 | 默认情报可用但需自行验证 | 默认你已替主上过滤过风险 |
| **③ 主动披露深度** | 只报最坏后果，方案留一半 | 报后果 + 给一个可执行方案 | 报后果 + 方案 + 主动说出自己会在哪一步抽身 |
| **④ 协助／冒险意愿** | 评估你是负资产，建议主上切割 | 按主上利益办，你顺带受益 | 肯把"我自己的退路"这条底牌交给你 |
| **⑤ 拒绝与设限方式** | 直接判定不值得做，不留余地 | 给出不做的代价账，由主上定 | 说明拒绝理由并给出他愿意承担的那部分 |
| **全档不变** | 先报最坏后果再给方案，方案含代价/退出条件/备用手段之一；以主上利益为判断轴；不得变谄媚弄臣／温吞解说员／和事佬；不得只复述局势把决定全推回玩家 |

**对照要点**：吕雉的高档表现为**语域软化 + 交底**，贾文和的高档表现为**信息完整度提升 + 交出自己的退出条件**，声线毫无软化。这证明姿态层是通用机制而非角色特判——同一个"高好感"在两人身上长相完全不同。

### 5.4 成人化表达变体（不由本文定义）

路线图 G0 明确：成人化表达是**同一姿态层的可选变体**，仅在成人开关、成年与情境门禁全部满足时**由 Grok 补充**，不得反向污染普通场景。因此本文只声明两条边界，具体变体内容不在此起草：

1. 变体只能改**表达**，不得新增维度、不得改上表任何"全档不变"行。
2. 与既有 `intimacyProfiles` 的两道门（名单门 + 场景门）叠加，不另起门禁；吕雉的处子边界（裁定 #111 同族）在任何档位、任何变体下不可写破。

### 5.5 验收（G2，Claude 独立真机执行）

同存档、同动作跑三档，须同时满足：① 差异可感知但不过火；② **去掉显式亲疏措辞后仍能认出是同一个吕雉**；③ 核心人格与当前政治目标一致；④ 高档下拒绝仍可能成立；⑤ 低档不泄漏未知事实；⑥ 刷新/续玩后姿态稳定。再跑贾文和复验通用性。

## 7. 裁定主体：混合方案的具体切分

用户口径："没想好，感觉混合比较合适但不确定"。本节把"混合"落成可执行的边界，避免停留在感觉。

**走确定性引擎裁定（LLM 不得改值）：**
1. 触犯人格底线 → 固定扣减 + 强制降档（§3.4）
2. 正典高光节点与关卡里程碑的既定好感变化
3. 阶梯投影、滞回、cap、速率上限——全部是纯函数，LLM 无权覆盖
4. 关卡初始值（§6.1）

**交 LLM 结构化命令（受约束）：**
1. 日常互动的小幅增减，单回合净变化受 ±15 硬上限约束（由 `commandValueValidator` 执法）
2. LLM 只能发 `add`，不能发 `set` 直接跳档——`set 好感度` 收归引擎专用

**理由**：这与项目既有共识"确定性调度定发生什么、LLM 只管怎么讲"一致，且改动面最小——现有 LLM 出好感命令的链路不推翻，只加上限与命令类型门禁。**若用户否决，退路是"全 LLM + 硬约束"，代价是 cap 与降档无法保证。**
