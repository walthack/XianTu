## 接入范围与模型归属

| 模块 | 职责 | 执行时机／权限 |
|---|---|---|
| 动作与事实结算 | 现有本地合同、当前步骤／整件事件完成、位置／在场人物／知识投影 | 代码先在clone预结算，正文通过后由原事务入口唯一提交 |
| 演出 | 本轮公开场景及前后承接，纯正文，无状态指令 | main现有指定模型（当前Jev），前台等待 |
| 摘要 | 选择编号原句／段落，代码取回原文，最多4条且总长≤1000字符 | memory_summary现有指定模型（当前MiniMax），前台落盘后后台运行 |
| 质量检查 | 原文证据＋具体问题，提供建议，不重写正文 | text_optimization现有指定模型（当前OpenRouter DeepSeek），与摘要并行、遵守原功能开关 |
| 汇总／保存 | 回合ID、角色、槽位、页面生命周期版本、叙事版本核对；串行保存提案 | 不回灌捕获的整份旧存档，不把模型输出当正式世界事实 |

首版只接已有Legacy场景合同的阶段01／02动作（含南荒期限谈判）。自由交谈、判定回执、机会动作、拒赌专用动作、离馆后段落等继续原链路，在模块试玩打开时记录为 `legacy`。因此这不是所有功能全部迁移，关系确认／长线世界模拟尚未解耦。

谈期限第1步只完成提议；场景包明确「整件事件未完成」，正文提前确认期限会被拒绝且不结算。完整第二步仍以本地合同回执为准。保留现有前台请求预算；新增后台独立90秒请求截止、8192输出预算和调用级low推理设置，均不改持久API参数。未覆盖回合仍可能遇到Run6的延迟问题。

原 `text_optimization` 开关目前关闭，普通试玩默认不发DeepSeek请求；若要三模型同测，可在游戏API功能设置里自行开启该功能。受控浏览器和本轮三模型实测只在临时浏览器副本开启，服务器配置hash保持不变。

## 真机复测顺序

1. 谈期限检查点：自然输入与按钮各测；第1步只提议，第2步确认；正文与状态一致，不重复结算。
2. 至少20个真实回合，分开统计模块／原链路。从点击发送到输入恢复计前台耗时，另计摘要／检查耗时；全部提交包括失败计入分母，勿只计成功回合。
3. 一轮后台未完时马上发下一轮；另测切档、读同槽检查点、刷新、退出游戏。旧任务不得影响新正文、新档或忙碌状态。
4. 对照关闭模块开关的同检查点与相同行动；正文长度、缓存命中、模型路由、成功率、事件完成及关系变化都记录。小样本快不能直接归因架构净收益。
5. 凝羽自由交谈、身份拒绝／确认及跨关连续性继续单列：本轮不宣布修复或通过。
