# R2-11G：失败—准备—重试生命周期 G1（2026-07-21）

## 结论

非机会卡本地合同现可表达“贸然尝试失败 → 花一回合准备 → 下一回合按准备结果重试”。失败、准备和重试都是引擎持有的结构化动作，不从 LLM 正文猜测。

## 生命周期

- 每个世界回合最多消费一个事件动作；同轮第二个动作被拒绝。
- `failure` 不完成事件，Rail 继续开放，玩家也仍可闲逛或等待绝对截止。
- `prepare` 成功后写入事件内 preparation key，但本身绝不完成事件。
- 需要该 key 的 attempt 在准备前不可见、不可执行；准备完成后出现。
- preparation 随 JSON 存档保留，但不跨事件，也不跨合同热更。
- 审计只保留最近 8 条尝试，另有单调 `attemptCount`，避免长期重试后记忆 id 重复。

## `s01_09` 纵切

低魅力角色可选择不经核对直接宣旨并失败；吕雉会降低信任并记住这次贸然尝试。下一回合核对名册、印信和见证次序，准备成功但事件不结算；再下一回合开放“按核定程序重新宣旨”，成功后才由引擎完成事件，并形成“受阻后补齐准备、最终履责”的长期经历。

原有直接主持路线仍保留，成功／partial 合同不被替代；玩家不介入仍由六回合绝对截止场外收束。

## 自动化

- failure 不结算，同回合第二动作拒绝。
- preparation 经 JSON 往返仍存在，且准备动作不结算。
- 准备前隐藏重试、准备后隐藏重复准备并开放重试。
- 三次动作的 attemptCount、outcome 序列、态度净变化与长期经历可审计。
- validator 拒绝无 grantsPreparation 的 prepare 与不存在的 requiresPreparation 引用。
