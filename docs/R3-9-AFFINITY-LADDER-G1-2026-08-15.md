实际是**六处**，不是规格说的四处：

- 第五处 `RelationshipNetworkPanel` 的级数与新阶梯同为 8，**但边界不同——不是 1:1 平移**（报告初版把它写成"1:1 映射"，是错的）：好感 -5 从 `dislike` 变 `neutral`、-50 从 `enemy` 变 `hostile`，因为新阶梯把 0~19 与 -9~-1 合并成「陌路」，并把 enemy 门槛从 -41 下移到 -60。CSS 类名与样式确实零改动，变的是判据边界。
- 第六处由独立二审发现：`runtime.ts` 的 `projectBottomLinesToNpcs` 另有一份 `底线揭示好感 = 30`，负责把正典 principles 落到 `社交.关系.<NPC>.人格底线`（UI 显示 + 触犯暴跌机制）。初版只迁了 prompt 侧的 30→40，导致同一个「底线揭示」概念**两侧脱钩**：好感 35 且非自己人标签时，UI 会填底线、prompt 却隐藏。现已同源。

### 1.4 偏离规格一处（有依据）

规格 §3.6 写失配检测「改用姿态档」。实测这会**放松**检测：姿态高的门槛是 40，敌对标签配好感 25 就不再被检出，比原有 `>=20` 更松。故改按**档位**表达（敌对类标签合法域 = 相识档之下，等价于原判据），语义化而不改行为。亲密侧 §4.2 声明应收紧到 ≥40，但对存量存档会造成误报风暴，本轮保守沿用 `<=0`，留到 §4 词表阶段连同标签迁移一起做。已在 `affinityLadder.ts` 注释写明。

### 1.5 命令门禁（§7 混合裁定）

`createAffinityCommandGate()` 每回合一个实例，挂在 `_preprocessCommands`（**只服务 LLM 的 `tavern_commands`**，引擎路径不经过，已核实该函数仅一个调用者）：

- `set 好感度` → 一律拒绝，写入权归引擎；
- `add` → 单回合净变化钳到 ±15，且**按 NPC 跨命令累计**（只钳单条的话，拆成三条 +15 就绕过去了）；
- 反向操作可收回额度（净变化语义），非数值 add 不拦、交既有校验链。

### 3.3 真机抓包发现并修复的缺陷（本轮自测的主要产出）

**首轮抓包发现：主角自己被注入了姿态合同** ——「程宗扬·关系姿态：陌路（好感 0）」。主角就是玩家，"他对玩家的姿态"无意义；好感 0 只是因为主角不在 `社交.关系` 里。`voiceCards` 与 `intimacyProfiles` 靠名单门天然规避，姿态层是全量注入所以漏了。

**第一次修复用错了判据**：`character.id !== runtime.opening?.playerCharacterId`。重新抓包发现主角**依然在**——查存档确认 `runtime.opening` 只有 `text` 与 `relatedCharacterIds`，`canon.opening` 直接是 `null`，该字段在运行时投影里根本不存在，判据恒真、形同虚设。（附带发现：`storyContext.ts:618/824/920` 三处既有代码也在用同一字段，可能同样是 no-op——**属既有问题，本轮未动，登记待查**。）

**最终判据**改为语义正确的版本：只有**确实存在关系数据**的角色才注入（`live !== undefined || canonFav !== undefined`）。主角既不在 `社交.关系` 也不在 `playerRelationships`（`relationships.ts` 建档时显式 `continue`），由此自动排除；顺带解决了"给素未谋面的路人注入好感 0＝陌路"这种虚假精确。

复验：主角命中 **0 次**，改为小紫（信重 40）与殇侯（陌路 5）两个不同档位同场。已加回归测试锁死判据。

> 方法论备注：这个缺陷单元测试抓不到（`formatRelationStance` 本身完全正确），只有真机抓包能发现。第一次修复"看起来对"但实际无效，也只有第二次抓包才暴露——印证 skill 的纪律：**先证明你测的东西在链路上**。

### 5.2 看哪里

**A. 档位名（一眼可见，不用打一轮）**
- 人物属性 → 内部 tab「社交」→ 关系列表右侧，应显示「亲厚 70」而不是光秃秃的「70」。
- 人物关系 → 点任一 NPC → 详情徽章应显示「信重 40」而不是「好感 40」。
- 判断标准：档位名要和数值对得上（20~39 相识 / 40~59 信重 / 60~79 亲厚 / 80+ 生死 / -9~19 陌路 / -24~-10 戒备 / -59~-25 敌意 / ≤-60 仇雠）。

**B. 姿态差异（要打回合）**
存档 11111 现成有跨档 NPC，可直接对比：
- **小紫（信重 40，高档）** vs **殇侯（陌路 5，中档）** vs **鬼巫王（敌意 -55，低档）**
- 对不同档位的 NPC 做**同一个动作**（例如都向其询问对当前局面的判断），看五个维度是否真的不同：语气称谓、是否默认你有善意、主动说多少、愿不愿担风险、拒绝时怎么拒绝。

**这次要请你重点盯的三件事**（都是最可能翻车的地方）：
1. **高好感有没有变成舔狗**——小紫应该仍然会拒绝、仍然有自己的算计，只是会说明理由。如果她变得有求必应、一味顺从，就是过火了。
2. **低好感有没有变成脸谱化恶人**——鬼巫王应该仍然聪明、仍然会权衡，只是不信任你。如果变成无脑敌对、说话失了智，也是过火。
3. **去掉亲疏措辞后还认不认得出是同一个人**——这是最重要的判据。小紫在高档和中档下都该是那个"白切黑、比你多想三步"的小紫，而不是换了个人。

**C. 顺手可验的**：让 AI 大幅加好感（比如做一件对某 NPC 天大的好事），单回合最多只会 +15；如果看到一次跳 +40，说明门禁漏了。

### 5.3 反馈什么

差异**太小**（三档读起来差不多）或**太大**（同一个人在不同档位像两个人）都要说。具体到"哪个 NPC、什么动作、你期望的反应 vs 实际反应"最有用。
